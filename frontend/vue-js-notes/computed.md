computed
======================

1\. 정의
--------------
```
기존의 반응형 데이터(State, Props 등)를 기반으로 새로운 값을 계산해 내는 종속 데이터입니다.
```

2\. 사용하는 이유
--------------
```
템플릿 내부에 복잡한 로직을 직접 작성하면 코드가 지저분해지고 가독성이 떨어집니다. computed를 사용하면 복잡한 연산 로직을 스크립트 
단으로 분리하여 템플릿을 깨끗하게 유지할 수 있습니다.
```

3\. 특징
--------------
```
1) 캐싱
 - computed는 종속된 반응형 데이터가 변경될 때만 재계산됩니다.
 - 종속 데이터가 바뀌지 않았다면, 몇 번을 호출해도 새로 계산하지 않고 이전에 계산해 둔 결과값(캐시)을 즉시 반환합니다.
 - 무거운 배열 연산이나 complex한 로직일수록 성능 이점이 극대화됩니다.
2) 종속성 추적
 - Vue는 computed 내부 코드를 실행하면서 어떤 데이터가 사용되었는지 자동으로 추적합니다.
 - 사용된 반응형 데이터 중 하나라도 값이 변경되면 computed는 자신도 "Dirty(변경됨)" 상태로 표시하고, 다음 접근 시 재계산을 수행합니다.
3) 읽기 전용 기본값
 - 기본적으로 computed는 계산된 값을 반환(return)만 하는 읽기 전용 형태입니다.
 - 직접 값을 할당(computedValue.value = 'new')하면 경고가 발생합니다.
```

4\. Computed vs Methods vs Watch
--------------
셋의 차이점을 파악하는 것이 Vue의 상태 관리를 잘하기 위한 핵심입니다.
```
구분              computed                        methods                         watch
캐싱              지원 (종속 데이터 변동 시만 계산)    미지원 (리렌더링 시마다 매번 실행)    해당 없음
목적              새로운 데이터/값을 산출할 때        이벤트 처리 및 일반 함수 정의       데이터 변화에 따른 부작용(Side-effect) 처리
반환값             반드시 return 필요               return 선택 사항                보통 return 없음
주요 유스케이스    필터링된 리스트, 합계/평균 연산      클릭 이벤트 핸들러, API 호출 함수   비동기 로직(API 요청), DOM 직접 조작

💡 Computed vs Methods 예시
템플릿 안에서 {{ getDoubleCount() }}(Method)를 호출하면 컴포넌트가 재렌더링될 때마다 계속 함수가 실행되지만, 
{{ doubleCount }}(Computed)는 count가 바뀌지 않는 한 기존 계산값을 재사용합니다.
```

5\. 고급 활용: Writable Computed (수정 가능한 Computed)
--------------
```
getter와 setter를 명시해주면 computed에 값을 직접 할당할 수도 있습니다. 주로 v-model과 함께 상위 컴포넌트의 Props를 
양방향 바인딩할 때 매우 유용하게 사용됩니다.
```

6\. Computed 사용 시 주의사항 (Best Practices)
--------------
```
1) 사이드 이펙트(Side Effects) 금지:
 - computed 내부에서 API를 호출하거나, DOM을 조작하거나, 다른 상태(State)를 변경하지 마세요.
 - 오직 순수 함수(Pure Function)처럼 "입력(종속 데이터)을 받아 출력(값)을 반환"하는 역할만 해야 합니다. (사이드 이펙트는 watch나 
   이벤트 핸들러에서 처리)
2) Computed 값 자체를 직접 수정하지 말 것:
 - Writable Computed가 아닌 이상 computed.value = xxx 형태로 직접 변경하면 안 됩니다.
 - computed가 바라보고 있는 원본 반응형 데이터(State)를 변경해야 합니다.
```
