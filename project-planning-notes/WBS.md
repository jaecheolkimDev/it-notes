WBS(Work Breakdown Structure, 작업 분할 구조도)
=================

1\. 정의
---------------
```
프로젝트를 관리 가능한 작은 단위로 쪼개어 시각화한 체계적 구성도입니다. 
프로젝트의 전체 범위를 정의하고 일정을 수립하는 가장 기초적이고 중요한 도구입니다.
```

1\. 주요 특성 및 핵심 요소
---------------
```
1) 100% Rule (100% 법칙): WBS 최상위 계층의 작업 합은 전체 프로젝트의 100% 범위를 담아야 하며, 하위 단계 작업들의 합은 상위 단계 
                         작업의 100%와 정확히 일치해야 합니다.
2) 상호 배타적 (Mutually Exclusive): 하위 요소 간 작업 중복이 없어야 합니다.
3) 작업 패키지 (Work Package): WBS의 가장 최하위 단계 작업 단위로, 일정과 비용을 산정하고 담당자를 할당할 수 있는 수준의 크기입니다.
```

1\. 작성 4단계
---------------
```
1) 프로젝트 목적 및 최종 인도물(Deliverables) 정의
 - 프로젝트 완료 시 생성되어야 하는 최종 결과물을 명확히 정의합니다.
2) 주요 단계 및 산출물 분할
 - 기획, 설계, 개발, 테스트 등 하위 영역 또는 대분류로 분할합니다.
3) 작업 패키지 단주위 분해
 - 담당자가 명확히 배정되고 추적 가능한 수준(보통 8시간~80시간 소요 분량)으로 작업을 잘게 쪼갭니다.
4) 코드 체계 부여 및 WBS 사전 작성
 - 각 작업에 식별 번호(예: 1.1, 1.1.1)를 부여하고, 작업 내용·담당자·필요 자원 등을 명시한 WBS 사전(WBS Dictionary)을 작성합니다.
```

1\. 구조 및 예시 (웹사이트 제작 프로젝트)
---------------
```
계층 Level    코드      작업 명칭 (Task Name)       비고 / 설명
1단계         1.0     신규 웹사이트 구축              프로젝트 전체
2단계         1.1     기획 및 분석                 대분류
3단계         1.1.1   요구사항 정의                 중분류
4단계         1.1.1.1 사용자 인터뷰 및 분석        Work Package (최하위 작업)
4단계         1.1.1.2 요구사항 명세서 작성         Work Package
2단계         1.2     UI/UX 디자인               대분류
3단계         1.2.1   와이어프레임 제작           Work Package
3단계         1.2.2   메인 및 서브 페이지 디자인     Work Package
```

1\. WBS 활용 시 얻는 핵심 이점
---------------
```
1) 범위 명확화: 프로젝트 누락 요소를 방지하고 스코프 크립(Scope Creep, 프로젝트 범위가 제어 없이 확장되는 현상)을 막습니다.
2) 정확한 추정: 전체를 한 번에 추정하는 것보다 최하위 단위를 각각 추정하여 합산하는 방식(Bottom-up)으로 산정 정확도를 높입니다.
3) 책임 소재 제공: 각 작업 패키지별 담당자(RACI)를 지정하여 책임 소재를 분명히 합니다.
4) 일정/비용 관리의 기준: 간트 차트(Gantt Chart) 제작 및 일정/예산 관리의 기초 데이터로 활용됩니다.
```
