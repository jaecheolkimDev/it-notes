RFx (RFI, RFP, RFQ 등)
=================

1\. IT 시스템 구축 사업 흐름
---------------
```
[1. RFI 단계]
"클라우드 전환을 하고 싶은데 최신 트렌드나 적합한 플랫폼 정보 좀 보내주세요." (시장 조사)
       ↓
[2. RFP 단계]
"정보를 바탕으로 '쇼핑몰 시스템 클라우드 전환' 사양서를 썼으니, 구현 방법과 견적이 담긴 제안서를 주세요." (업체 선정)
       ↓
[3. RFQ 단계]
"선정된 방법대로 구축할 AWS 서버 인스턴스 20대의 최종 정밀 견적서를 보내주세요." (계약/구매)
```

2\. RFI (Request for Information / 정보 요청서)
---------------
```
1) 목적: 아이디어나 기술, 시장 동향을 파악하기 위해 폭넓은 정보를 수집하는 단계입니다.
2) 상황: "문제가 발생했는데, 시장에 이를 해결해 줄 수 있는 솔루션이나 기술이 뭐가 있는지 잘 모를 때" 사용합니다.
3) 내용: 업체 소개서, 보유 기술 사양, 관련 프로젝트 포트폴리오, 일반적인 제품 라인업 등.
4) 특징: 아직 프로젝트의 요구사항이 구체적이지 않습니다. 따라서 계약 체결 목적이 아니라 공부 및 시장 조사용입니다.
```

3\. RFP (Request for Proposal / 제안 요청서)
---------------
```
1) 목적: 구체적인 문제 해결 방안(아이디어, 사업 수행 전략, 가격 등)을 업체로부터 공식 제안받는 단계입니다.
2) 상황: "우리가 무슨 시스템/기능을 만들고 싶은지 명확해졌으니, 실제 개발이나 구축 사업을 맡길 업체를 뽑을 때" 사용합니다.
3) 내용: 프로젝트 목표 및 세부 요건(SRS), 제출 기한, 제안서 작성 가이드라인, 평가 기준, 예산 범위.
4) 특징: 가장 흔하게 작성되는 문서입니다. 업체들은 이에 맞춰 제안서(Proposal)를 제출하며, 발주자는 이를 바탕으로 기술 및 가격 평가를 
        거쳐 업체를 최종 선정합니다.
```

4\. RFQ (Request for Quotation / 견적 요청서)
---------------
```
1) 목적: 명확하게 정의된 스펙이나 물품/서비스에 대해 정확한 비용(가격)을 받아보기 위한 단계입니다.
2) 상황: "구입할 제품이나 개발해야 할 내용의 스펙이 이미 100% 결정되어 있어서 제안(아이디어)은 필요 없고, 가격 비교만 하면 될 때" 
        사용합니다.
3) 내용: 품목, 정확한 수량, 명세서, 납기일, 결제 조건, 단가 및 총액 제출란.
4) 특징: 창의적인 제안보다는 가격과 납기 조건이 낙찰을 결정하는 가장 중요한 요소입니다. (장비 구매, 규격화된 소프트웨어 라이선스 구매, 
        단순 외주 인력 계약 등)
```

5\. RFE (Request for Evaluation)
---------------
```
실제 제품을 도입하기 전 성능을 평가/테스트(PoC)해보고 싶을 때 보냅니다.
```

6\. RFT (Request for Tender)
---------------
```
주로 공공기관이나 대기업의 입찰(Tender) 공고에서 RFP와 유사한 의미로 쓰입니다.
```
