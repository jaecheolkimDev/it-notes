Envers
======================

1\. 정의
--------------
```
Spring Data JPA에서 Hibernate Envers를 설정해 두면, 개발자가 일일이 이력을 저장하는 코드를 짜지 않아도 알아서(자동으로) 
변경 내역을 테이블에 기록해 줍니다.
```

1\. Envers
--------------
```
엔티티에 @Audited 어노테이션이 있으면 애플리케이션 구동 시점에 해당 엔티티를 감시 대상에 등록합니다.
```

2\. @Audited(withModifiedFlag = true)
--------------
```
Hibernate Envers 라이브러리에서 제공하는 어노테이션으로, 데이터의 변경 이력(Audit Log)을 자동으로 기록해줍니다.

이력 관리: 이 어노테이션이 붙으면 데이터가 수정되거나 삭제될 때마다 별도의 이력 테이블(보통 테이블명_AUD)에 변경 전후 데이터와 
         수정 시점, 수정 유형 등이 저장됩니다.

withModifiedFlag = true: 데이터가 변경되었을 때, 어떤 컬럼이 수정되었는지를 나타내는 별도의 플래그 컬럼(컬럼명_MOD)을 이력 테이블에 
                         추가합니다.

예를 들어 UPDATE_DATE가 바뀌었다면 UPDATE_DATE_MOD 컬럼에 true가 기록되어, 나중에 "어떤 값이 바뀌어서 이 이력이 생성되었는지"를 
쉽게 쿼리할 수 있게 해줍니다.
```

3\. @NotAudited
--------------
```
굳이 이력을 남길 필요가 없는 단순 참고용 데이터라면, 부모 엔티티의 해당 필드에 @NotAudited를 붙여 이력 추적에서 제외합니다.
```

4\. 주의할 점 (알아서 안 해주는 것 한 가지)
--------------
```
기본적으로 Envers는 '언제', '어떤 데이터'가 바뀌었는지는 100% 자동으로 기록하지만, '누가(어떤 사용자가)' 바꾸었는지는 기본으로 
기록해주지 않습니다.
"누가 수정했는지"까지 자동으로 남기려면 RevisionListener라는 인터셉터를 구현해서 로그인한 사용자 정보를 Envers에 넘겨주는 
설정(커스텀 리비전)을 아주 조금만 추가해 주면 됩니다.
```
