JPA 어노테이션 공부 노트
===========================================


1\. @EntityListeners({AuditingEntityListener.class, RegistrationEventListener.class})
-----------------------
```
이 어노테이션은 엔티티의 생명주기(Lifecycle) 동안 발생하는 이벤트(저장, 수정, 삭제 등)를 감지하여 특정 로직을 실행하도록 설정합니다.

AuditingEntityListener.class: Spring Data JPA에서 제공하는 기본 리스너입니다. 
    @CreatedDate나 @LastModifiedDate가 붙은 필드에 현재 시간을 자동으로 주입하는 역할을 합니다.

RegistrationEventListener.class: 사용자가 직접 정의한 커스텀 리스너입니다. 
    앞서 설명드린 것처럼 어댑터를 통해 creatorId나 modifierId 같은 사용자 정보를 주입하는 로직을 실행합니다.

작동 방식: DB에 INSERT나 UPDATE가 일어나기 직전에 이 리스너들이 가동되어 필요한 데이터(시간, ID 등)를 엔티티에 채워 넣습니다.
```

2\. @MappedSuperclass
-----------------------
```
이 클래스가 직접적인 DB 테이블로 생성되는 것이 아니라, 다른 엔티티 클래스들에게 매핑 정보(필드)를 상속해주는 부모 클래스임을 나타냅니다.

코드 효율성: creatorId, createDate 처럼 모든 테이블에 공통으로 들어가는 컬럼들을 매번 선언할 필요 없이, 
           이 클래스를 상속(extends Registration)만 하면 자동으로 해당 컬럼들이 포함됩니다.

추상화: Registration 클래스는 보통 abstract로 선언되어 단독으로 객체를 생성하지 못하게 막습니다.
```

3\. @Audited(withModifiedFlag = true)
-----------------------
```
Hibernate Envers 라이브러리에서 제공하는 어노테이션으로, 데이터의 변경 이력(Audit Log)을 자동으로 기록해줍니다.

이력 관리: 이 어노테이션이 붙으면 데이터가 수정되거나 삭제될 때마다 별도의 이력 테이블(보통 테이블명_AUD)에 변경 전후 데이터와 수정 시점, 수정 유형 등이 저장됩니다.

withModifiedFlag = true: 데이터가 변경되었을 때, 어떤 컬럼이 수정되었는지를 나타내는 별도의 플래그 컬럼(컬럼명_MOD)을 이력 테이블에 추가합니다.

예를 들어 UPDATE_DATE가 바뀌었다면 UPDATE_DATE_MOD 컬럼에 true가 기록되어, 나중에 "어떤 값이 바뀌어서 이 이력이 생성되었는지"를 쉽게 쿼리할 수 있게 해줍니다.
```
