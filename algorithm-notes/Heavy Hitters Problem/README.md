'Heavy Hitters Problem(헤비 히터 문제) 해결 알고리즘' 또는 'Streaming Top-K 알고리즘'
======================

1\. 정의
--------------
```
전체 데이터 스트림에서 지정한 비율(예: 전체의 1% 이상)을 초과하여 빈번하게 등장하는 항목을 찾는 문제
```

1\. 해결 기법
--------------
```
1) Count-Min Sketch (+ Min-Heap)
 - 원리: 데이터를 적당히 뭉뚱그려 숫자를 세는 '요약장부'입니다.
 - 용도: "이 항목이 몇 번 나왔지?" 추정할 때 쓰입니다.
2) Space-Saving 알고리즘
 - 원리: 의자 $K$개만 놓아두고, 새 손님이 오면 가장 인기 없는 사람을 쫓아내며 상위 $K$개만 남기는 방식입니다.
 - 용도: "지금 가장 인기 있는 Top-K가 누구지?" 찾을 때 쓰입니다.
```

1\. 필요한 이유
--------------
```
"메모리는 부족한데, 수억 건의 데이터 속에서 가장 인기 있는 항목(Top-K)을 실시간으로 찾아야 해서"입니다.
```

1\. 탄생 배경
--------------
```
모든 데이터를 하나하나 기억하려면 엄청난 컴퓨터 메모리(RAM)가 필요합니다. 하지만 "약간의 오차(확률)를 허용하는 대신, 극소량의 메모리만 
써서 인기 항목을 찾아내자"는 아이디어로 만들어진 편법(자료구조)들입니다.
```

1\. 사용 사례
--------------
```
실시간 검색어 순위, 트위터/X의 실시간 트렌드, 네트워크 디도스(DDoS) 공격 IP 감지처럼 데이터가 폭주하는 환경에서 필수적으로 쓰이는 
기법들입니다.
```
