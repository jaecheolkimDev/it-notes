인터벌 스케줄링(Interval Scheduling)
===========================================

1\. 정의
--------------
```
여러 개의 작업(Task)이 시작 시간과 종료 시간을 가질 때, 하나의 자원(서버, 강의실, 사람 등)에서 서로 시간이 겹치지 않게 실행할 수 있는 
최대 작업 개수를 찾는 대표적인 최적화 문제입니다.
```

2\. 최적 해 구하기
--------------
```
탐욕 알고리즘(Greedy Algorithm)을 사용하여 항상 최적의 해를 구할 수 있음
```

3\. 핵심 아이디어 : 종료 시간이 가장 빠른 것 선택
--------------
직관적으로 생각하면 다음과 같은 여러 기준을 고려해볼 수 있습니다.
```
1) 가장 짧은 작업부터 선택? -> 오답 (긴 작업 하나와 겹치는 짧은 작업 여러 개를 놓칠 수 있음)
2) 시작 시간이 가장 빠른 것부터 선택? -> 오답 (아주 일찍 시작해서 매우 늦게 끝나는 작업이 먼저 선택될 수 있음)
3) 종료 시간이 가장 빠른 것부터 선택? -> 정답!

이유: 작업을 일찍 끝낼수록 남은 시간(자원)을 가장 많이 확보할 수 있으므로, 이후에 더 많은 작업을 추가할 기회가 생깁니다.
```

4\. 알고리즘 수행 단계
--------------
```
1) 모든 작업을 종료 시간(Finish Time) 기준 오름차순으로 정렬합니다.
2) 첫 번째 작업을 선택하여 스케줄에 추가합니다.
3) 다음 작업들을 순회하면서, 현재 작업의 시작 시간이 이전에 선택한 작업의 종료 시간보다 같거나 늦다면 해당 작업을 선택합니다.
4) 모든 작업을 확인 완료할 때까지 반복합니다.
```

5\. 시간 복잡도
--------------
```
1) 정렬: $O(N \log N)$ ($N$은 작업의 개수)
2) 순회 및 선택: $O(N)$
3) 전체 시간 복잡도: $O(N \log N)$ (정렬이 전체 복잡도를 지배)
```

6\. 변형
--------------
```
가중치 인터벌 스케줄링 (Weighted Interval Scheduling): 각 작업에 '중요도'나 '수익' 같은 가중치가 부여된 경우, 탐욕 알고리즘으로는 풀 수 없으며 동적 계획법(Dynamic Programming)이나 이진 탐색을 함께 활용해야 합니다.
```
