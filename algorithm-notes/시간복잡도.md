알고리즘 공부 노트
======================


1\. 빅오표기법
-----------------------
빅오 표기법이란 복잡도에 가장 영향을 많이 끼치는 항의 상수인자를 빼고 나머지 항을 없애서 복잡도를 나타내는 표기법입니다.
```
- n! > 2^n > n^2 > nlogn > n > logn > 1

빅오메가    : 최선의 경우 한 번에 찾음!
벡오      : 최악의 경우 배열의 길이만큼 걸림!
빅세타     : 평균의 경우 배열의 길이 중간 만큼 걸림!
```

2\. 시간복잡도
-----------------------
시간복잡도란 입력크기에 대해 어떠한 알고리즘이 실행되는데 걸리는 시간이며 주요로직의 반복횟수를 중점으로 측정됩니다.
```
- 상수시간 시간복잡도 O(1)
    - 상수시간 시간복잡도는 입력크기와 상관없이 일정한 시간복잡도를 가지는 것을 말하며 O(1)의 시간복잡도를 씁니다.
        - ex) 입력과 출력, 곱하기, 간단한 비교 if문, 배열의 인덱스 참조 등등...
    - 존재이유 : 효율적인 코드의 척도
    - ex) O(n^2)의 시간복잡도로 문제를 풀었을때 느리거나 시간초과가 나거나 하면 O(nlogn) 이하의 알고리즘을 써볼까? 라고 생각할 수 있는 기준점이 된다.
```

3\. 자료구조 시간 복잡도 (Data Structure Time Complexity)
-----------------------
```
자료구조의 성능은 접근(Access), 검색(Search), 삽입(Insertion), 삭제(Deletion) 연산을 기준으로 평가합니다.
일반적인 '쓰기(Update)' 연산은 수정을 원하는 위치를 찾는 '접근' 단계를 거친 후 O(1)로 수행되므로, 접근 복잡도와 유사한 흐름을 가집니다.

자료구조            접근 (Access)  검색       삽입/삭제     주요 특징 및 비고
배열 (Array)         O(1)         O(N)        O(N)    인덱스를 통한 직접 접근은 최강이나, 삽입/삭제 시 데이터 이동(Shift) 필요 
연결 리스트           O(N)         O(N)        O(1)    위치를 알고 있다면 삽입/삭제는 즉시 가능, 단 위치 탐색까지 O(N) 소요 
스택 (Stack)         O(N)         O(N)        O(1)    후입선출 (LIFO) 구조. 언제나 최상단(Top) 데이터만 제어 
큐 (Queue)           O(N)         O(N)        O(1)    선입선출 (FIFO) 구조. 뒤(Rear)로 넣고 앞(Front)에서 꺼냄 
양방향 큐 (Deque)     O(N)         O(N)        O(1)    앞(Front)과 뒤(Rear) 양방향에서 모두 삽입 및 삭제 가능 
해시 테이블           O(1)       평균 O(1)    평균 O(1)  해시 충돌(Hash Collision)이 극단적으로 잦을 경우 최악 O(N)으로 성능 저하
                               최악 O(N)    최악 O(N)  
HashSet               -        평균 O(1)    평균 O(1)  중복을 허용하지 않는 구조. 내부 메커니즘은 해시 테이블과 동일
                               최악 O(N)    최악 O(N)  
TreeSet             O(logn)     O(logn)     O(logn)
맵                  O(logn)     O(logn)     O(logn)
```

4\. 정렬 알고리즘 시간 복잡도 (Sorting Algorithm Time Complexity)
-----------------------
정렬 알고리즘은 초기 데이터의 배열 상태(정렬 여부, 역순 여부 등)에 따라 성능 편차가 발생하므로 최선(Best), 평균(Average), 최악(Worst)의 경우를 
모두 고려해야 합니다.
```
정렬 알고리즘    최선           평균          최악          주요 특징 및 비고 
버블 정렬       O(N^2)         O(N^2)       O(N^2)      인접한 두 원소를 비교하며 교환. 구현이 매우 직관적이나 대용량에 부적합 
선택 정렬       O(N^2)         O(N^2)       O(N^2)      최소 혹은 최댓값을 찾아 순서대로 배치. 데이터 상태와 무관하게 고정 성능 
삽입 정렬       O(N)           O(N^2)       O(N^2)      앞서 정렬된 부분과 비교해 알맞은 위치에 삽입. 정렬이 거의 된 상태에서 최강 
병합 정렬  	  O(Nlog N)     O(Nlog N)    O(Nlog N)     분할 정복(Divide and Conquer) 방식 활용. 데이터 상태에 관계없이 일정한 성능 보장 
퀵 정렬        O(Nlog N)     O(Nlog N)      O(N^2)      피벗(Pivot)을 기준으로 좌우 분할. 평균 성능이 매우 뛰어나 현업에서 애용됨
> 데이터가 이미 정렬되어 있거나 역순인 상태에서 배열의 첫 번째 원소를 고정적으로 피벗으로 선택할 경우, 분할 밸런스가 한쪽으로 완전히 붕괴되어 O(N^2)이 
  발생합니다. 이를 예방하기 위해 실제 라이브러리에서는 랜덤 피벗 선택 또는 세 값의 중앙값(Median of Three) 방식을 적용합니다. 
```

5\. 성능 판단 시 추가 고려사항 (Checklist)
-----------------------
```
1. 공간 복잡도 (Space Complexity): 데이터 가용 메모리 외에 알고리즘 수행을 위한 추가 메모리(예: 병합 정렬의 임시 배열 공간)가 얼마나 필요한지 확인해야 합니다.
2. 캐시 지역성 (Cache Locality): 배열처럼 연속된 메모리를 쓰는 구조는 CPU 캐시 히트율이 높아 이론적 성능보다 실제 속도가 더 빠를 수 있습니다.
3. 동시성 (Thread Safety): 멀티스레드 환경에서는 성능 저하를 최소화하면서 데이터 무결성을 지킬 수 있는 자료구조 설계가 필요합니다.
```
