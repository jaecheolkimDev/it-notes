AVL 트리(Adelson-Velsky and Landis Tree)
======================

1\. 정의
--------------
```
스스로 균형을 잡는 이진 탐색 트리(Self-Balancing Binary Search Tree, BST)입니다.
```

2\. 필요성
--------------
```
일반 이진 탐색 트리(BST)는 데이터가 정렬된 순서대로 삽입되면 한쪽으로 치우치는 편향 트리(Skewed Tree)가 됩니다. 
이 경우 탐색, 삽입, 삭제 속도가 $O(N)$으로 상쇄되어 단순 연결 리스트와 다를 바 없어진다는 한계가 있습니다.
AVL 트리는 트리의 높이(Height)를 최적화하여 어떤 상황에서도 모든 주요 연산의 시간 복잡도를 $O(\log N)$으로 보장합니다.
```

3\. 균형 인수 (Balance Factor)
--------------
AVL 트리의 핵심 규칙은 모든 노드에서 왼쪽 서브트리와 오른쪽 서브트리의 높이 차이가 최대 1 이하여야 한다는 점입니다.
```
Balance Factor (BF) = Height(Left Subtree) - Height(Right Subtree)
 - 허용되는 BF: -1, 0, 1
 - 불균형 상태: BF가 2 이상이거나 -2 이하로 떨어지면, 트리 회전(Rotation)을 수행하여 균형을 맞춥니다.
```

4\. 트리의 재균형: 4가지 회전 (Rotations)
--------------
데이터 삽입/삭제 시 BF 조건이 깨지면 다음 4가지 회전 알고리즘을 통해 즉시 균형을 복구합니다.
```
1) LL (Left-Left) 케이스 -> Single Right Rotation
 - 원인: 왼쪽 자식의 왼쪽에 데이터가 삽입되어 균형이 깨진 경우 (BF = +2, 자식 BF = +1)
 - 해결: 불균형 노드를 기준으로 시계 방향(오른쪽) 회전을 수행합니다.
2) RR (Right-Right) 케이스 -> Single Left Rotation
 - 원인: 오른쪽 자식의 오른쪽에 데이터가 삽입되어 균형이 깨진 경우 (BF = -2, 자식 BF = -1)
 - 해결: 불균형 노드를 기준으로 반시계 방향(왼쪽) 회전을 수행합니다.
3) LR (Left-Right) 케이스 -> Double Rotation (Left + Right)
 - 원인: 왼쪽 자식의 오른쪽에 데이터가 삽입된 경우 (BF = +2, 자식 BF = -1)
 - 해결: 자식 노드에 대해 왼쪽 회전을 적용해 LL 케이스로 변환한 후, 오른쪽 회전을 수행합니다.
4) RL (Right-Left) 케이스 -> Double Rotation (Right + Left)
 - 원인: 오른쪽 자식의 왼쪽에 데이터가 삽입된 경우 (BF = -2, 자식 BF = +1)
 - 해결: 자식 노드에 대해 오른쪽 회전을 적용해 RR 케이스로 변환한 후, 왼쪽 회전을 수행합니다.
```

5\. 연산별 시간 복잡도 (Time Complexity)
--------------
```
연산              평균 복잡도  최악 복잡도      비고
탐색 (Search)     O(logN)     O(logN)     완벽히 엄격한 균형을 유지하므로 탐색 속도가 매우 빠름
삽입 (Insert)     O(logN)     O(logN)     위치 탐색 O(logN) + 회전 연산 O(1)
삭제 (Delete)     O(logN)     O(logN)     삭제 후 루트 노드까지 재귀적으로 높이 갱신 및 회전
```

6\. AVL 트리 vs 레드-블랙 트리 (Red-Black Tree)
--------------
자료구조를 선택할 때 대표적인 자가 균형 이진 탐색 트라인 Red-Black Tree와 자주 비교됩니다.
```
1) 균형의 엄격함: AVL 트리가 Red-Black 트리보다 훨씬 더 엄격하게 균형을 유지합니다. (AVL은 높이 차 1 이하, Red-Black은 
                최대 2배 높이 차 허용)
2) 탐색 성능: AVL 트리가 더 엄격한 균형을 유지하므로 탐색(Lookup) 속도가 더 빠릅니다.
3) 삽입/삭제 성능: AVL 트리는 재균형을 위한 회전 연산이 더 빈번하게 발생하므로, 데이터의 추가/삭제가 잦은 환경에서는 Red-Black 트리가 
                 더 효율적입니다.
4) 실무 활용:
 - AVL 트리: 조회 연산이 훨씬 많고 변경이 적은 데이터베이스 인덱싱/캐싱 구조
 - Red-Black 트리: C++ std::map, Java TreeMap/HashMap 등 데이터 삽입과 삭제가 빈번한 범용 라이브러리
```
