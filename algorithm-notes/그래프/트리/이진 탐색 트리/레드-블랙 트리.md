레드-블랙 트리(Red-Black Tree, RBT)
======================

1\. 정의
--------------
```
대표적인 자체 균형 이진 탐색 트리(Self-Balancing Binary Search Tree)입니다.
```

2\. 특징
--------------
```
AVL 트리와 달리 strict한 균형 대신 적절한 균형을 유지하여, 데이터의 추가/삭제 과정에서 일어나는 재균형(Rebalancing) 비용을 
최소화하도록 설계되었습니다.
```

3\. 5가지 필수 속성 (Properties)
--------------
레드-블랙 트리는 모든 노드가 Red 또는 Black의 색상을 가지며, 다음 5가지 규칙을 단 하나도 위반하지 않고 항상 만족해야 합니다.
```
1) Every node is either red or black. (모든 노드는 Red 또는 Black이다.)
2) The root is black. (루트 노드는 항상 Black이다.)
3) Every leaf (NIL) is black. (모든 리프 노드/NIL 노드는 Black이다.)
 - 참고: 실제 데이터가 아닌, 트리의 끝을 나타내는 가상/성미 노드(NIL)를 Black으로 처리합니다.
4) If a node is red, then both its children are black. (Red 노드의 자식은 모두 Black이다.)
 - 즉, Red 노드가 연속해서 등장할 수 없습니다 (No Double Red).
5) For each node, all simple paths from the node to descendant leaves contain the same number of black nodes. 
   (임의의 노드에서 해당 노드의 자손 리프 노드까지 이르는 모든 경로에는 동일한 개수의 Black 노드가 존재한다.)
 - 이 속성을 Black-Height(검은 높이) 조건이라고 부릅니다.
```

4\. 왜 높이 균형이 보장되는가?
--------------
```
- 속성 4번(Double Red 금지)에 의해, 가장 긴 경로는 [Black - Red - Black - Red ...] 순서로 교차하는 구조입니다.
- 속성 5번(Black-Height 동일)에 의해, 가장 짧은 경로는 [Black - Black - Black ...] 만으로 구성된 구조입니다.
- 따라서 가장 긴 경로의 길이는 가장 짧은 경로의 길이의 2배를 넘지 않습니다. ($h \le 2 \log_2(N + 1)$)
- 이로 인해 최악의 경우에도 탐색 시간 복잡도는 $O(\log N)$이 보장됩니다.
```

5\. 데이터 삽입과 재균형 (Rebalancing)
--------------
새로운 노드를 삽입할 때는 항상 Red 노드로 삽입합니다. (Red로 넣어야 Black-Height 조건인 5번 속성을 깨뜨리지 않기 때문입니다.)
새 노드 삽입 후 부모 노드가 Red일 경우 Double Red (속성 4 위반)가 발생합니다. 이때 부모의 형제 노드(삼촌 노드, Uncle)의 색상에 
따라 2가지 방식으로 재균형을 잡습니다.
```
① Recoloring (삼촌 노드가 Red인 경우)
 - 부모 노드와 삼촌 노드를 Black으로 변경하고, 할아버지(Grandparent) 노드를 Red로 변경합니다.
 - 할아버지 노드가 Red가 되었으므로 상위 트리에서 다시 Double Red가 발생할 수 있어, 루트 방향으로 올라가며 검사를 재귀적으로 
   진행합니다. (루트까지 올라가면 루트는 속성 2에 의해 다시 Black이 됨)

② Restructuring / Rotation (삼촌 노드가 Black이거나 NIL인 경우)
 - 자신, 부모, 할아버지 노드 3개의 값을 기준으로 중윗값(Median)을 선택합니다.
 - 중윗값 노드를 부모로 만들고, 나머지 두 노드를 자식으로 배치(회전 연산)합니다.
 - 새로운 부모 노드를 Black, 두 자식 노드를 Red로 설정합니다.
 - Restructuring은 한 번 수행하고 나면 상위 트리에 영향을 주지 않으므로 연산이 종료됩니다.
```

6\. 연산별 시간 복잡도
--------------
```
연산              평균 복잡도  최악 복잡도      설명
탐색 (Search)     O(logN)     O(logN)     높이가 최대 2logN으로 제한됨
삽입 (Insert)     O(logN)     O(logN)     위치 탐색 O(logN) + 회전/색상변경 최대 O(logN)
삭제 (Delete)     O(logN)     O(logN)     삭제 후 재균형 작업 수행
```

7\. Red-Black 트리 vs AVL 트리 비교
--------------
```
구분                  Red-Black Tree                  AVL Tree
균형 엄격도          완화된 균형 (높이 차 최대 2배)     엄격한 균형 (높이 차 최대 1)
탐색 (Search) 속도  약간 느림 (트리 높이가 다소 높음)    더 빠름 (트리 높이가 최적화됨)
삽입/삭제 속도        더 빠름 (회전 횟수가 적음)        상대적으로 느림 (자주 회전 발생)
실무 주 사용처        범용 표준 라이브러리, OS 커널      탐색 연산 비율이 압도적으로 높은 시스템
```

8\. 노드를 삭제할 때 복잡한 재균형(Rebalancing) 과정이 발생하는 상황
--------------
실제 삭제되는 노드(또는 대체 노드)의 색상이 Black일 때
```
1) 핵심 원인: 검은 높이(Black-Height)의 파괴
레드-블랙 트리의 5번 속성은 "임의의 노드에서 리프 노드까지의 경로에 존재하는 Black 노드의 개수는 모두 동일해야 한다"입니다.
 - Red 노드 삭제 시: 트리의 Black 개수 변화가 없으므로 추가 재균형 작업이 불필요하거나 매우 간단하게 끝납니다.
 - Black 노드 삭제 시: 해당 경로의 Black 노드 개수가 1개 줄어들면서 5번 속성(Black-Height 동일 조건)이 깨집니다.
이때 감소한 Black-Height 1을 메우기 위해 해당 위치에 유령처럼 "Double Black(이중 검은색)" 개념을 부여하고, 이를 상위 노드로 
전파하거나 회전/색상 변경을 통해 해소하는 복잡한 과정이 시작됩니다.

2) 가장 복잡해지는 세부 조건
Black 노드가 삭제된 후, 형제(Sibling) 노드의 색상과 형제의 자식 노드들의 색상에 따라 재균형 절차가 결정됩니다. 이 중 가장 복잡한 
케이스는 형제 노드가 Black이고, 그 형제의 자식들도 모두 Black인 경우입니다.

삭제 후 재균형의 4가지 주요 케이스
 [Case 1] 형제 노드가 Red인 경우
  - 형제를 Black으로, 부모를 Red로 바꾼 뒤 부모 기준으로 회전하여 형제를 Black으로 만든 후 다른 케이스로 전환합니다.
 [Case 2] 형제 노드가 Black이고, 형제의 두 자식도 모두 Black인 경우 (가장 까다로운 전파)
  - 형제 노드를 Red로 변경하여 형제 쪽의 Black-Height도 1 줄입니다.
  - 부모 노드가 Red였다면 부모를 Black으로 바꾸면서 종료되지만, 부모 노드가 이미 Black이었다면 이 불균형(Double Black)이 부모 
    노드로 이동하여 루트 방향으로 재귀적으로 전파됩니다.
 [Case 3] 형제 노드가 Black, 형제의 꺾인 방향 자식이 Red인 경우
  - 형제와 그 자식의 색상을 바꾸고 회전시켜 [Case 4] 형태로 변환합니다.
 [Case 4] 형제 노드가 Black, 형제의 같은 방향 자식이 Red인 경우
  - 회전과 색상 조정을 통해 최종적으로 불균형을 해소하고 연산을 완료합니다.

3) 요약
레드-블랙 트리의 삭제 연산에서 복잡한 회전 및 색상 변경 연산이 발생하는 핵심 조건은 Black 노드를 삭제했을 때이며, 특히 형제 노드 
및 부모 노드가 모두 Black이라 불균형 상태가 루트(Root) 방향으로 타고 올라가는 상황(Case 2 전파)에서 가장 복잡한 재균형 처리가 
일어납니다.
```
