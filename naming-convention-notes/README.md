네이밍 컨벤션
======================

1\.
--------------
```
이 모든 규칙의 뿌리는 결국 "컴퓨터가 이해할 수 있는 규칙(공백 없음)을 지키면서도, 인간이 읽기 편한 코드(가독성)를 
작성하려는 프로그래머들의 가독성 투쟁사"에서 비롯되었습니다.
```

1\. 대표적인 변수 명명 스타일
--------------
오늘날에는 언어와 환경마다 굳어진 관례(자바는 카멜, 파이썬은 스네이크, URL/CSS는 케밥)를 따르는 것이 협업의 표준이 되었습니다.
```
스타일         예시                      주요 사용 분야
Camel Case  "userName, totalPrice"      "Java, JavaScript, Swift"
Snake Case  "user_name, total_price"    "Python, SQL, C"
Pascal Case "UserName, TotalPrice"      "클래스/타입 명칭 (C#, Java 등)"
Kebab Case  "user-name, total-price"    "HTML/CSS, URL 경로"
```

1\. 중요한 이유
--------------
단순히 코드를 동작하게 만드는 것을 넘어, 소프트웨어의 품질과 개발 생산성을 결정짓는 핵심 요소입니다.
```
1) 코드 가독성 향상: 잘 지은 변수 이름은 별도의 주석 없이도 변수의 역할과 목적을 즉시 이해할 수 있게 합니다.
2) 유지보수 비용 절감: 개발자는 코드를 작성하는 시간보다 읽고 분석하는 데 훨씬 많은 시간을 씁니다. 명확한 이름은 미래의 자신이나 동료가 
                    코드를 해석하는 시간을 획기적으로 줄여줍니다.
3) 버그 예방: 변수의 의미가 분명하면 의도치 않은 데이터 타입 할당이나 잘못된 연산 등 개발자의 실수를 사전에 방지할 수 있습니다.
4) 협업의 원활화: 팀 프로젝트에서 통일된 규칙으로 작성된 코드는 개발자 간의 소통을 원활하게 하고 신규 팀원의 온보딩을 돕습니다.
```
