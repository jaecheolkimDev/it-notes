해시 공부 노트
=====================

1\. 해시
--------------------------------------
```
1) 해시 함수    : f(x) 처럼 입력을 출력으로 바꿔주는 함수 그 자체.
2) 해시 값     : 해시 함수의 결과물 (예: 0x7a2f...).
3) 해시 코드    : 주로 객체 지향 언어(Java 등)에서 객체를 식별하기 위해 해시 함수가 내놓은 정수값.
4) 해시 테이블   : 배열과 해시 함수를 결합해 만든 자료구조.
```

2\. 해싱 (Hashing): 과정과 기술
--------------------------------------
입력값을 해싱하여 해시값을 생성한다
```
1) 해싱은 어떤 데이터를 해시 함수(Hash Function)라는 규칙을 통해 고정된 길이의 값으로 변환하는 작업 그 자체를 말합니다.
2) 동사적 의미: "데이터를 잘게 쪼개고 섞어서 값을 만든다"는 뜻입니다.
3) 핵심 역할: 검색, 저장, 보안 등의 목적으로 데이터를 처리하는 '기술'을 의미할 때 주로 사용합니다.
```

3\. 해시 함수
-------------------------
해시 기반 시스템의 '엔진'과 같습니다. 이 엔진이 얼마나 성능이 좋고 안정적인지에 따라 전체 시스템의 속도와 보안이 결정됩니다.
```
1) 정의   : 해시 함수는 임의의 길이의 데이터(입력)를 고정된 길이의 데이터(출력)로 변환하는 함수입니다.
    Input: 문자열, 숫자, 이미지 파일, 거대한 텍스트 등 무엇이든 가능합니다.
    Output: 항상 일정한 길이의 숫자나 문자열(해시 값)이 나옵니다.
    
2) 3대 핵심 성질 : 좋은 해시 함수라면 반드시 갖춰야 할 조건들입니다.
    결정론적 (Deterministic): 동일한 입력에는 반드시 동일한 출력이 나와야 합니다. (그래야 나중에 데이터를 다시 찾을 수 있습니다.)
    효율성 (Efficiency): 결과값을 계산하는 속도가 매우 빨라야 합니다.
    충돌 저항성 (Collision Resistance): 서로 다른 입력 데이터가 우연히 같은 결과값을 내놓는 상황(충돌)을 최소화해야 합니다.
    
3) 유형 (용도별 분류)  : 실무에서는 용도에 따라 완전히 다른 알고리즘을 사용합니다.
    자료구조용 (Non-cryptographic):
        목적: 속도가 최우선입니다. 데이터가 해시테이블에 골고루 퍼지게 하는 것이 중요합니다.
        예시: Java의 hashCode(), MurmurHash, CityHash.
    암호학적 (Cryptographic):
        목적: 보안이 최우선입니다. 결과값만 보고 원래 데이터를 유추하는 것이 불가능해야 합니다.
        특징: 입력값이 1비트만 바뀌어도 결과가 완전히 달라지는 산사태 효과(Avalanche Effect)가 강력합니다.
        예시: SHA-256, SHA-3, MD5(현재는 보안 취약으로 비권장).
        
4) 작동 원리 (수학적 예시)   : 가장 간단한 해시 함수 중 하나인 나머지 연산(Modulo)을 예로 들어보겠습니다.
    함수: f(x) = x \pmod{10} (데이터를 10으로 나눈 나머지)
        입력 153 → 해시 값 3
        입력 49 → 해시 값 9
        입력 23 → 해시 값 3 (충돌 발생! 153과 23의 결과가 같습니다.)
    실제 해시 함수는 훨씬 복잡한 비트 연산과 수식을 사용하여 이런 충돌이 거의 일어나지 않게 설계됩니다.
```

4\. 해시 테이블
-------------------------
해시 함수를 사용하여 키(Key)를 특정 인덱스(Index)로 변환하고, 그 인덱스 위치에 값(Value)을 저장하는 연관 배열(Associative Array) 구조의 
자료구조입니다.
```
1) 3대 구성 요소
    키 (Key): 데이터를 찾기 위한 고유한 식별자 (예: 사용자 ID, 이름).
    해시 함수 (Hash Function): 키를 해시 값(인덱스)으로 바꿔주는 엔진.
    버킷/슬롯 (Bucket/Slot): 실제 데이터(Value)가 저장되는 배열의 각 공간.
    
2) 작동 프로세스
    해싱: 키를 해시 함수에 넣어 해시 코드를 얻습니다.
    인덱스 변환: 해시 코드를 배열의 크기에 맞춰 나머지 연산(Modulo) 등을 통해 실제 인덱스로 변환합니다.
    저장/조회: 결정된 인덱스 위치의 버킷에 데이터를 저장하거나 꺼내옵니다.
    
3) 충돌 해결 방법 (Collision Resolution)  : 해시테이블의 성능을 좌우하는 가장 중요한 관리 로직입니다.
    Separate Chaining (분리 연결법):
        충돌 발생 시 해당 버킷에 데이터를 연결 리스트(Linked List)로 줄 세우는 방식입니다.
        Java의 HashMap 등 대부분의 언어에서 기본으로 채택합니다.
    Open Addressing (개방 주소법):
        충돌 시 빈 공간을 찾아 다른 버킷에 저장하는 방식입니다.
        선형 조사(한 칸씩 이동), 제곱 조사(제곱만큼 이동) 등의 방법이 있습니다.
        
4) 성능 및 시간 복잡도
    평균 시간 복잡도: O(1) (삽입, 삭제, 탐색 모두 동일).
    최악의 경우: O(n) (모든 키가 충돌하여 하나의 버킷에 몰리는 경우).
    
5) 주요 용어 정리
    Load Factor (부하율): 해시테이블이 얼마나 차 있는지를 나타내는 비율 (데이터 개수 / 버킷 개수). 
                         보통 0.7~0.75를 넘으면 성능을 위해 크기를 키웁니다.
    Rehashing (리해싱): 테이블의 크기를 키우고 모든 데이터를 새로운 해시 함수 규칙에 따라 다시 배치하는 과정입니다.
    Immutable Key (불변 키): 해시테이블의 키가 중간에 변하면 해시 값도 바뀌어 데이터를 찾을 수 없게 됩니다. 
                            그래서 주로 String이나 Integer 같은 불변 객체를 키로 사용합니다.
    
6) 실무 적용 및 주의사항
    공간-시간 트레이드오프: 메모리를 더 많이 써서 버킷을 넉넉히 잡을수록 충돌이 줄어들어 속도가 빨라집니다.
    데이터 순서: 일반적인 해시테이블은 저장 순서를 보장하지 않습니다. 순서가 필요하다면 LinkedHashMap과 같은 변형 구조를 써야 합니다.
```
