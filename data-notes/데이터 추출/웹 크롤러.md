웹 크롤러(Web Crawler)
=============

3\. 정의
--------
```
인터넷을 자동 탐색하며 웹 페이지를 수집하고 데이터를 추출하는 소프트웨어 프로그램입니다.
스파이더(Spider) 또는 봇(Bot)으로도 불리며, 검색엔진 인덱싱, 데이터 분석, 가격 비교 서비스 등의 핵심 기반 기술입니다.
```

4\. 웹 크롤링 (Web Crawling) vs 웹 스크래핑 (Web Scraping)
--------
```
구분  웹 크롤링 (Web Crawling)                        웹 스크래핑 (Web Scraping)
목적  웹상의 페이지들을 탐색 및 수집                       특정 페이지에서 특정 데이터 추출
방식  링크를 따라 지속적으로 이동 (Graph Traversal)       타깃 URL의 HTML을 파싱하여 특정 태그 추출
범위  방대하고 광범위한 웹 페이지                         정해진 특정 웹 사이트 / 데이터 분야
```

5\. 핵심 동작 프로세스
--------
```
1) Seed URL 수집:초기 탐색 시작점.
 - 크롤러가 방문할 시작 웹페이지 주소(Seed URLs)를 큐(URL Frontier)에 등록합니다.
2) HTTP 요청 및 HTML 다운로드:
 - 큐에서 URL을 꺼내 대상 웹 서버에 HTTP GET 요청을 보내고, 응답받은 HTML 문서를 다운로드합니다.
3) 데이터 파싱 및 저장:
 - 다운로드한 HTML을 파싱하여 본문 데이터(텍스트, 이미지 등)를 추출한 뒤 데이터베이스에 저장합니다.
4) 새로운 URL 추출 및 중복 검사:
 - HTML 내부의 <a> 태그 등에서 새로운 Hyperlink를 추출합니다. 이후 이미 방문한 URL인지 블룸 필터(Bloom Filter)나 DB로 검증합니다.
5) 큐 추가 및 반복:
 - 중복되지 않은 새로운 URL을 다시 URL Frontier 큐에 추가하고 1단계부터 동일하게 반복 실행합니다.
```

6\. 대규모 크롤러 설계 시 핵심 고려사항
--------
```
1) 분산 처리 & 확장성: 수억 개의 URL을 처리하기 위해 Kafka/RabbitMQ 기반의 메시지 큐와 여러 수집 노드를 배치하는 분산 아키텍처가 
                    필요합니다.
2) 동적 웹페이지 처리: React, Vue 등 CSR(Client Side Rendering) 기반 사이트는 단순히 HTML 요청만으로는 데이터 수집이 
                불가능하므로, Headless Browser(Selenium, Playwright)를 활용하거나 내부 API 엔드포인트를 직접 분석해야 합니다.
3) 차단 회피 (Anti-Bot Bypass): User-Agent 순환, 프록시 IP Pool 활용, CAPTCHA 대응, TLS Fingerprint 모방 등의 기법을 
                              적용합니다.
```

3\. 대상 사이트에 과부하를 주지 않고 안정적으로 데이터를 수집하기 위해 반드시 고려해야 하는 핵심 5가지
--------
```
1) 크롤링 요청 간격 조절 (Politeness Delay)
 - Throttling: 연속적인 HTTP 요청 사이에 최소 지연 시간(예: 1~3초)을 설정합니다.
 - 동시 요청 제한 (Concurrency Control): 동일한 도메인(IP)으로 들어가는 동시 연결 수를 제한하여 서버 리소스 급증을 방지합니다.
2) robots.txt 및 Crawl-delay 준수
 - Crawl-delay 지침 확인: 대상 사이트의 robots.txt에 명시된 Crawl-delay 파라미터를 읽고 이를 엄격히 준수합니다.
 - 수집 금지 구역 준수: Disallow 규칙을 확인하여 원치 않는 대량의 수집 시도를 사전에 차단합니다.
3) 분산 크롤링 시 Domain-based Rate Limiting 적용
 - 여러 IP나 스레드를 사용하더라도 목적지 도메인 단위로 속도를 제한해야 합니다. IP 분산만 믿고 한 서버에 과도한 트래픽을 집중시키면 
   DDoS 공격으로 간주될 수 있습니다.
4) 캐싱 및 변경 감지 (Conditional GET Requests)
 - HTTP 헤더 활용: If-Modified-Since 또는 ETag 헤더를 활용해 변경된 데이터만 요청합니다.
 - 불필요한 중복 다운로드를 줄임으로써 상대 서버의 네트워크 대역폭과 CPU 부담을 대폭 감소시킵니다.
5) 에러 대응 및 백오프 전략 (Exponential Backoff)
 - 상대 서버에서 429 Too Many Requests나 503 Service Unavailable 응답을 보내면 요청 속도를 즉시 줄이거나 정지합니다.
 - 실패 시 바로 재시도하지 않고, 재시도 간격을 지수적으로 늘려가는 Exponential Backoff 방식을 적용합니다.
```
