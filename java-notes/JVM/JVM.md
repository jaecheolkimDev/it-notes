3\. Region 계산 방식
-------------------
```
JVM은 전체 힙 메모리를 약 2,048개의 Region으로 나누는 것을 목표로 삼습니다.

- 계산 공식: 전체 힙 크기 / 2,048을 한 뒤, 1MB, 2MB, 4MB... 순으로 2의 거듭제곱 값 중 가장 가까운 값을 선택합니다. (최소 1MB ~ 최대 32MB)
    ex) (8GB): 8,192MB / 2,048 = 4MB
```

4\. 거대 객체(Humongous Object)
-------------------
```
기준: 객체 하나가 **Region 크기의 50%(현재 기준 2MB)**를 넘어가면 거대 객체로 취급합니다.

문제점: 1. 이런 거대 객체는 일반적인 Young 영역에서 관리되지 않고 Old 영역으로 바로 들어가거나, 여러 Region을 연속적으로 차지하며 박혀버립니다.
       2. 이렇게 박힌 객체들은 청소하기가 매우 까다로워 GC 효율을 급격히 떨어뜨리고, 결국 **CPU 0%의 'Full GC'**를 유발합니다.
       
해결방안: Region Size를 증가시켜서 '거대 객체'가 아닌 **'일반 객체'**로 취급받도록해서 Young 영역에서 효율적으로 수거되도록 한다.

체감 성능: 메모리 파편화가 줄어들고, GC가 훨씬 더 똑똑하고 빠르게 "슥슥" 지나가게 됩니다.
```
