JAVA JVM 공부 노트
=================
-X나 -XX로 시작하는 이 설정들을 JVM 옵션(JVM 파라미터)이라고 부릅니다

1\. 옵션
-------------------
```
-Xms8g	초기 힙(Heap) 메모리 크기 (Default. 1/64)
    : 시작부터 8GB를 확보하여 메모리 할당 부하를 줄입니다.
-Xmx8g	최대 힙(Heap) 메모리 크기 (Default. 1/4)
    : 가장 중요. 8GB를 넘지 않게 제한합니다.
-XX:+UseG1GC	G1 Garbage Collector 사용	
    : 대용량 메모리에서 '끊김 현상'을 줄이는 최신 알고리즘입니다.
-XX:MaxGCPauseMillis	최대 GC 중단 목표 시간	기본 200ms. 
    : 이 값을 늘리면(예: 500) 배치의 전체 처리량이 좋아집니다.
-XX:InitiatingHeapOccupancyPercent	GC 시작 타이밍(IHOP)	
    : 힙이 몇 % 찼을 때 청소를 시작할지 결정합니다. (기본 45%)
-XX:+HeapDumpOnOutOfMemoryError     : 메모리가 꽉 차서 죽을 때, 당시의 메모리 상태를 파일(.hprof)로 남깁니다. (나중에 범인 잡기용)
-XX:HeapDumpPath=./logs/            : 덤프 파일이 저장될 경로를 지정합니다.
-XX:G1HeapRegionSize=16M            : RegionSize를 16M로 설정

-Xlog:gc* (Java 9 이상)
    : GC가 언제, 얼마나 일어났는지 상세히 기록합니다. 아까 보여주신 CPU 0% 구간이 정말 GC 때문인지 이 로그로 100% 확신할 수 있습니다.
```

2\. 주의사항
-------------------
```
-XX: 뒤에 +가 붙는 건 '사용함'을 뜻하고, =가 붙는 건 '값을 설정함'을 뜻합니다.
```

3\. Region 계산 방식
-------------------
```
JVM은 전체 힙 메모리를 약 2,048개의 Region으로 나누는 것을 목표로 삼습니다.

- 계산 공식: 전체 힙 크기 / 2,048을 한 뒤, 1MB, 2MB, 4MB... 순으로 2의 거듭제곱 값 중 가장 가까운 값을 선택합니다. (최소 1MB ~ 최대 32MB)
    ex) (8GB): 8,192MB / 2,048 = 4MB
```

4\. 거대 객체(Humongous Object)
-------------------
```
기준: 객체 하나가 **Region 크기의 50%(현재 기준 2MB)**를 넘어가면 거대 객체로 취급합니다.

문제점: 1. 이런 거대 객체는 일반적인 Young 영역에서 관리되지 않고 Old 영역으로 바로 들어가거나, 여러 Region을 연속적으로 차지하며 박혀버립니다.
       2. 이렇게 박힌 객체들은 청소하기가 매우 까다로워 GC 효율을 급격히 떨어뜨리고, 결국 **CPU 0%의 'Full GC'**를 유발합니다.
       
해결방안: Region Size를 증가시켜서 '거대 객체'가 아닌 **'일반 객체'**로 취급받도록해서 Young 영역에서 효율적으로 수거되도록 한다.

체감 성능: 메모리 파편화가 줄어들고, GC가 훨씬 더 똑똑하고 빠르게 "슥슥" 지나가게 됩니다. 
         몇분씩 멈추던 시간이 몇 초 단위로 줄어드는 마법이 여기서 일어납니다.
```
