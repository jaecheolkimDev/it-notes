synchronized
=================

1\. 정의
-----------
```
멀티스레드 환경에서 동시성(Concurrency) 문제를 해결하기 위한 스레드 동기화(Synchronization) 제어자입니다.
```

2\. 핵심 개념: 임계 영역과 락(Lock)
-----------
```
1) 임계 영역(Critical Section): 오직 한 스레드만 접근해야 하는 코드 블록 또는 메서드입니다.
2) 모니터 락(Monitor Lock / Intrinsic Lock)
    : 자바의 모든 객체는 내부적으로 하나의 락을 가지고 있습니다. 스레드가 synchronized 블록이나 메서드에 진입하려면 해당 객체의 락을 
      획득해야 하며, 작업이 끝나면 락을 반환합니다. 락을 얻지 못한 다른 스레드는 락이 해제될 때까지 대기(BLOCKED 상태)합니다.
```

3\. 주요 사용 방식
-----------
```
1) 메서드 단위 동기화 (메서드 전체를 임계 영역으로 지정)
 ├─ 인스턴스 메서드  : public synchronized void method()
 │   └─ [락 대상] 현재 인스턴스(this)
 │   └─ [통제 범위] 같은 인스턴스의 다른 synchronized 메서드까지 함께 블로킹됨
 └─ 정적(static) 메서드 : public static synchronized void method()
     └─ [락 대상] 클래스 객체(Class.class)
     └─ [통제 범위] 해당 클래스의 모든 인스턴스 및 static synchronized 영역 통제

2) 블록 단위 동기화 (권장 - 필요한 코드 구간만 임계 영역으로 최소화)
 ├─ 인스턴스 락 (this) : synchronized (this) { ... }
 │   └─ [특징] 지정한 코드만 잠그지만, this(인스턴스) 열쇠를 공유하는 다른 영역에 영향을 줌
 └─ 전용 객체 락 (lock) : synchronized (lock) { ... }  ★ 가장 권장
     └─ [특징] private final Object lock = new Object(); 전용 열쇠 사용
     └─ [장점] 임계 영역 최소화 + 타 로직과의 락 간섭 최소화 (독립적 제어)
```

4\. 사용 시 장단점
-----------
```
1) 장점	
 • 사용법이 매우 직관적이고 간단합니다.
 • JVM 차원에서 지원하므로 락 획득/해제가 자동으로 관리됩니다.

2) 단점	
 • 성능 저하: 락을 얻기 위해 스레드가 대기하므로 병렬 처리 효율이 떨어집니다.
 • 교착 상태(Deadlock): 둘 이상의 스레드가 서로의 락이 해제되기를 기다릴 때 무한 대기에 빠질 위험이 있습니다.
 • 공정성 부재: 먼저 대기한 스레드가 먼저 락을 취득한다는 보장이 없습니다.
```

5\. 대체 및 발전된 대안
-----------
자바 5부터는 java.util.concurrent 패키지를 통해 보다 세밀한 동기화 제어 수단을 제공합니다.
```
1) ReentrantLock: 락의 획득/해제 시점을 명시적으로 제어하며, 타임아웃(tryLock) 및 공정성(Fairness) 설정이 가능합니다.
2) Atomic 클래스 (예: AtomicInteger): 락을 사용하지 않고 CAS(Compare-And-Swap) 알고리즘을 활용해 단일 변수의 동시성을 가볍고 
   빠르게 처리합니다.
3) ConcurrentHashMap / CopyOnWriteArrayList: 컬렉션 자체에서 효율적인 동시성을 제어하는 클래스들입니다.
```
