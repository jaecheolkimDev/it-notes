volatile
=================

1\. 정의
-----------
```
다중 스레드(Multi-thread) 환경에서 변수 값의 '가시성(Visibility)'을 보장하기 위해 사용하는 키워드입니다.
```

2\. 필요한 이유 (메모리 가시성 문제)
-----------
```
문제 상황:
1) 스레드 1(CPU Core 1)이 변수 flag의 값을 true로 변경합니다.
2) 이 변경 사항이 즉시 메인 메모리에 반영되지 않고 Core 1의 CPU 캐시에만 남아있을 수 있습니다.
3) 스레드 2(CPU Core 2)는 메인 메모리나 자신의 CPU 캐시에서 이전 값(false)을 계속 읽어와 무한 루프에 빠지거나 잘못된 로직을 
   수행하게 됩니다.

이처럼 한 스레드가 변경한 값이 다른 스레드에게 보이지 않는 문제를 가시성 문제(Visibility Problem)라고 합니다.
```

3\. 작동 원리
-----------
```
1) 메인 메모리 직접 읽기/쓰기 (Main Memory Direct Access)
 - Read: CPU 캐시가 아닌 메인 메모리에서 직접 값을 읽어옵니다.
 - Write: 값을 변경할 때 즉시 메인 메모리에 기록합니다.
2) 명령어 재배치 금지 (Instruction Reordering Prevent / Happens-Before Guarantee)
 - 컴파일러나 CPU는 성능 최적화를 위해 코드 실행 순서를 임의로 뒤바꿀 수 있습니다(Reordering).
 - volatile 변수에 대한 읽기/쓰기 작업 전후로는 명령어 순서가 넘어가거나 뒤바뀌지 않도록 제한합니다.
```

4\. 사용 시 주의사항 (원자성 부재)
-----------
가시성만 보장할 뿐, 원자성(Atomicity)은 보장하지 않습니다.
```
count++ 작업은 단일 연산이 아니라 내부적으로 3단계로 동작합니다:
1) count 값을 메모리에서 읽기 (Read)
2) 읽어온 값에 +1 가산 (Modify)
3) 새로운 값을 메모리에 쓰기 (Write)

여러 스레드가 동시에 increment()를 호출하면, 두 스레드가 동일한 count 값을 동시에 읽어 동기화 오류(Race Condition)가 발생할 수 
있습니다.
```

5\. 언제 사용해야 할까?
-----------
하나의 스레드만 쓰기 작업을 하고, 나머지 스레드는 읽기만 하는 상태 플래그(Flag) 제어에 가장 적합합니다.
```
구분                                  volatile 적합 여부              대체 방안
단일 스레드 쓰기 / 다중 스레드 읽기       "적합 (상태 플래그, 종료 조건 등)"      -
다중 스레드 쓰기 / 복합 연산 (count++)   부적합                           "synchronized, ReentrantLock, AtomicInteger"
```
