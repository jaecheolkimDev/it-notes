Elasticsearch 명령어 공부 노트
======================

1\. 인덱스 (테이블)
--------------
```
1) 생성
# PUT /{인덱스명}
PUT /users
PUT /boards

2-1) 인덱스 생성/삭제됐는 지 확인하기
# GET /{인덱스명}
GET /users
GET /boards
GET /boards

2-2) 없는 인덱스를 조회했을 때 응답값 확인하기
GET /abc

3) 인덱스 삭제
# DELETE /{인덱스명}
DELETE /boards
```


2\. 매핑 (스키마)
--------------
```
1-1) 매핑 정의하기
# PUT /{인덱스명}/_mappings
PUT /users/_mappings
{
  "properties": {
    "name": { "type": "keyword" },
    "age": { "type": "integer" },
    "is_active": { "type": "boolean" }
  }
}

1-2) 인덱스 생성 + 매핑 정의
PUT /products
{
  "mappings": {
    "properties": {
      "name": {
        "type": "text"
      }
    }    
  }
}


2) 매핑 확인하기
# GET /{인덱스명}
GET /users
```

3\. 도큐먼트 (레코드, 로우)
--------------
```
1-1) 도큐먼트 삽입 (id 자동 생성)
    # POST /{인덱스명}/_doc
    POST /users/_doc
    {
      "name": "Alice",
      "age": 28,
      "is_active": true
    }
    
    POST /users/_doc
    {
      "name": "Bob",
      "age": 30,
      "is_active": false
    }

1-2) 도큐먼트 삽입 (id 직접 지정)
    # POST /{인덱스명}/_create/{id}
    POST /users/_create/1
    {
      "name": "jscode",
      "age": 30,
      "is_active": true
    }
    
    # 이미 존재하는 id로 데이터 저장하면 어떻게 되는 지 확인하기    => 409
    POST /users/_create/1
    {
      "name": "jscode",
      "age": 30,
      "is_active": true
    }
    
1-3) 도큐먼트 저장 및 업데이트 (이미 id가 존재한다면 데이터 덮어씌움 = UPSERT)
    PUT /users/_doc/2
    {
      "name": "jason",
      "age": 30,
      "is_active": true
    }
    
    # 이미 존재하는 id로 데이터 저장하면 어떻게 되는 지 확인하기    => 덮어쓰기
    POST /users/_doc/2
    {
      "name": "jason2", 
      "age": 30,
      "is_active": true
    }
    
1-4) 일부 필드만 수정
    # 특정 도큐먼트 수정
    # POST /{인덱스명}/_update/{id}
    POST /users/_update/2
    {
      "doc": {
          "age": 10,
          "is_active": false
      }
    }

2-1) 모든 도큐먼트 조회
# GET /{인덱스명}/_search
GET /users/_search

2-2) id로 특정 도큐먼트 조회
# GET /{index}/_doc/{id}
GET /users/_doc/1
GET /users/_doc/2

2-3) 특정 조건을 만족하는 도큐먼트 조회 (name 필드에 '맥북 에어 13 M4'가 포함된 도큐먼트 조회)
    GET /products/_search
    {
      "query": {
        "match": {
          "name": "맥북 에어 13 M4" 
        }
      }
    }

2-4) term   : 데이터가 가진 값과 정확히 일치하게 검색하지 않으면 도큐먼트가 조회되지 않는다. 
    GET /boards/_search
    {
      "query": {
        "term": {
          "category": "자유"
        }
      }
    }
    
2-5) terms  : category가 자유 게시판 또는 익명 게시판인 모든 데이터를 조회하고 싶을때 사용한다.
    GET /boards/_search
    {
      "query": {
        "terms": {
          "category": ["자유 게시판", "익명 게시판"]
        }
      }
    }

2-6) bool(filter)   : 2가지 이상 조건 사용
    GET /boards/_search
    {
      "query": {
        "bool": {
          "filter": [
            {
                  "term": {
                    "category": "자유 게시판"
                  }
                },
                {  
                  "term": {
                  "board_id": 1
                }
              }
            ]
        }
      }
    }

2-7) bool(filter, must)   : 2가지 이상 조건 사용
    GET /boards/_search
    {
      "query": {
        "bool": {
          "must": [
            { "match": { "title": "검색엔진" } } // 유연한 검색이 필요 (must)
          ],
          "filter": [
            { "term": { "category": "자유 게시판" } }, // 정확한 검색이 필요 (filter)
            { "term": { "is_notice": false } } // 정확한 검색이 필요 (filter)
          ]
        }
      }
    }

2-8) bool(filter, must, must_not)   : 2가지 이상 조건 사용
    GET /boards/_search
    {
      "query": {
        "bool": {
          "must": [
            { "match": { "title": "검색엔진" } } // 유연한 검색이 필요 (must)
          ],
          "filter": [
            { "term": { "is_notice": false } } // 정확한 검색이 필요 (filter)
          ],
          "must_not": [
            { "term": { "category": "광고 게시판" } }
          ]
        }
      }
    }
    
2-9) range  : 범위 검색
    GET /users/_search
    {
      "query": {
        "bool": {
          "filter": [
            {
              "range": {
                "age": {
                  "gte": 30     // 30살 이상
                }
              }
            },
            {
              "range": {
                "created_at": {
                  "gte": "2025-01-01"       // 2025년 1월 1일 이후
                }
              }
            }
          ]
        }
      }
    }

2-10) should    : 원하는 조건에 가산점 부여
    GET /products/_search
    {
      "query": {
        "bool": {
          "must": [
            {
              "match": {
                "name": "무선 이어폰" 
              }
            }
          ],
          "should": [
            {
              "range": {
                "rating": {
                  "gte": 4.5 // 4.5 이상의 평점의 상품일 경우 score에 가산점 부여
                }
              }
            },
            {
              "range": {
                "likes": {
                  "gte": 100 // 좋아요 수가 100개 이상인 상품일 경우 score에 가산점 부여
                }
              }
            }
          ]
        }
      }
    }
        
2-11) 오타가 어느 정도 포함되어 있어도 검색되게 만들기
    GET /boards/_search
    {
      "query": {
        "match": {
          "title": {
            "query": "elastiksearch",
            "fuzziness": "AUTO"         // fuzziness : AUTO : 단어 길이에 따라 오타 허용 개수를 자동으로 설정
          }
        }
      }
    }
    
2-12) 제목과 내용에 포함되는 검색어로 검색하기
    GET /boards/_search
    {
      "query": {
        "multi_match": {
          "query": "엘라스틱서치 적용 후기",
          "fields": ["title", "content"]
        }
      }
    }
        
2-13) 제목에 가중치 부여해서 검색하기
    GET /boards/_search
    {
      "query": {
        "multi_match": {
          "query": "엘라스틱서치 적용 후기",
          "fields": ["title^2", "content"] // title에 2배 더 높은 score를 부여
        }
      }
    }
    
2-14) 검색한 키워드를 하이라이팅 처리하고 싶을 때 (highlight)
    GET /boards/_search
    {
      "query": {
        "multi_match": {
          "query": "엘라스틱서치 적용 후기",
          "fields": ["title", "content"]
        }
      },
      "highlight": {
        "fields": {
          "title": {
            "pre_tags": ["<mark>"],
            "post_tags": ["</mark>"]
          },
          "content": {
            "pre_tags": ["<b>"],
            "post_tags": ["</b>"]
          }
        }
      } 
    }

2-15) 페이지네이션 적용시켜서 데이터 불러오기
    // 1 페이지
    GET /boards/_search
    {
      "query": {
        "match": {
          "title": "글"
        }
      },
      "size": 3,
      "from": 0
    }
    
    // 2 페이지
    GET /boards/_search
    {
      "query": {
        "match": {
          "title": "글"
        }
      },
      "size": 3,
      "from": 3
    }
    
    // 3 페이지
    GET /boards/_search
    {
      "query": {
        "match": {
          "title": "글"
        }
      },
      "size": 3,
      "from": 6
    }

2-16) 좋아요 수(likes)를 내림차순으로 정렬해보자. 
    GET /boards/_search
    {
      "query": {
        "match": {
          "title": "글"
        }
      },
      "sort": [
        {
          "likes": {
            "order": "desc"
          }
        }
      ]
    }

2-17) 특수 가전제품 카테고리의 상품만 검색하고 싶을 때
    PUT /products
    {
      "mappings": {
        "properties": {
          "name": {
            "type": "text",
            "analyzer": "nori"
          },
          "category": {
            "type": "text",         // text, keyword 타입의 형태로 나눠서 보관하게 된다. 
            "analyzer": "nori",
            "fields": { 
              "raw": { // 서브 필드명 (다른 이름으로 설정해도 됨)
                "type": "keyword"   // text, keyword 타입의 형태로 나눠서 보관하게 된다. 
              }
            }
          }
        }
      }
    }
    POST /products/_search
    {
      "query": {
        "term": {
          "category.raw": "특수 가전제품"
        }
      }
    }
    
2-18) 검색 키워드를 일부 입력했을 때 검색어를 추천해주는 기능 (자동 완성 기능)
    GET /products/_search
    {
      "query": {
        "multi_match": {                // 여러 필드에 걸쳐서 데이터 검색
          "query": "돌김", 
          "type": "bool_prefix",        // 앞쪽 단어는 match, 마지막 단어는 prefix match
          "fields": [
            "name",
            "name._2gram",
            "name._3gram"
          ]
        }
      }
    }

DELETE /users/_doc/2
```

4\. 문법 (Analyze API)
--------------
```
1) 기본 애널라이저 설정 방법
    1-1) standard만 명시
        GET /_analyze
        {
          "text": "Apple 2025 맥북 에어 13 M4 10코어",
          "analyzer": "standard"
        }

    1-2) standard analyer의 구성을 직접 명시
        GET /_analyze 
        {
          "text": "Apple 2025 맥북 에어 13 M4 10코어",
          "char_filter": [],
          "tokenizer": "standard",  // 공백 또는 ,, ., !, ?와 같은 문장 부호를 기준으로 문자열을 자름
          "filter": ["lowercase"]   // 소문자로 변환
        }

2) 특정 인덱스의 필드에 적용된 Analyzer를 활용해 분석
    GET /boards/_analyze
    {
      "field": "content",
      "text": "<h1>Running cats, jumping quickly — over the lazy dogs!</h1>"
    }



// 인덱스 생성 + 매핑 정의 + Custom Analyzer 적용
PUT /products
{
  "settings": {
    "analysis": {
      "analyzer": {
        "products_name_analyzer": {
          "char_filter": [],
          "tokenizer": "standard",
          "filter": []
        }
      }
    }
  },
  "mappings": {
	  "properties": {
	    "name": {
	      "type": "text",
	      "analyzer": "products_name_analyzer"
	    }
	  }
	}
}


// 인덱스 생성 + 매핑 정의 + Custom Analyzer 적용
PUT /boards
{
  "settings": {
    "analysis": {
      "analyzer": {
        "boards_content_analyzer": {
          "char_filter": ["html_strip"],
          "tokenizer": "standard",
          "filter": ["lowercase"]
        }
      }
    }
  },
  "mappings": {
	  "properties": {
	    "content": {
	      "type": "text",
	      "analyzer": "boards_content_analyzer"
	    }
	  }
	}
}


// 인덱스 생성 + 매핑 정의 + Custom Analyzer 적용
PUT /products
{
  "settings": {
    "analysis": {
      "filter": {
        "products_synonym_filter": {
          "type": "synonym",
          "synonyms": [
            "notebook, 노트북, 랩탑, 휴대용 컴퓨터, laptop",
            "samsung, 삼성"
          ]
        }
      },
      "analyzer": {
        "products_name_analyzer": {
          "char_filter": [],
          "tokenizer": "standard",
          "filter": [
            "lowercase",
            "products_synonym_filter"
          ]
        }
      }
    }
  },
  "mappings": {
	  "properties": {
	    "name": {
	      "type": "text",
	      "analyzer": "products_name_analyzer"
	    }
	  }
	}
}
```

5\. Nori(노리) Analyzer
--------------
```
1) 기본 애널라이저 설정 방법
    1-1) nori만 명시
        GET /_analyze
        {
          "text": "백화점에서 쇼핑을 하다가 친구를 만났다.",
          "analyzer": "nori"
        }


    1-2) nori analyzer의 구성을 직접 명시
        GET /_analyze
        {
          "text": "백화점에서 쇼핑을 하다가 친구를 만났다.",
          "char_filter": [], 
            "tokenizer": "nori_tokenizer", 
            "filter": ["nori_part_of_speech", "nori_readingform", "lowercase"]
        }
```

6\. 매핑_다양한 타입
--------------
```
1) 매핑 정의 + 인덱스 생성
    PUT /product_reviews
    {
      "mappings": {
        "properties": {
          "review_id": {
            "type": "long" // 현업에서 확장성을 고려해 integer가 아닌 long으로 셋팅하는 편
          },
          "user_id": {
            "type": "long" // 현업에서 확장성을 고려해 integer가 아닌 long으로 셋팅하는 편
          },
          "user_name": {
            "type": "text" // 일부분으로도 검색할 수 있게 설정 (만약 부분 검색이 필요 없다면 keyword로 설정)
          },
          "categories": {
            "type": "keyword" // 정확한 비교로만 사용하기 때문에 keyword로 설정
          },
          "rating": {
            "type": "double" // 소수점을 가진 숫자이므로 double로 설정
          },
          "is_verified_purchase": {
            "type": "boolean" 
          },
          "review_date": {
            "type": "date" // 날짜 데이터
          },
          "review_text": {
            "type": "text" // 유연하게 검색할 수 있도록 text 설정
          }
        }
      }
    }
```
