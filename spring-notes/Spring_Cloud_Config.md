Spring Cloud Config
=================

1\. 개념
---------------
"중앙 집권식 설정 관리"
```
MSA에서 각 서비스의 설정(application.yml)을 로컬이 아닌 **원격 저장소(Git, 파일 시스템 등)**에 두고 중앙에서 관리하는 시스템입니다.
```

2\. 왜 로컬 yml보다 원격 서버 설정이 우선할까?
---------------
```
클라우드 환경이나 MSA에서는 애플리케이션을 빌드하여 배포한 후에도 설정(DB 접속 정보, API 키 등)을 유연하게 변경할 수 있어야 합니다.
만약 로컬 yml 파일이 우선순위를 가진다면, 설정을 바꿀 때마다 코드를 다시 빌드하고 배포해야 하므로 중앙 관리의 의미가 퇴색됩니다. 
따라서 스프링 부트는 기본적으로 원격 Config Server에서 가져온 설정(설정 덤프)을 로컬 파일(application.yml)보다 더 높은 우선순위로 
병합(Merge)하거나 덮어씁니다.
```

3\. bootstrap.yml
---------------
스프링 부트 애플리케이션이 구동될 때, 일반적인 application.yml을 읽기 전 가장 먼저(초기화 단계) 읽는 설정 파일입니다.
```
보통 "원격 Config 서버의 주소가 어디인지"에 대한 정보가 적혀 있습니다. 애플리케이션은 이 파일을 보고 원격 서버에 접속해 설정 값들을 
덤프(가져오기)합니다.
```
