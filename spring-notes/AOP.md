AOP (Aspect Oriented Programming, 관점 지향 프로그래밍)
=================

1\. 개념
------------------
```
핵심 로직(Core Concern) 과 공통 로직(Cross-cutting Concern) 을 분리하여, 공통 기능을 횡단 관심사(Aspect) 로 관리하는 방식
    → 예: 로깅, 트랜잭션, 보안 처리 등
    > 횡단 관심사 : 여러 서비스에서 공통적으로 쓰이는 것
    > AOP를 사용하지 않으면 모든 메서드마다 session.beginTransaction(), commit(), rollback() 같은 코드를 직접 작성해야 합니다.
      하지만 AOP를 적용하면 "이 메서드는 트랜잭션 안에서 실행되어야 해"라는 설정만으로 트랜잭션 처리를 외부에서 주입할 수 있습니다.
    > 스프링은 AOP를 구현하기 위해 프록시 패턴을 사용합니다. 
      우리가 @Transactional이 붙은 빈을 호출할 때, 스프링은 원본 객체 대신 이를 감싸고 있는 프록시 객체를 주입해 줍니다.
```

2\. 포인트컷(Pointcut)
------------------
AOP(관점 지향 프로그래밍)에서 부가 기능을 적용할 위치를 지정하는 것
```
메소드명, 패키지명뿐만 아니라 파라미터 타입, 어노테이션, 심지어 클래스 상속 구조까지 정말 다양하고 정교하게 타겟을 잡아낼 수 있습니다.
```

3\. 패키지명 기준으로 잡기
------------------
특정 패키지 또는 그 하위 패키지에 속한 모든 클래스의 메소드를 타겟으로 삼을 수 있습니다.
```
within(com.example.service..*)
    com.example.service 패키지 및 그 하위 패키지(..)에 있는 모든 메소드를 잡습니다.
execution(* com.example.controller.*.*(..))
    controller 패키지 바로 밑에 있는 클래스의 모든 메소드를 잡습니다.
```

4\. 메소드명 기준으로 잡기
------------------
특정 단어로 시작하거나 끝나는 메소드만 쏙 골라낼 수 있습니다. (가장 흔하게 쓰이는 방식입니다.)
```
execution(* *.get*(..))
    메소드 이름이 get으로 시작하는 모든 메소드를 잡습니다. (예: getName(), getUserId())
execution(* *.*Save(..))
    메소드 이름이 Save로 끝나는 모든 메소드를 잡습니다.
```

5\. 클래스 및 인터페이스 기준으로 잡기
------------------
특정 클래스 내부의 메소드나, 특정 인터페이스를 구현한 구현체들을 타겟으로 잡습니다.
```
execution(* com.example.service.OrderService.*(..))
    OrderService 클래스(또는 인터페이스) 안에 있는 모든 메소드를 잡습니다.
```

6\. 어노테이션 기준으로 잡기 (강력 추천)
------------------
패키지나 메소드명이 제각각이어도, 내가 만든 커스텀 어노테이션이나 Spring이 제공하는 어노테이션이 붙은 곳만 정확하게 낚아챌 수 있습니다.
```
@annotation(com.example.annotation.LogExecutionTime)
    메소드에 @LogExecutionTime이라는 어노테이션이 붙은 메소드만 잡습니다.
@within(org.springframework.web.bind.annotation.RestController)
    클래스 레벨에 @RestController가 붙은 모든 컨트롤러의 메소드를 잡습니다.
```

7\. 매개변수(파라미터) 기준으로 잡기
------------------
메소드가 받는 파라미터의 타입이나 개수를 기준으로도 필터링이 가능합니다.
```
execution(* *(String, ..))
    첫 번째 파라미터 타입이 무조건 String인 메소드만 잡습니다.
execution(* *(..))
    파라미터가 없든, 있든, 몇 개든 상관없이 모든 메소드를 잡습니다. (..이 와일드카드 역할을 합니다.)
```
