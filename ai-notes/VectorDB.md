AI 벡터 DB 공부 노트
======================


1\. 임베딩 벡터 저장 (Storage)
--------------
```
메모리나 디스크에 임베딩된 고차원 배열(예: 1536차원의 float 배열)을 효율적으로 저장하는 공간이 필요합니다. 
자바로 치면 Map<String, float[]> 구조를 디스크 파일 시스템이나 메모리에 최적화하여 압축 저장하는 포맷입니다.
```

2\. 고속 검색을 위한 '인덱싱(Indexing)' 알고리즘
--------------
Vector DB 구현의 핵심이자 기술력의 중추입니다. 데이터를 그냥 쌓아두는 게 아니라, 검색하기 좋은 '구조'로 가공합니다.
```
가장 유명한 알고리즘 두 가지는 다음과 같습니다.
1) HNSW (Hierarchical Navigable Small World): 현재 가장 많이 쓰이는 그래프 기반 알고리즘입니다. 벡터들을 서로 거리가 가까운 것끼리 선으로 연결해 
    둡니다. 거대한 지도에서 '대도시 ➡️ 소도시 ➡️ 우리 동네' 순으로 찾아가듯, 상위 레이어에서 크게 건너뛰며 가다가 목적지 근처에서 촘촘하게 링크를 타고
    들어가 가장 유사한 벡터를 찾습니다.
2) IVF (Inverted File Index): 전체 벡터 공간을 K-Means 클러스터링 같은 알고리즘으로 여러 개의 방(Cluster)으로 나눕니다. 질문이 들어오면 
    "이 질문은 3번 방이랑 가장 가깝네?"라고 판단한 뒤, 3번 방 안에 있는 벡터들과만 유사도를 계산합니다. 전체를 다 뒤질 필요가 없어 속도가 빠릅니다.
```

3\. 유사도 측정 엔진 (Distance Metrics)
--------------
두 벡터가 얼마나 닮았는지 계산하는 수학적 연산기입니다.
```
1) 코사인 유사도(Cosine Similarity): 벡터의 크기(길이)와 상관없이 '방향'이 얼마나 일치하는지 파악 (RAG에서 가장 흔히 씀)
2) 내적(Dot Product): 벡터의 방향과 크기를 모두 고려 (임베딩 모델이 정규화되어 있을 때 매우 빠름)
3) 유클리드 거리(L2 Distance): 다차원 공간에서 두 점 사이의 절대적인 직선거리
```
