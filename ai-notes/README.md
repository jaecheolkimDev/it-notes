AI 공부 노트
======================

1\. RAG(Retrieval-Augmented Generation, 검색 증강 생성)
--------------
AI에게 오픈북 테스트를 시키는 기술
```
1) 필요성
 - 할루시네이션(환각) 방지: AI가 모르는 걸 아는 척 거짓말하는 것을 막습니다. "문서에 있는 내용만 기반으로 답해줘"라고 강제할 수 있기 때문입니다.
 - 최신성 유지: 모델을 새로 학습(파인튜닝)하지 않아도, 최신 엑셀 파일이나 PDF만 폴더에 넣어주면 AI가 바로 그 내용을 인식합니다.
 - 데이터 보안 및 권한 관리: AI 모델 자체에는 민감 정보를 학습시키지 않고, 사용자의 권한에 맞는 문서만 검색해서 보여주도록 설계할 수 있습니다.
 
2) 작동 원리
 2-1) 데이터 수집 및 분할 (Indexing): 사내 가이드라인(PDF, Docx)이나 DB 데이터를 작은 조각(Chunk)으로 자릅니다.
 2-2) 벡터화 (Embedding): 자른 텍스트를 AI가 이해할 수 있는 숫자(벡터)로 변환하여 벡터 데이터베이스에 저장합니다.
 2-3) 검색 (Retrieval): 사용자가 질문을 하면, 질문과 의미가 가장 유사한 문서 조각을 벡터 DB에서 찾아냅니다.
 2-4) 답변 생성 (Generation): AI에게 "찾아낸 문서 내용들을 참고해서 질문에 답해줘"라고 명령(Prompt)을 내립니다.
 
3) RAG 기반 대화형 모델의 특징
1. 단순 답변을 넘어선 '맥락 있는 대화'
    RAG는 질문이 들어오면 내부 지식(PDF, DB 등)에서 관련 내용을 먼저 찾습니다. 그 내용을 AI에게 전달할 때 "이전 대화 내용"도 함께 전달하기 때문에, 
    사용자가 "아까 말한 그 에러 다시 설명해줘"라고 해도 찰떡같이 알아듣고 대화를 이어갈 수 있습니다.
2. '모른다'고 말할 줄 아는 정직한 AI (Hallucination 방지)
    일반 AI는 모르는 것도 지어내지만, RAG는 "준비된 문서(파프리카 가이드 등)에 해당 내용이 없습니다"라고 대답하도록 설정할 수 있습니다. 
    금융권이나 전문 기술 분야에서 가장 중요한 '신뢰도'를 확보할 수 있는 핵심입니다.
3. 실시간 지식 업데이트 (재학습 없는 지식 확장)
    대화형 모델을 새로 학습시키려면 엄청난 시간과 비용이 들지만, RAG는 새로운 엑셀 파일이나 PDF를 폴더에 넣는 것만으로도 5분 뒤에 그 내용을 바탕으로 
    대화가 가능해집니다.
```

2\. LLM(Large Language Model, 거대 언어 모델)
--------------
수조 개의 문장 데이터를 학습하여 인간처럼 언어를 이해하고 생성할 수 있도록 설계된 인공지능 모델입니다.
```
1)
    L(Large): 모델을 구성하는 파라미터(매개변수)의 수가 수십억~수천억 개에 달할 정도로 거대합니다.
    L(Language): 텍스트를 입력받아 텍스트를 출력하는 언어 처리에 특화되어 있습니다.
    M(Model): 복잡한 신경망 구조(Transformer 아키텍처)를 가진 소프트웨어 덩어리입니다.

2) 주요 특징
    ① In-Context Learning (문맥 학습)
        모델을 새로 학습시키지 않아도, 질문(Prompt) 안에 정보를 넣어주면 그 정보를 즉시 이해하고 답변에 활용합니다. (RAG의 핵심 원리입니다.)
    ② Zero-shot / Few-shot 능력
        한 번도 해보지 않은 작업(Zero-shot)이나 몇 가지 예시(Few-shot)만 보고도 번역, 요약, 코딩 등의 복잡한 업무를 수행합니다.
    ③ Hallucination (환각 현상)
        매우 그럴듯하게 들리지만 사실이 아닌 거짓 정보를 생성하는 특성이 있습니다. 이를 제어하기 위해 RAG 같은 기술을 접목합니다.

3) 관련 용어
    Parameter (파라미터): AI의 '지능'을 결정하는 입자입니다. 보통 Llama 3 8B에서 8B는 파라미터가 80억 개(8 Billion)라는 뜻입니다.
    Token (토큰): LLM이 텍스트를 처리하는 최소 단위입니다. 문장은 여러 개의 토큰으로 쪼개져 처리됩니다.
    Context Window (컨텍스트 창): 한 번에 입력받을 수 있는 최대 정보량입니다. 이 창이 클수록 긴 문서를 참조하기 유리합니다.
    Quantization (양자화): 모델의 정밀도를 낮춰(예: 16bit → 4bit) 성능 하락을 최소화하면서 용량과 메모리 점유율을 1/4 수준으로 줄이는 
                          기술입니다.
```

3\. sLLM(Small Large Language Model, 소형 거대언어모델)
--------------
수천억 개의 파라미터를 가진 거대 모델(LLM)과 달리, 파라미터 수를 수십억~백억 개(7B, 8B, 10B 등) 수준으로 줄인 모델을 의미합니다.
```
1)
    S (Small): 모델의 크기가 작아 메모리(RAM) 점유율이 낮습니다.
    LLM (Large Language Model): 그럼에도 불구하고 언어 이해 및 생성 능력은 거대 모델의 핵심 기능을 유지합니다.
    
2) 핵심 가치
    ① 하드웨어 제약 극복        : GPT-4 같은 모델은 수천 대의 GPU가 필요하지만, sLLM(예: Llama 3 8B)은 양자화(Quantization) 기술을 
                                적용하면 개발자님이 확인하신 8~16GB RAM 환경의 일반 CPU 서버에서도 충분히 돌아갑니다.
    ② 데이터 보안 (Privacy)    : 외부 API를 호출하지 않고 사내 서버 내에서만 연산이 이뤄집니다. 금융권처럼 데이터 유출에 민감한 환경에서 
                                폐쇄망 AI를 구축할 수 있는 유일한 대안입니다.
    ③ 특정 도메인 최적화        : 모델이 작기 때문에 특정 업무(보험, 금융, 코딩 가이드 등)에 맞게 파인튜닝(Fine-tuning)하거나 
                                RAG를 접목했을 때 반응 속도가 빠르고 효율적입니다.
    
3) 대표적인 오픈소스 sLLM 모델 
    모델명	        제작사	    특징
    Llama 3 (8B)	Meta	    현재 전 세계적으로 가장 널리 쓰이며 성능이 검증된 모델.
    Gemma (7B)	    Google	    구글의 기술력을 바탕으로 만든 가볍고 똑똑한 모델.
    Mistral (7B)	Mistral AI	유럽에서 만든 모델로, 효율성과 추론 속도가 매우 뛰어남.
    Solar (10.7B)	Upstage	    한국어 성능이 매우 뛰어나 국내 기업용 프로젝트에 최우선 고려됨.
    
4) 기술 포인트
    양자화 (Quantization)          : 모델의 가중치를 16bit에서 4bit로 압축하여 성능은 유지하면서 메모리 사용량을 1/4로 줄이는 기술입니다. 
                                    (예: GGUF 포맷)
    추론 엔진 (Inference Engine)    : 모델을 실제로 구동하는 엔진입니다. Ollama, llama.cpp 등이 있으며, 이 엔진들이 REST API를 제공하므로 
                                     자바(JDK 1.8)와 연동이 가능합니다.
    토큰 처리 (Tokenization)        : sLLM은 한 번에 처리할 수 있는 토큰 양(Context Window)이 거대 모델보다 작을 수 있습니다. 
                                     따라서 RAG 구현 시 문서를 잘게 잘라서 필요한 것만 넣어주는 전략이 중요합니다.
```

4\. 파인튜닝(Fine-tuning)
--------------
이미 방대한 데이터로 학습된 기본 모델(Pre-trained Model)에 나의 특정 데이터(보험 도메인 지식, 사내 코딩 컨벤션 등)를 추가로 학습시켜
내 입맛에 맞게 업그레이드하는 과정입니다.
```
1) 학습 방식 선택 (LoRA / QLoRA)
LoRA    : 모델 전체를 건드리는 것이 아니라 일부만 수정하기 때문에 학습 속도가 빠르고 낮은 사양의 GPU(VRAM 24GB 수준)에서도 가능합니다.
QLoRA   : LoRA를 더 압축한 방식으로, 더 낮은 사양에서도 돌아가게 만듭니다.

2) 학습 실행 및 병합
준비된 데이터를 학습 엔진(Hugging Face의 trl 라이브러리 등)에 넣고 돌립니다. 학습이 끝나면 원본 모델에 학습된 가중치(Weight)를 합쳐서(Merge) 
최종 모델을 완성합니다.

3) 파인튜닝 도구
    Axolotl: 설정 파일(YAML) 하나로 파인튜닝을 자동화해 주는 도구입니다. 최근 가장 많이 쓰입니다.
    Unsloth: 파인튜닝 속도를 2~5배 이상 높여주고 메모리 사용량을 획기적으로 줄여주는 라이브러리입니다. (Llama 3, Gemma 등 지원)
    AutoTrain: GUI 기반으로 데이터만 넣으면 알아서 학습해 주는 도구입니다.
```
