임베딩 모델(Embedding Model)
======================

1\. 개념
--------------
"인간의 언어(텍스트)를 컴퓨터가 이해할 수 있는 '의미 있는 숫자 목록(벡터, Vector)'으로 번역해 주는 통역사"입니다.
```
```

2\. 비교가 아닌 의미와 맥락으로 표현 
--------------
```
과거에는 단순히 글자 그대로 비교(Keyword Matching)를 했습니다. 글자가 다르면 찾아내지 못합니다.
이 문제를 해결하기 위해 단어가 가진 '의미'와 '맥락'을 숫자로 바꾸어 표현해야 하는데, 이 역할을 하는 알고리즘이 바로 임베딩 모델입니다.
```

3\. 임베딩 모델이 일하는 방식 (좌표계 비유)
--------------
```
임베딩 모델은 단어나 문장을 수백~수천 개의 숫자로 이루어진 배열(이것을 벡터라고 합니다)로 만듭니다. 이 숫자들은 사실상 "의미의 지도 위의 
주소(좌표)"와 같습니다.

지도 위의 좌표를 통해 비슷한 의미인지 다른 의미인지 알아냅니다.

실제 임베딩 모델은 이런 기준(차원)을 1,536개 정도로 매우 조밀하게 쪼개서 문장의 미묘한 어조나 맥락까지 숫자로 녹여냅니다.
```

4\. 종류
--------------
```
1) OpenAI의 text-embedding-3-small
2) Upstage의 임베딩 모델
```

5\. 문장도 임베딩이 되나요?
--------------
```
단어뿐만 아니라 긴 문장이나 문서 전체도 숫자로 바꿀 수 있습니다. 임베딩 모델은 문맥을 파악하기 때문에 신기하게도 글자는 다르지만 의미가 통하는 문장들을 
비슷한 숫자로 변환합니다.
```

6\. RAG 파이프라인에서의 역할
--------------
```
벡터 DB에 저장되는 데이터의 정체가 바로 이 임베딩 모델이 만든 '숫자 배열(벡터)'입니다.

내 문서 임베딩: 회사 규정집(텍스트)을 임베딩 모델에 넣어서 숫자(벡터)로 변환 후 벡터 DB에 저장.
질문 임베딩: 사용자가 "나 휴가 언제 써?"라고 질문하면, 이 질문도 똑같은 임베딩 모델에 넣어서 숫자로 변환.
유사도 검색: 벡터 DB 안에서 사용자의 질문 숫자와 가장 근접한 숫자를 가진 문서 조각을 찾아냄 (이게 바로 Retrieval 단계).

임베딩 모델은 텍스트를 컴퓨터가 계산할 수 있는 '의미 기반의 숫자 주소(벡터)'로 바꾸어 주는 핵심 AI 엔진입니다. 이 주소가 있어야 벡터 DB가 유사한 
내용을 찾아낼 수 있습니다.
```
