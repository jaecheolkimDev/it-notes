2\. 우분투(Debian 계열)와 레드햇(RHEL/CentOS 계열) 리눅스 비교
-----------------------
```
공통점: 리눅스 커널 기반으로 대부분의 기본 명령어 (ls, cd, grep, ps, top, vi 등)는 동일하게 사용 가능합니다.
차이점: 패키지 설치/관리가 가장 큰 차이점이며, 이는 apt vs yum/dnf 명령어와 .deb vs .rpm 패키지 파일에서 발생합니다.
선택: 서버용은 RHEL/CentOS 계열, 데스크톱 및 초보자에게는 Ubuntu가 일반적으로 선호됩니다. 
```

3\. 개념
-----------------------
```
옵션 : 일반적으로 short option은 하이픈 한 개(-)로 시작하고, long option은 하이픈 두 개(--)로 시작한다. 
 **여러 옵션을 같이 쓸 수 있다.** 
  - 하나의 명령어에서 여러 옵션을 함께 쓸 수 있다. (`ls -l -a`)
  - short option과 long option을 같이 쓸 수 있다. (`ls -l --all`)
  - 옵션끼리는 순서가 상관없다. (`ls -a -l` = `ls -l -a`)
  - short option은 묶어서 한 번에 쓸 수 있다. (`ls -a -l` = `ls -al` = `ls -la`)
  
경로
 - 절대 경로 : **루트 디렉터리를 기준으로** 파일 위치를 표현(경로가 `/`로 시작하면 무조건 절대 경로다.)
 - 상대 경로 : **현재 디렉터리를 기준으로** 파일 위치를 표현(경로가 `/` 이외의 문자로 시작한다.)
  - `.` : 현재 디렉터리 경로를 의미(= `./`)
  - `..` : 상위 디렉터리 경로를 의미
  
홈 디렉터리(~) : /home/{사용자명}
```

4\. 사용자 / 그룹 / 권한
-----------------------
1) 사용자
```
1) 슈퍼 사용자(관리자) : 시스템의 모든 권한을 가진 계정
- 어떠한 제한도 없이 모든 명령어를 실행시킬 수 있으며 모든 파일을 조작할 수 있다.
- 실수로 중요한 시스템 파일을 지우는 것도 가능하므로, 안전을 위해 평소에는 일반 사용자 계정을 사용하는 것을 추천한다.
- 일반적으로 `root` 계정이 슈퍼 사용자로 설정되어 있다.
- 슈퍼 사용자로 전환되면 입력창에서 $가 #으로 바뀐다.(직관적으로 알려주기 위해서)

2) 일반 사용자
- 권한이 허용된 명령어만 실행시킬 수 있고, 권한이 허용된 파일만 조작할 수 있다.
- 실수로 중요한 시스템 파일을 지우는 것이 불가능하다.
- ex) `ubuntu`

3) 명령어
    whoami      : 현재 접속해있는 사용자 계정을 알려준다.
    sudo su     : 슈퍼 사용자(root 계정)로 접속하는 방법
    su [사용자명] : 일반 사용자(ubuntu 계정)로 접속하는 방법
```
2) 그룹
```
1) 리눅스에서 그룹(group)이란 사용자 계정을 묶어서 관리하기 위한 단위이다.
   여러 사용자에게 공통된 권한을 한 번에 부여하고 관리할 때 유용하게 사용된다.

2) 특징
- 한 사용자(user)는 무조건 하나의 그룹(group)에 속해야 한다.
- 한 사용자(user)는 여러 그룹(group)에 속할 수 있다.

3) 명령어
    # groups [사용자명]
    $ groups ubuntu
    ubuntu : ubuntu adm cdrom sudo dip lxd
    - `ubuntu` 사용자는 `ubuntu`, `adm`, `cdrom`, `sudo`, `dip`, `lxd`라는 그룹에 속해있다. 
    
    $ groups root
    root : root
    - `root` 사용자는 `root`라는 그룹에만 속해있다.
    
    $ id [사용자] : 특정 사용자의 기본 그룹(primary group) 확인 방법
    $ id ubuntu
    uid=1000(ubuntu) gid=1000(ubuntu) groups=1000(ubuntu),4(adm),24(cdrom),27(sudo),30(dip),105(lxd)
    - ubuntu 사용자는 여러 그룹에 속해있다. 그 중에서 gid=1000(ubuntu)의 괄호 안에 설정되어 있는 값이 기본 그룹(primary group)이다. 
    
4) 소유 그룹
- 파일을 생성한 사용자의 기본 그룹(primary group)으로 자동 설정된다. (소유 그룹을 변경할 수도 있다.) 
```
3) 권한
```
1) 리눅스에서는 여러 사용자 계정을 만들어서 사용할 수 있다고 했다.
   그러다보니 특정 사용자가 다른 사용자의 파일을 마음대로 접근하는 걸 막기 위해 권한(Permission)이라는 기능을 추가했다.
   권한(Permission)을 활용하면 특정 사용자에 대해서만 특정 파일 또는 디렉터리에 접근할 수 있게 만들 수 있다.
   
2) 리눅스의 모든 파일에는 ‘누구에게 어떤 권한까지 허용할 지’와 ‘소유자’와 ‘소유 그룹’이 설정되어 있다.
   파일에서 이 정보를 직접 눈으로 확인해보자. 
   
3) -rwxrw-r--
   ↑↑  ↑  ↑
  ①②  ③ ④
  
 ①1번째 글자 : 파일 유형(File Type)을 의미
    - `-` : 일반 파일
    - `d` : 디렉터리
    - `l` : 심볼링 링크를 의미한다. (심볼릭 링크가 뭔지 아직 알 필요 없다.)
 ②2~4번째 글자 : 소유자에게 허용된 권한을 의미
    
    **[일반 파일인 경우]**
    
    - `r`(read) : 파일을 읽을 수 있다. (= 파일 내부 내용 확인 가능)
    - `w`(write) : 파일을 수정할 수 있다.
    - `x`(execute) : 파일을 실행할 수 있다. (실행 파일 또는 쉘 스크립트인 경우)
    
    * 권한을 `r`, `w`, `x`의 순서로 표시한다. 해당 권한이 없을 경우 `-`로 표시한다. 
    
    **[디렉터리인 경우]**
    
    - `r` : 디렉터리 내부 파일 조회(`ls`)가 가능하다.
    - `w` : 디렉터리 내부에 파일을 생성/삭제할 수 있다.
    - `x` : 디렉터리 내부로 접근(`cd`)할 수 있다.
    
    ** 디렉터리 내부의 파일을 생성/삭제(`w`)하려면 접근 권한(`x`)이 필수다. 그러다보니 대부분의 경우에는 디렉터리에 `w` 권한을 부여하고 싶다면 `x` 권한도 같이 부여하는 편이다. 
    
 ③5~7번째 글자 : 소유 그룹에게 허용된 권한을 의미
    
    (2번의 내용과 동일)
 ④8~10번째 글자 : 그 외의 사용자에 허용된 권한을 의미
    ** 그 외의 사용자 : 소유자도 아니고, 소유 그룹에 속하지도 않은 사용자인 경우
    
    (2번의 내용과 동일)
    
4) 권한 변경하는 방법 (chmod) : 숫자 3개를 활용해서 변경할 권한을 설정한다. 각 권한은 아래와 같이 해당하는 숫자가 있다. 이 숫자를 더해서 변경할 권한을 설정할 수 있다. 
────────────────────────────────
│ r (읽기) │ w (쓰기) │ x (실행) │
────────────────────────────────
│ 4	      │ 2	     │ 1       │
────────────────────────────────
- 사용 예시:
    - $ chmod 777 script.sh     : script.sh에 rwxrwxrwx 권한 부여
        - 7 : 4+2+1 이면 모든 권한을 부여함.(rwx)
    - $ chmod 644 file.txt      : file.txt에 rw-r--r-- 권한 부여
        - 6 : 4+2 이면 (rw-)
        - 5 : 4+1 이면 (r-x)
        - 4 : 4 이면 (r--)
    - $ chmod 755 secret.txt    : secret.txt에 rwxr-xr-x 권한 부여
        - 3 : 2+1 이면 (-rx)
        - 2 : 2 이면 (-w-)
        - 1 : 1 이면 (--x)
    - $ chmod 444 readme.md     : readme.md파일을 읽기전용으로 만들기.
    
    - $ chmod +x first.sh       : 모든 사용자에게 실행 권한(x)을 추가(+)하겠다는 의미이다. 
    
5) 어떠한 제약도 없이 모든 기능을 사용할 수 있는 관리자 권한 (sudo)
- 권한이 없을때 해결하는 방법
 - 슈퍼 사용자(root 사용자)로 접근해서 명령어 실행
  - $ sudo su                     : root 사용자로 전환
 - 일반 사용자가 슈퍼 사용자처럼 명령어를 실행하거나 파일에 접근할 수 있는 방법.
  - $ sudo [실행시키고자 하는 명령어]
 - 파일의 권한 바꾸기.
* root 사용자로 아예 전환해서 명령어를 조작하다보면 실수로 시스템에 치명적인 명령어를 입력해 시스템이 손상될 수도 있다.
  그래서 일반 사용자로 명령어를 입력하다가, 정말 권한이 필요한 명령어에 한해서만 sudo를 붙여 사용하는 방식을 권장한다.
```


5\. 패키지 매니저(Package Manager)
-----------------------
```
1) 패키지 매니저(Package Manager)란?
갤럭시(Android)에서 앱을 받을 때는 Play Store를 활용하고, 아이폰(iOS)에서 앱을 받을 때는 App Store를 활용할 것이다. 

이런 것처럼 개발 환경에서는 프로그램(소프트웨어, 라이브러리 등)을 설치할 때 패키지 매니저를 사용한다.
패키지 매니저는 운영체제 또는 개발 환경에 따라 그에 맞는 패키지 매니저를 사용해야 한다.

- node 환경 → `npm`, `yarn`
- spring 환경 → `gradle`, `maven`
- python 환경 → `pip`
- **리눅스 환경 → `apt`, `yum`, `dnf` 등**
    - Ubuntu에서 `apt`를 사용한다.
    - CentOS에서 `yum` 또는 `dnf`를 사용한다.
    
    ** 운영체제 또는 개발 환경에 따라 다른 패키지 매니저를 사용한다. 
    
사실 패키지 매니저는 프로그램을 설치할 때 뿐만 아니라, 업데이트 및 제거를 할 때도 사용한다.
따라서 **패키지 매니저**는 **프로그램을 설치, 업데이트, 제거를 쉽게 관리해주는 도구**라고 할 수 있다.


2) 명령어
$ sudo apt install [패키지명]                   : 패키지 설치
$ sudo apt update                               : 패키지 목록 최신화(수동 동기화: 실시간 동기화를 제공해주지 않음)
$ sudo apt list --installed                     : 현재 컴퓨터에 설치된 모든 패키지 목록을 출력 
$ sudo apt list --installed | grep [패키지명]   : 설치된 특정 패키지 확인
$ sudo apt purge --auto-remove [패키지명]       : 설치된 패키지에 관련된 모든 파일을 깔끔하게 삭제
 - apt remove 명령어는 설정 파일이 남겨지고 삭제되기 때문에 apt purge 명령어를 주로 사용한다.
$ sudo yum remove [패키지명]                    : yum에서는 apt처럼 purge와 remove차이가 없어서 하나로 사용함.
$ sudo yum list java*jdk-devel                  : 설치 가능한 JDK 목록 확인
 - *을 통해 LIKE 검색이 가능하다.

sudo를 안쓸때 오류나는 경로의 파일 권한을 확인해보면 root 이외의 사용자에게는 아무런 권한도 없는 경우가 많다.
```


6\. 표준 출력(stdout) / 표준 에러 출력(stderr)
-----------------------
1) 표준 출력(stdout)이란? '>', '>>'
```
**표준 출력(stdout)**이란, **명령어의 실행 결과를 ‘출력할 곳’으로 이동시켜주는 통로**이다. 
    - 표준 출력에 기본값으로 설정되어 있는 **출력할 곳**은 **‘터미널 화면’**이다.
    - 표준 출력의 **출력할 곳**을 **‘터미널 화면’**이 아닌 **다른 곳(ex. 파일)**으로도 바꿀 수 있다.(리다이렉션)
    - 이와 같이 표준 출력을 어디로 연결할 지 변경하는 것을 보고 리다이렉션(Redirection)이라고 한다.

- 사용 예시:
    - $ ls > list.txt # 터미널 화면에 아무것도 출력이 안 됨(파일에 저장됨 - 리다이렉션)
    - $ pwd > directory.txt # 터미널 화면에 아무것도 출력이 안 됨(파일에 저장됨 - 리다이렉션)

- 주의사항
    - 같은 명령어 여러번 사용하면 파일이 덮어쳐짐.
    - 이어서 쓰기 위해선 '>>' 명령어를 사용해야함.
```

2) 표준 에러 출력(stderr)이란? '2>', '2>>'
```
리눅스에서 명령어의 실행 결과가 아닌 에러 메시지를 출력할 때는 별도의 메서드를 호출해서 출력한다.
즉, 정상적인 실행 결과값을 출력하는 함수와 에러 메시지를 출력하는 함수가 구별되어 있다.
이 때, 에러 메시지를 출력하는 함수의 역할은 표준 에러 출력이라는 곳으로 에러 메시지를 전달하는 역할을 한다.
그러면 에러 메시지를 전달 받은 표준 에러 출력은, 기본적으로 터미널 화면에 에러 메시지가 출력되도록 만든다.
    - 표준 출력과 표준 에러 출력은 독립적인 통로로 구성되어 있기 때문에,
      에러 메시지가 발생했을 때는 표준 출력이 아닌 표준 에러 출력의 통로를 거쳐 터미널 화면으로 에러 메시지가 출력된 것이다. 
  
- 사용 예시:
    - $ ls abc 2> list.txt # 터미널 화면에 아무것도 출력이 안 됨(파일에 저장됨 - 리다이렉션)
    - $ pwd > directory.txt # 터미널 화면에 아무것도 출력이 안 됨(파일에 저장됨 - 리다이렉션)

- 주의사항
    - 같은 명령어 여러번 사용하면 파일이 덮어쳐짐.
    - 이어서 쓰기 위해선 '2>>' 명령어를 사용해야함.
```

3) 같은 파일로 출력하려면? '2>&1'
```
- 사용 예시:
    - $ ls > all.txt 2>&1 # 이렇게 작성하는 것이 올바른 방식이다.

7\. 프로세스(process) : 실행 중인 프로그램
-----------------------
```
ctrl + shift + esc  : 윈도우에서 작업 관리자 창(실행 중인 프로그램들 조회)
$ ps aux            : 리눅스에서 실행 중인 모든 프로세스 조회
 - `USER` : 프로세스를 실행한 사용자
 - `PID` : 프로세스를 식별하기 위한 ID (Process ID)

 - `%MEM` : 메모리 사용률
 - `COMMAND` : 프로세스를 실행할 때 사용한 명령어를 보여줌 → 어떤 프로세스인지 쉽게 파악할 수 있음
```


8\. 포그라운드(foreground), 백그라운드(background)란?
-----------------------
```
터미널 창을 끄더라도 프로그램이 계속 실행되도록 만들기 (nohup, &)

**포그라운드(foreground)**는 **내가 실행시킨 프로그램의 내용이 화면에서 실행되고 출력되는 상태**를 뜻한다.
 그러다보니 포그라운드 상태에서는 다른 프로그램을 조작할 수가 없다. 

**백그라운드(background)**는 **내가 실행시킨 프로그램이 컴퓨터 내부적으로 실행되는 상태**를 의미한다.
 그래서 프로그램이 어떻게 실행되고 있는 지에 대한 정보가 화면에 자동으로 출력되지는 않는다.
 이런 특성 때문에 다른 명령어를 추가로 입력할 수도 있고, 새로운 프로그램을 조작할 수도 있다.
 
서버를 실행시킬 때 24시간 내내 터미널 창을 켜놓을 순 없다.
 따라서 서버를 실행시킨 뒤에 터미널 창을 끄더라도 프로세스가 계속 실행되어야 한다.
 그럴 때 아래 명령어를 활용해서 백그라운드에 프로세스를 실행시키면 된다. 
 - $ nohup [프로그램을 실행하는 명령어] &
```

- 정의: `rm`은 **대상 파일**, **옵션(-r, -f)**, **영구삭제 동작**을 포함하여 파일을 삭제하는 명령어.

    - `$ ls -lh`: 사람이 읽기 쉬운 형식으로 파일 크기 표시.
    - `$ ls -R`: 하위 디렉터리까지 모든 내용 출력.

11) less
```
#### less — 파일 내용을 한 화면씩 출력하며 탐색할 수 있는 명령어(파일명·탐색·옵션이 구성요소)
- 정의: `less`는 **파일명**, **탐색(앞/뒤로 이동)**, **옵션**을 사용하여 파일 내용을 한 화면씩 출력하며 탐색할 수 있는 명령어.
    - `cat` 명령어와 달리, 대용량 파일을 효율적으로 탐색 가능.

- 주요 탐색 키:
    - `Space`               : 다음 화면으로 이동.
    - `b`                   : 이전 화면으로 이동.
    - `Enter`               : 한 줄씩 아래로 이동.
    - `k`                   : 한 줄 위로 이동.
    - `q`                   : 종료.
    - `g`                   : 현재 열려있는 파일의 가장 첫번째 줄로 즉시 이동합니다.

                              `ctrl + c` : 모니터링 멈춤

- 주요 옵션:
    - `-N`          : 각 줄의 번호를 표시.
    - `-S`          : 긴 줄을 잘라내지 않고 가로 스크롤 가능.
    - `+/[검색어]`     : 파일 열 때 특정 문자열 검색.

    - '+G'          : 파일을 열자마자 마지막 부분부터 보여줍니다.

- 사용 예시:
    - `$ less file.txt`: `file.txt`의 내용을 한 화면씩 출력.
    - `$ less -N file.txt`: 줄 번호를 표시하며 파일 내용 출력.
    - `$ less +/pattern file.txt`: `file.txt`에서 `pattern`을 검색하며 열기.
    - `$ less -S file.txt`: 긴 줄을 잘라내지 않고 가로 스크롤 가능.

#### TMOUT — 셸 세션의 자동 로그아웃 시간을 설정하는 환경 변수

- 주의사항:
    - `TMOUT`은 현재 셸 세션에만 적용되며, 영구적으로 적용하려면 설정 파일(`~/.bashrc` 또는 `~/.bash_profile`)에 추가해야 합니다.
    - 예: `echo "export TMOUT=300" >> ~/.bashrc`

- 사용 예시:
    - `$ export TMOUT=600`: 10분 동안 입력이 없으면 자동 로그아웃.
    - `$ export TMOUT=0`: 자동 로그아웃 기능 비활성화.

## 3. 화면 상단(System Summary)

- **uptime**: 시스템 가동 시간과 로그인한 사용자 수를 나타내는 정보이다.
- **load average**: 1·5·15분 평균 CPU 부하로, 실행 대기 중인 프로세스 수를 의미한다.
- **Tasks**: 전체 프로세스 수와 실행·대기·중지·좀비 상태의 구성 현황이다.
- **%Cpu(s)**: user·system·idle 등 CPU 사용 비율을 구성요소별로 나타낸다.
 - ex) 99.7 id      : 여유로운 CPU 비중이 99.7%
- **MiB Mem**: 전체·사용·여유·버퍼/캐시 메모리로 구성된 물리 메모리 상태이다.
 - ex) 538.4 free   : 538.4MB만큼 사용할 수 있는 여분이 메모리가 있음 
- **MiB Swap**: 스왑 메모리의 전체 용량과 사용량을 나타내는 가상 메모리 정보이다.

## 4. 프로세스 목록(Process List)

- **PID**: 프로세스를 식별하는 고유한 프로세스 ID이다.
- **USER**: 해당 프로세스를 실행한 사용자 계정이다.
- **PR**: 커널이 관리하는 프로세스 우선순위 값이다.
- **NI**: nice 값으로, 우선순위 조정을 위한 사용자 지정 값이다.
- **VIRT**: 프로세스가 사용하는 전체 가상 메모리 크기이다.
- **RES**: 실제 RAM에서 사용 중인 물리 메모리 크기이다.
- **SHR**: 다른 프로세스와 공유 중인 메모리 크기이다.
- **S**: 프로세스 상태(R 실행, S 대기 등)를 나타낸다.
- **%CPU**: 해당 프로세스의 CPU 사용 비율이다.
- **%MEM**: 전체 메모리 대비 해당 프로세스의 사용 비율이다.
- **TIME+**: 프로세스가 CPU를 사용한 누적 시간이다.
- **COMMAND**: 실행 중인 명령어나 프로그램 이름이다.

## 5. 실행 중 키 명령어

- **q**: top 명령어를 종료한다.
- **P**: CPU 사용률 기준으로 프로세스를 정렬한다.
- **M**: 메모리 사용량 기준으로 프로세스를 정렬한다.
- **T**: 실행 시간 기준으로 프로세스를 정렬한다.
- **k**: 특정 PID를 입력해 프로세스를 종료한다.
- **1**: CPU 코어별 사용률을 개별로 표시한다.
- **h**: 도움말 화면을 출력한다.

## 6. 초보자 핵심 체크 포인트
