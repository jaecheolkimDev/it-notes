MCI (Multi-Channel Integration, 다중 채널 연계)
======================

1\. 정의
--------------
```
금융권이나 대규모 기업 시스템에서 내부 시스템과 다양한 대고객 접점(채널)을 연결해 주는 미들웨어 솔루션입니다.
```

1\. 핵심 역할
--------------
```
1) 프로토콜 및 전문 변환: 다양한 채널(WEB, App, ATM, 콜센터 등)에서 들어오는 서로 다른 통신 방식(HTTP, TCP/IP, SOAP 등)과 
                    데이터 포맷(JSON, XML, 전문/Fixed-length)을 내부 계정계/단말 시스템이 이해할 수 있는 규격으로 자동 변환합니다.
2) 트래픽 제어 및 부하 분산: 특정 채널에서 순간적인 요청이 급증할 때 제어(Throttling) 기능을 제공하여 코어 시스템(계정계)이 다운되지 
                        않도록 보호합니다.
3) 라우팅 및 보안 관리: 요청 목적지에 따라 올바른 내부 서비스로 연결하고, 데이터 암/복호화 및 사용자 인증 처리를 중간에서 수행합니다.
```

1\. 도입 효과 및 유의점
--------------
```
1) 개발 효율성 향상: 채널별로 코어 시스템 통신 로직을 일일이 구현할 필요 없이 MCI 규격만 맞추면 되므로 개발 생산성이 올라갑니다.
2) 유연한 채널 확장: 신규 채널(예: 모바일 앱 연동)을 추가할 때 코어 시스템 수정 없이 MCI 설정만으로 빠르게 오픈할 수 있습니다.
3) 단일 실패점(SPOF) 주의: 모든 채널의 관문 역할을 하므로 MCI 장애 시 전체 채널 서비스가 중단될 수 있어 고가용성(HA) 및 이중화 
                        구성이 필수적입니다.
```

1\. MCI / EAI / FEP 비교
--------------
기업 연계 시스템은 목적과 범위에 따라 보통 세 가지로 구분됩니다.
```
구분                                          주요 대상                                       주요 역할
MCI (Multi-Channel Integration)             "내부 서비스 ↔ 고객 대면 채널 (WEB, App, ATM 등)"   고객 접점 채널 연계 및 메시지 변환
EAI (Enterprise Application Integration)    "내부 시스템 ↔ 내부 시스템 (ERP, CRM, 계정계 등)"     내부 비즈니스 시스템 간 비동기/동기 데이터 연동
FEP (Front End Processor)                   "내부 시스템 ↔ 외부 기관 (VAN사, 카드사, 은행 등)"      대외 기관과의 전문 통신 및 암호화 연계
```
