MVC(Model-View-Controller)
=================

4\. 정의
-----------
```
소프트웨어 공학에서 애플리케이션의 구성 요소를 세 가지 역할로 나누어 개발하는 대표적인 소프트웨어 설계 패턴(Design Pattern)입니다.
```

4\. 핵심 목적
-----------
```
화면 구성(UI)과 백엔드 로직(비즈니스 로직)을 분리하여 유지보수가 용이하고 코드의 재사용성을 높이는 것이 핵심 목적입니다.
```

4\. 3가지 핵심 요소
-----------
```
구성 요소               역할                                      핵심 특징
Model (모델)          애플리케이션의 데이터와 비즈니스 로직을 담당    "DB 조회, 데이터 가공, 규칙 처리. View나 Controller의 정보를 몰라야 함"
View (뷰)            사용자에게 보여지는 **화면(UI)**을 담당       "HTML, CSS, React 등. Model의 데이터를 받아 화면을 생성하며 자체 로직을 포함하지 않음"
Controller (컨트롤러)   Model과 View를 연결하는 중재자 역할        사용자 요청 수신 → Model 데이터 업데이트 → 적절한 View 전달
```

4\. 동작 흐름
-----------
```
1) 사용자 요청: 사용자가 버튼 클릭이나 URL 입력 등을 통해 시스템에 요청(Request)을 보냅니다.
2) Controller 처리: 컨트롤러가 요청을 받아 어떤 작업을 수행할지 판단한 뒤 Model을 호출합니다.
3) Model 비즈니스 로직 실행: 모델이 DB 연산이나 데이터 처리를 완료하고 최신 데이터 상태를 만듭니다.
4) View에 전달: 컨트롤러가 업데이트된 모델 데이터를 View에 전달합니다.
5) 화면 출력: 뷰가 전달받은 데이터를 바탕으로 화면을 렌더링하여 사용자에게 응답(Response)합니다.
```

4\. 장점과 한계
-----------
```
1) 장점
 - 관심사의 분리(Separation of Concerns): 각 역할이 명확히 나뉘어 개발자가 자신의 영역(프론트엔드/백엔드)에 집중할 수 있습니다.
 - 높은 재사용성: 동일한 모델 데이터를 웹 화면(View A), 모바일 앱 화면(View B) 등 다양한 형태로 재활용할 수 있습니다.
 - 유지보수성 향상: 화면 디자인이 바뀌어도 모델 로직을 수정할 필요가 없습니다.
2) 한계 (Massive Controller)
 - 애플리케이션 규모가 커질수록 컨트롤러가 복잡해지고 비대해지는 Massive Controller 문제가 발생할 수 있습니다.
 - 이를 해결하기 위해 최근 현대적인 프론트엔드/백엔드 개발에서는 MVVM, MVP, 혹은 Clean Architecture 같은 변형 패턴을 함께 
   활용합니다.
```
