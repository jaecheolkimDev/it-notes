Circuit Breaker(서킷 브레이커) 패턴
=================

1\. 개념
----------------------------------------
```
MSA에서 특정 서비스에 문제가 발생했을 때 그 여파가 시스템 전체로 퍼지는 것을 방지하는 장벽 역할을 하는 설계 패턴입니다.
```

2\. 주요 작동 원리 (3가지 상태)
----------------------------------------
```
Closed (닫힘):
    정상적인 상태입니다. 모든 요청이 목적지 서비스로 전달됩니다.
    실패 횟수가 미리 설정한 임계치(Threshold)를 넘지 않으면 계속 이 상태를 유지합니다.

Open (열림):
    에러 발생률이 임계치를 넘으면 서킷 브레이커가 '열립니다'.
    이때부터는 요청을 목적지 서비스로 보내지 않고, 즉시 에러를 반환하거나 대체 로직(Fallback)을 실행합니다. 
    이를 통해 결함이 있는 서비스에 추가적인 부하를 주지 않고 대기 시간을 줄입니다.

Half-Open (반열림):
    서킷이 열린 후 일정 시간이 지나면 '반열림' 상태가 되어, 시스템이 회복되었는지 확인하기 위해 소량의 테스트 요청을 보냅니다.
    테스트가 성공하면 다시 Closed로 돌아가고, 실패하면 다시 Open 상태가 됩니다.
```

3\. 왜 사용하는가? (핵심 이점)
----------------------------------------
```
장애 전파 방지 (Cascading Failure)    : 하나의 서비스가 느려지거나 응답이 없으면, 그 서비스를 호출하는 다른 서비스들의 스레드도 함께 점유되어 
                                      시스템 전체가 마비될 수 있습니다. 서킷 브레이커는 이를 중간에 끊어줍니다.
빠른 실패 (Fail Fast)                : 응답을 받지 못할 서비스에 계속 요청을 보내며 기다리는 대신, 빠르게 실패를 선언하고 사용자에게 
                                      대체 화면을 보여줄 수 있습니다.
자동 복구 시도                        : 사람이 직접 개입하지 않아도 시스템 스스로 서비스의 상태를 체크하고 정상화되면 다시 연결을 재개합니다.
```
