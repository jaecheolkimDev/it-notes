사이드카 패턴(Sidecar Pattern) 패턴
=================

1\. 개념
-----------
```
오토바이 옆에 붙어 있는 사이드카처럼, 
기능을 확장하거나 공통 기능을 제공하는 별도의 컨테이너(또는 프로세스)를 메인 애플리케이션 옆에 붙이는 패턴입니다.
```

2\. 특징
-----------
```
런타임 분리: 메인 애플리케이션과 사이드카는 서로 다른 프로세스로 동작합니다. (예: Java 1.8 기반 WAS와 Python 기반 AI 모듈이 각각 독립된 프로세스로 실행됨)
언어 독립성: 메인 앱이 Java여도 사이드카는 Go, Python 등 다른 언어로 작성될 수 있습니다.
배포 단위: 컨테이너 환경(Kubernetes 등)에서는 하나의 Pod 안에 두 개의 컨테이너가 함께 배포되는 구조를 가집니다.
```

3\. 주요 기능
-----------
```
통신 및 보안: 서비스 메시(Service Mesh) 환경에서 mTLS 암호화, 프록시 역할.
로그 및 모니터링: 메인 앱의 로그를 수집하여 중앙 서버로 전송.
설정 관리: 환경 설정 파일을 실시간으로 감시하고 갱신.
AI 및 데이터 처리: JDK 1.8 환경(메인) 옆에 최신 AI 엔진(사이드카)을 붙여 기능을 확장하는 경우.
```

4\. 디자인 패턴(데코레이터 패턴)과의 관계
-----------
```
재미있게도 사이드카 패턴은 객체지향 디자인 패턴 중 데코레이터(Decorator) 패턴의 개념을 시스템 아키텍처로 확장한 것과 같습니다. 
기존 기능을 수정하지 않고 겉에 새로운 기능을 덧씌운다는 철학이 같기 때문입니다.
```
