템플릿 메소드 패턴(상속을 이용하는 방법)
=================
```
템플릿 메소드 패턴은 알고리즘의 구조를 메소드에 정의하고, 알고리즘의 일부 단계들을 서브클래스에서 구현하도록 하는 행동 패턴입니다.

알고리즘의 전체적인 흐름은 바꾸지 않으면서, 특정 단계의 구체적인 내용을 서브클래스에서 재정의할 수 있게 합니다.

1. 핵심 개념
   추상 클래스 (Abstract Class): 알고리즘의 뼈대를 이루는 템플릿 메소드를 구현합니다.

템플릿 메소드 (Template Method): 알고리즘의 실행 순서를 정의합니다. 내부에서 추상 메소드나 구현된 메소드를 호출합니다.

구현 클래스 (Concrete Class): 부모 클래스에서 정의한 추상 메소드를 구체적으로 구현합니다.

2. 장점과 단점
   장점
   코드 중복 제거: 알고리즘의 공통 부분은 부모 클래스에서 한 번만 구현하면 됩니다.

확장성: 알고리즘의 구조는 유지하면서 특정 부분만 수정하기 용이합니다.

제어의 역전 (IoC): 부모 클래스에서 전체 흐름을 제어하므로 자식 클래스는 복잡한 로직을 몰라도 됩니다.

단점
유연성 제한: 알고리즘의 전체 골격이 고정되어 있어 변경이 어려울 수 있습니다.

클래스 폭발: 세부 구현이 조금만 달라도 새로운 서브클래스를 계속 만들어야 할 수 있습니다.

3. 구현 예제 (Java)
   커피와 차를 만드는 과정(물 끓이기 -> 우려내기 -> 컵에 붓기 -> 첨가물 넣기)을 예로 들어보겠습니다.

4. 훅(Hook) 메소드
   템플릿 메소드 패턴에서는 Hook이라는 개념을 자주 사용합니다. 부모 클래스에서 기본적으로 아무 내용도 없거나 기본 구현을 제공하는 메소드로, 서브클래스에서 필요에 따라 선택적으로 오버라이딩할 수 있게 합니다.

5. 요약
   템플릿 메소드 패턴은 "변하지 않는 부분은 부모 클래스에, 변하는 부분은 자식 클래스에" 두는 패턴입니다. 상속을 통해 코드 재사용성을 높이고 싶을 때 매우 유용합니다.
```
