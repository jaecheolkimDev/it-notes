템플릿 콜백 패턴(Template Callback Pattern)
=====================

1\.
-----------------------------
전략 패턴(Strategy Pattern)의 변형
```
스프링(Spring) 프레임워크에서 자주 사용되는 아주 유용한 디자인 패턴입니다.
"변하지 않는 큰 틀(템플릿)을 만들어 두고, 변하는 부분만 핵심 로직(콜백)으로 만들어서 넘겨주는 방식"입니다.
```

2\. 주요 개념 이해하기
-----------------------------
```
1) 템플릿 (Template)
    - 전체적인 작업 흐름을 정의한 고정된 틀입니다.
    - 반복되는 작업(예: DB 연결, 자원 해제, 예외 처리 등)을 미리 다 작성해 둡니다.
2) 콜백 (Callback)
    - 템플릿 안에서 실행될 실제 핵심 비즈니스 로직입니다.
    - 보통 자바에서는 익명 내부 클래스나 람다식(Lambda)을 활용해 메서드의 파라미터(인자)로 전달됩니다.

ex) 공장에 '붕어빵 굽기 기계(템플릿)'가 있습니다. 기계는 온도를 맞추고 뒤집는 고정된 일(컨텍스트)을 합니다. 이때 안에 넣을 '팥소'나 '슈크림'(콜백)만 
    바꿈으로써 단팥 붕어빵도 만들고 슈크림 붕어빵도 만드는 것과 같습니다.
```

3\. 왜 사용할까요?(장점)
-----------------------------
```
1) 중복 코드 제거: 매번 작성해야 하는 DB 연결, 트랜잭션 시작/종료, 로깅 같은 귀찮은 코드(Boilerplate code)를 템플릿에 한 번만 써두면 됩니다.
2) 유지보수성 향상: 공통 흐름이 바뀌면 템플릿 하나만 수정하면 되므로 관리가 매우 편해집니다.
3) 유연한 확장: 전체 흐름을 건드리지 않고, 필요한 비즈니스 로직만 그때그때 람다식 등으로 갈아 끼울 수 있습니다.
```

4\. 스프링에서의 대표적인 예시
-----------------------------
스프링 프레임워크를 쓰다 보면 이름 뒤에 Template이 붙는 클래스들을 자주 보게 되는데, 이것들이 전부 이 패턴을 사용한 것입니다.
```
클래스 이름                  역할
JdbcTemplate            JDBC 활용 시 반복되는 DB 연결 및 자원 해제(close) 자동화
RestTemplate            HTTP REST API 호출 시 반복되는 연결 및 예외 처리 자동화
TransactionTemplate     트랜잭션 시작, 커밋/롤백 등의 반복 흐름 자동화
```

5\. 전략 패턴과의 차이점
-----------------------------
```
1) 전략 패턴: 객체를 미리 생성해서 주입(DI)받아 두고 두고 쓰는 방식이 많습니다.
2) 템플릿 콜백 패턴: 실행할 때마다 메서드의 파라미터로 로직(콜백)을 동적으로 전달합니다. 자바의 람다식과 궁합이 아주 잘 맞습니다.
```
