레플리케이션(Replication)
================

1\. 개념 : 서버를 복제해 '가용성'을 높이는 것
-----------------------------
가지고 있는 데이터를 복제, 복사한다는 의미입니다.
```
현대의 분산시스템에서 데이터는 여러 노드에 분산되어 있고, 네트워크는 본질적으로 신뢰하기가 어렵기 때문에
데이터의 손실을 방지하기 위해 여러곳에 데이터를 저장하는것은 필수가 되었습니다.

데이터가 거의 변하지 않는다면 복제는 간단합니다. 하지만 대부분의 현대 시스템은 그렇지 않습니다.

쓰기 요청은 어떻게 적시에 일관성을 유지하면 전파될 수 있을까요?
이를 위한 몇 가지 복제방식이 있으며, 각각에는 트레이드 오프가 존재합니다.
```

2\. 목적
-----------------------------
```
1) 시스템 장애 시 데이터 손실을 방지하기 위해.
2) 증가한 트래픽을 처리하기 위해.
3) 지역별로 지연 시간을 개선하기 위해.
```

3\. 복제 방식
-----------------------------
```
1) 리더-팔로워 구조 (프라이머리-레플리카 구조)
    1-1) 동기 방식 (데이터 일관성이 강하게 보장되지만, 지연/레이턴시가 발생할 수 있습니다.)
    쿼리는 하나의 지정된 리더의 쓰기를 수행하고, 리더는 변경된 데이터를 팔로워들에게 복사를 합니다.
    리더는 팔로워들이 데이터가 확실히 써졌는지 요청을 보내면, 팔로워는 ACK을 리더에게 보냄으로써 쓰기 작업이 완료가 됬다고 판단할 수 있습니다.
    
    1-2) 비동기 방식
    팔로워의 ACK을 기다리지 않고 다음 작업을 바로 수행하기 때문에 쓰기 작업이 상대적으로 더 빠릅니다.
    하지만, 리더와 팔로우 사이의 시간 차이로 인한 데이터 일관성에는 약간의 리스크가 존재합니다.
    
    1-3) 리더가 죽으면 failover
    하나의 팔로워가 리더로 승격되어 역할을 이어받습니다.

2) 리더-리더 구조 (여러개의 리더가 존재하는 구조)
    각 리더들은 독립적으로 쓰기작업을 수행할 수 있고, 자신이 받은 변경사항을 다른 리더들에게 복제할 수 있습니다.
    이런 구조는 다중 데이터 센터에서 운영을 합니다.
    각 사용자는 가까운 리더에 쓰기 때문에 지연 시간이 상대적으로 낮게 느껴집니다.
    한 데이터 센터의 리더가 다운이 되더라도 다른 리더가 계속해서 서비스를 할 수 있습니다.
```

4\. 일관성을 맞추는 방법
-----------------------------
```
1) 최종 작성자 우선 (Last Writer Wins)     : 가장 마지막에 쓰여진 데이터를 유지하는 방식입니다.
2) 합의 알고리즘 (Consensus Algorithm)    : 여러 노드가 같은 데이터에 대해서 합의를 이루는 방법입니다. (Raft알고리즘)
                                          각 노드가 변경사항에 대해 합의를 거쳐야만 데이터를 적용하기 때문에 일관성을 유지할 수 있습니다.
3) 쿼럼 기반 방식 (Quorum-Based Approach) : 노드들 중 일정수의 노드가 데이터를 기록하고 읽을 때만 그 데이터가 유효하다고 판단하는 방식입니다.
4) 궁극적 일관성 (Eventual Consistency)   : 일시적으로 데이터가 불일치할 수는 있지만, 
                                          시간이 지나면서 모든 노드가 동일한 데이터를 가질 것이라는 가정입니다.
```
