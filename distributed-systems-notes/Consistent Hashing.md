일관성 있는 해싱(Consistent Hashing)
=================

1\. 정의
-----------
```
서버의 수가 유동적으로 변하는 분산 환경에서 데이터를 여러 서버(노드)에 균등하게 배분하고, 서버 추가/삭제 시 데이터 이동을 최소화하기 
위해 고안된 알고리즘입니다.
```

2\. 기존 해싱 방식의 한계 (Modulo Hashing)
-----------
```
 - 일반적인 분산 시스템에서는 키(Key)를 서버에 배정할 때 나눗셈 연산(Modulo)을 사용합니다.
 - Server Index = hash(key) (mod N) (N = 서버 개수)
 - 문제점: 서버 개수 $N$이 바뀌면(노드 추가/장애 발생) 대부분의 키에 대한 $\pmod$ 결과가 변하게 됩니다.
 - 결과: 서버 1대가 추가되거나 죽었을 때, 시스템 전체 데이터의 대부분($\frac{N}{N+1}$)이 다른 서버로 이동해야 하는 재배치 
        폭풍(Rebalancing Storm)과 Massive Cache Miss가 발생합니다.
```

3\. Consistent Hashing의 핵심 동작 원리
-----------
        [Server A (12시)]
          /         \
    (Key 1)           (Key 2)
        /             \
[Server C (8시)] --- [Server B (4시)]
- Key 1: 시계 방향 탐색 -> Server A에 저장
- Key 2: 시계 방향 탐색 -> Server B에 저장
```
Consistent Hashing은 해시 공간을 linear한 일직선이 아니라 360도 링(Ring) 형태로 연결해 문제를 해결합니다.
1) 해시 링(Hash Ring) 구성
 - 해시 함수(예: SHA-1 등)의 출력 범위(예: $0 \sim 2^{32}-1$)를 원형의 링으로 표현합니다.
2) 서버(노드) 및 키(Key) 배치
 - 서버 배치: 서버의 IP나 이름을 해시화하여 링 위의 특정 위치에 배치합니다.
 - 키 배치: 저장할 데이터의 Key 또한 동일한 해시 함수로 해시화하여 링 위의 위치를 잡습니다.
3) 데이터 조회 및 저장 (Clockwise Routing)
 - 특정 Key가 저장될 서버를 찾을 때, 해당 Key의 위치에서 시계 방향(Clockwise)으로 링을 탐색하며 가장 먼저 만나는 서버에 데이터를 
   저장합니다.       
```

4\. 서버 변경 시 동작 (최소한의 데이터 이동)
-----------
```
1) 서버 추가 (Server D 추가)
 - Server A와 Server B 사이(2시 방향)에 Server D가 새로 들어오면:
 - Key 2는 이제 시계 방향으로 탐색할 때 Server B 대신 Server D를 먼저 만납니다.
 - 이동 대상: Server A와 Server D 사이 영역에 위치하던 키들만 Server D로 이동합니다. 다른 서버(B, C)에 속한 키들은 전혀 영향을 
   받지 않습니다.
2) 서버 제거 (Server B 장애 발생)
 - Server B가 다운되면:
     - 기존에 Server B로 향하던 Key들은 시계 방향으로 더 진행하여 다음 노드인 Server C로 자동 재배치됩니다.
     - 이동 대상: Server B가 담당하던 데이터만 Server C로 넘어갈 뿐, 나머지 서버들의 데이터는 그대로 유지됩니다.
```

5\. 핫스팟 문제와 가상 노드 (Virtual Nodes)
-----------
```
1) 문제점: 불균등한 데이터 분산 (Hotspot Problem)
 - 노드 수가 적거나 해시 함수 분포상 특정 서버 간 거리가 멀어지면, 특정 서버가 링의 넓은 영역을 담당하게 되어 부하 쏠림 현상이 발생합니다.
 - 특정 서버가 장애로 이탈할 때, 그 서버의 모든 부하가 바로 다음 노드로만 몰리는 쇄도(Cascading Failure) 현상이 생길 수 있습니다.
2) 해결책: 가상 노드 (Virtual Nodes / VNodes)
실제 물리 서버 1당 여러 개의 가상 노드(예: 100~200개)를 해시 링 위에 무작위로 배치합니다. (예: ServerA_1, ServerA_2, ServerA_3...)
 - 효과:
     - 부하 균등화: 링 위에서 물리 서버의 지분이 촘촘하게 쪼개지므로 데이터가 한쪽으로 쏠리지 않고 고르게 분산됩니다.
     - 장애 분산: 서버 A가 죽더라도 해당 서버의 데이터가 링 곳곳에 분포된 가상 노드들에 의해 여러 다른 물리 서버들로 균등하게 분산 
       이관됩니다.
```

6\. 핵심 요약
-----------
```
1) 목적: 노드의 가감(Scale-out/in)이 빈번한 분산 환경에서 키 재배치 비용 최소화.
2) 효과: 전체 $K$개의 키와 $N$개의 서버가 있을 때, 서버 변동 시 평균적으로 $K/N$개(전체의 $1/N$)의 키만 이동.
3) 대표 적용 사례: DynamoDB, Apache Cassandra, Couchbase, Memcached/Redis 클라이언트 링, CDN 라우팅.
```
