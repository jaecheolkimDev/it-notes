단축 URL
================

2\. 정의 (생성 방식)
-----------------------------
```
긴 웹주소(URL)를 식별 가능한 짧은 문자열로 변환하고, 사용자가 해당 짧은 URL로 접속했을 때 원래 주소로 연결(Redirection)해 주는 
기술입니다.
```

8\. 사용 배경
-----------------------------
글자 수 제한, 가독성, 데이터 추적, 보안 및 공유 편의성
```
1) 글자 수 제한 극복 (초기 핵심 배경)
 - 트위터(X)의 140자 제한: 단축 URL 서비스(bit.ly 등)가 폭발적으로 성장한 결정적 계기입니다. 한글이나 영문으로 길게 작성된 파라미터 
                        포함 URL 하나가 100자를 넘어가면 정작 작성할 글자 수가 남지 않아 주소를 줄여야만 했습니다.
 - SMS/MMS 문자 메시지: SMS 단문 메시지는 80~90바이트 제한이 있어, 길다란 URL을 넣으면 메시지가 2~3건으로 분할 전송되어 발송 비용이 
                      증가합니다.
2) 가독성 및 전달력 향상
 - 지저분한 한글/특수문자 인코딩 방지: URL에 한글이나 특수문자가 포함되면 (https://site.com/%EC%95%88%EB%83%90)...처럼 
                                 인코딩되어 지나치게 길어지고 복사/붙여넣기 시 깨지는 현상이 빈번합니다.
 - 오프라인/구두 전달: 인쇄물(포스터, 명함, 현수막)이나 방송/연설 등 직접 타이핑해야 하거나 말로 전달해야 하는 상황에서 짧은 주소가 
                    훨씬 유리합니다.
3) 데이터 추적 및 마케팅 분석 (기업의 핵심 목적)
 - 클릭 통계 수집: 원본 URL로 직접 연결하면 수집하기 어려운 클릭 횟수, 유입 경로, 접속 시간대, 사용자 기기/지역 데이터를 단축 URL 
                 서버가 중간에서 자동으로 수집합니다.
 - A/B 테스트 및 캠페인 관리: 동일한 상품 페이지라도 마케팅 채널(페이스북, 인스타그램, 이메일)마다 서로 다른 단축 URL을 발급하여 
                           어느 채널의 성과가 좋은지 측정합니다.
4) 동적 리다이렉트 (주소 변경 유연성)
이미 출력된 오프라인 홍보물이나 발송된 메시지의 링크 대상이 변경되었을 때, 원본 URL이 바뀌어도 단축 URL의 DB 매핑값만 수정하면 
사용자를 새로운 페이지로 안내할 수 있습니다.
```

9\. 주요 생성 방식
-----------------------------
```
1) 데이터베이스 Auto-Increment ID + Base62 변환 (가장 일반적인 방식)
 - 원리: DB에 긴 URL을 저장할 때 생성되는 고유 숫자 ID(예: 1000001)를 62진법(대소문자 $A-Z, a-z$, 숫자 $0-9$)으로 변환합니다.
 - 장점: ID가 유일하므로 충돌이 절대 발생하지 않으며, 계산 복잡도가 낮습니다.
 - 단점: ID 값이 순차적으로 증가하므로 다음 단축 URL을 쉽게 예측할 수 있어 보안(Scraping)에 취약할 수 있습니다. (Random Offset 등을 추가하여 보완)
2) 해시 함수(Hash Function) + 잘라내기(Truncation)
 - 원리: 긴 URL을 MD5나 SHA-256 같은 해시 알고리즘에 넣어 고정된 길이에 난해한 문자열을 만든 뒤, 앞 6~8자리를 잘라내어 사용합니다.
 - 장점: 입력값이 동일하면 항상 같은 해시 결과가 나오며, 예측이 불가능합니다.
 - 단점: 잘라내는 순간 해시 충돌(Collision) 위험이 발생하므로, DB 확인 후 충돌 시 사설 소금(Salt)을 붙여 재해싱하는 로직이 필수적입니다.
3) 난수 생성(Random String Generation)
 - 원리: Base62 문자 집합 내에서 랜덤하게 6~8자리 문자열을 생성하여 DB에 중복 여부를 확인한 뒤 매핑합니다.
 - 장점: 구현이 매우 직관적이고 예측이 불가능합니다.
 - 단점: 데이터가 쌓일수록 중복 발생 확률이 높아져 DB 조회 재시도 횟수가 늘어납니다.
```

2\. 동작 과정 (Redirection)
-----------------------------
1) 사용자가 단축 URL을 클릭합니다.
2) 서버는 단축 키(x7K9a)를 키로 사용하여 DB에서 매핑된 원본 URL을 찾습니다.
3) 서버가 브라우저에게 HTTP 301 (Permanent) 또는 HTTP 302 (Temporary) Redirect 응답과 함께 원본 URL을 전달합니다.
4) 브라우저가 원본 URL로 자동으로 이동합니다.
```
[사용자]  ──(1) 단축 URL 클릭 (예: short.link/x7K9a) ──> [단축 URL 서버]
                                                            │
                                                     (2) DB에서 x7K9a 조회
                                                            │
[사용자]  <──(3) 301/302 Redirect (원래 URL 전달) ──────────┘
   │
   └───(4) 원래 URL로 접속 (예: long-domain.com/article/123)
```
