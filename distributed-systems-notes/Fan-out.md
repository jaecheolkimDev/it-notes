Fan-out
================

8\. Fan-out-on-Write (Push 모델)
-----------------------------
```
1) 정의   : 포스팅이 생성되는 시점에 해당 사용자의 모든 팔로워 피드(캐시)에 게시글 ID를 즉시 밀어 넣는(Push) 구조이다.
2) 단점   : 핫스팟(Hotspot) 문제로 인한 시스템 부하 및 처리 지연입니다.
```

9\. 사례
-----------------------------
```
1) 팔로워가 많은 유명인(Celebrity) 처리 이슈
 - 팔로워가 수 천만 명에 달하는 사용자가 글을 하나 올리면, 단 한 번의 요청으로 수천만 건의 DB/캐시 쓰기 작업이 동시에 발생합니다.
 - 이로 인해 시스템 리소스가 순간적으로 고갈되거나 큐(Queue)에 병목이 생겨 피드 업데이트가 크게 지연될 수 있습니다.
2) 비활성 사용자(Inactive User)로 인한 자원 낭비
 - 서비스를 거의 방문하지 않는 팔로워의 피드까지 미리 생성하고 업데이트하기 때문에 불필요한 메모리 및 Storage 공간이 낭비됩니다.
```

2\. Push 모델 vs Pull 모델
-----------------------------
```
구분      Fan-out-on-Write (Push)             Fan-out-on-Read (Pull)
작동 시점   글 작성 시 팔로워 피드에 미리 쓰기    피드 조회 시점에 팔로우 대상 글을 읽어옴
주요 장점   피드 조회 속도가 매우 빠름             쓰기 부하가 적고 비활성 유저 자원 낭비 없음
주요 단점   대규모 팔로워 보유자 발생 시 쓰기 폭주  피드 조회(Read) 시 연산 비용 및 시간 증가
```

2\. 실무에서의 해결책 (하이브리드 접근법)
-----------------------------
실제 인스타그램이나 트위터(X) 같은 대규모 뉴스 피드 시스템에서는 두 방식을 혼합하여 사용합니다.
```
1) 일반 사용자: 핫스팟 우려가 없으므로 실시간 조회가 빠른 Push 모델 적용
2) 유명인(Celebrity): 팔로워 피드에 미리 밀어 넣지 않고, 팔로워가 앱을 켤 때 가져오도록 Pull 모델 적용
```
