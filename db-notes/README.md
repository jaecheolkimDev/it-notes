6\. Oracle의 성능 향상을 위한 캐싱 메커니즘
--------
```
오라클 DB에서 첫 실행 쿼리가 느리고 두 번째부터 빠른 이유는 데이터 및 실행 계획 캐싱 때문입니다. 
처음에는 디스크(HDD/SSD)에서 데이터를 불러오지만, 이후에는 메모리(Buffer Cache, Shared Pool)에 저장된 데이터를 사용하여 
I/O 병목이 사라져 속도가 빨라지는 현상입니다. 
Buffer Cache (데이터 블록 캐싱)    : 쿼리가 처음 실행될 때 필요한 데이터 블록이 디스크에서 메모리(Buffer Cache)로 로딩됩니다. 
                                  두 번째 실행 시, 디스크 I/O 없이 메모리에서 바로 데이터를 읽기 때문에 훨씬 빠릅니다.
Shared Pool (실행 계획 캐싱)  : Oracle은 쿼리의 SQL 문장 자체를 분석(Parsing)하고 최적의 실행 계획(Execution Plan)을 세우는 데 
                             시간이 걸립니다. 
                             한번 실행된 쿼리는 라이브러리 캐시(Library Cache)에 저장되어 이후 Parsing 과정을 생략합니다.
```

7\. SQL의 3단계 논리
--------
TRUE , FALSE , UNKNOWN
```
1) NOT IN의 이슈
    (10, 20, NULL)
    WHERE A != 10 AND A != 20 AND A != NULL
    (A != NULL) => UNKNOWN
    (TRUE AND TRUE AND UNKOWN) => UNKNOWN
    논리 연산에서 하나라도 'UNKNOWN'이면 전체 조회가 마비됩니다.
        => NULL은 IS NULL, IS NOT NULL로 조회해야 정상적으로 조회됩니다.
        => NOT IN에서 NULL이 포함되어 있으면 안됩니다.
```
