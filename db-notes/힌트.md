DB HINT 공부 노트
=============

1\. 조인(Join) 방식
-----------
각 방식은 데이터의 양, 인덱스 존재 여부, 메모리 상태에 따라 성능이 크게 달라집니다.
```
1) 중첩 루프 조인 (Nested Loop Join, NLJ)     : 가장 기본적인 조인 방식으로, 프로그래밍의 이중 for 문과 유사한 원리입니다.
    동작 방식: 선행 테이블(Outer Table)의 행을 하나씩 읽으며, 후행 테이블(Inner Table)에서 조건에 맞는 행을 찾아 결합합니다.
    특징:
        인덱스 의존성: 후행 테이블에 조인 컬럼 인덱스가 반드시 있어야 효율적입니다.
        소량 데이터: 처리할 데이터 양이 적을 때 유리합니다.
        응답 속도: 첫 번째 결과가 나오는 속도가 빨라 OLTP(온라인 트랜잭션 처리) 환경에 적합합니다.
2) 해시 조인 (Hash Join)        : 조인 조건 컬럼을 기준으로 해시 테이블을 생성하여 결합하는 방식입니다.
    동작 방식:
        작은 테이블(Build Input)을 읽어 메모리에 해시 테이블을 만듭니다.
        큰 테이블(Probe Input)을 읽으며 해시 함수를 통해 결합할 데이터를 찾습니다.
    특징:
        대용량 데이터: 인덱스가 없거나 처리해야 할 데이터가 많을 때 NLJ보다 훨씬 빠릅니다.
        메모리 사용: 해시 테이블이 메모리(Hash Area)보다 커지면 디스크를 사용하게 되어 성능이 떨어질 수 있습니다.
        동등 조인만 가능: = 조건에서만 사용할 수 있습니다.
3) 정렬 병합 조인 (Sort Merge Join)       : 양쪽 테이블을 조인 컬럼 기준으로 정렬한 뒤, 차례대로 스캔하며 병합하는 방식입니다.
    동작 방식:
        각 테이블을 조인 키로 정렬합니다.
        정렬된 두 리스트를 비교하며 조건에 맞는 데이터를 결합합니다.
    특징:
        인덱스가 없을 때: 인덱스가 없지만 대량의 데이터를 조인해야 할 때 해시 조인의 대안으로 사용됩니다.
        비동등 조인 가능: 해시 조인과 달리 >, < 같은 범위 조건 조인에서도 사용할 수 있습니다.
        정렬 부담: 이미 정렬되어 있는 데이터라면 매우 빠르지만, 그렇지 않다면 정렬 과정에서 부하가 큽니다.
```

NO_MERGE            : 뷰나 인라인 뷰를 해체하지 말아라.(=조인하지말아라) (인라인 뷰 = FROM절의 서브쿼리)
LEADING(S SAV T)    : 조인의 시작 순서 결정(스노우볼 전략)
USE_HASH(SAV T)     : 조인방식을 HASH조인으로 강제(대용량 조인에서 사용)
PARALLEL(SAV 4)     : 4개의 쓰레드 사용
SWAP_JOIN_INPUTS(S) : 해시 조인(Hash Join)을 수행할 때, 어느 테이블을 Build Input(해시 테이블을 만드는 쪽)으로 사용할지 명시적으로 지정하여 
                      실행 계획을 제어하는 힌트입니다.
