XA
=============
여러 개의 데이터베이스나 메시지 큐를 함께 사용할 때 XA와 Non-XA, 그리고 이를 돕는 JTA, Atomikos 같은 용어들이 등장

1\. XA vs Non-XA: "협력하느냐, 혼자 하느냐"
--------
```
Non-XA (Local Transaction): 단일 리소스(예: 하나의 DB)에 대한 트랜잭션입니다. 
                            우리가 흔히 쓰는 일반적인 방식이죠. "이 DB에 데이터 넣고 커밋해!"로 끝납니다.

XA (Extended Architecture): 분산 트랜잭션을 위한 표준 사양입니다. 
                            서로 다른 두 개 이상의 리소스(예: MySQL DB + Oracle DB, 혹은 DB + Kafka)를 하나의 트랜잭션으로 묶을 때 사용합니다.
    이를 위해 2단계 커밋 (2PC, Two-Phase Commit) 프로토콜을 사용합니다. 
    "모두 준비됐니?" 물어보고(1단계), 모두 OK 하면 "다 같이 커밋!"(2단계) 하는 방식이죠.
```

2\. JTA (Java Transaction API)
-----------
JTA는 자바에서 XA 트랜잭션을 처리하기 위한 표준 인터페이스(API)입니다.
```
역할: 개발자가 직접 "A DB 준비됐니? B DB 준비됐니?"라고 복잡하게 코딩하는 대신, 
     UserTransaction 같은 인터페이스를 통해 "트랜잭션 시작/종료"만 명령하면 나머지는 JTA가 알아서 관리하게 해줍니다.

특징: JTA 자체는 '껍데기(인터페이스)'일 뿐입니다. 실제로 이 기능을 수행할 구현체(매니저)가 필요합니다.
```

3\. Atomikos
--------
Atomikos는 위에서 말한 JTA의 실제 구현체 중 하나입니다.
```
왜 필요한가?: 과거에는 JTA를 쓰려면 WebLogic이나 JBoss 같은 무거운 유료 WAS(Web Application Server)가 필요했습니다. 
            하지만 Tomcat 같은 가벼운 서버는 JTA 기능을 내장하고 있지 않죠.

솔루션: Atomikos는 오픈 소스 트랜잭션 매니저로, Tomcat 같은 환경에서도 XA(분산 트랜잭션)를 가능하게 해줍니다. 
       스프링 부트(Spring Boot) 환경에서 분산 트랜잭션이 필요할 때 가장 많이 선택되는 라이브러리 중 하나입니다.
```
