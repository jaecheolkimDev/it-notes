분산 트랜잭션(Distributed Transaction)
=============

1\. 2PC (Two-Phase Commit): 원자성 중심 (ACID)
--------
```
2PC는 주로 인프라/미들웨어 계층에서 해결하려는 방식입니다.
    
    갈래: 결정론적(Deterministic) 프로토콜. 모든 참여자가 "YES"를 해야만 최종 커밋을 하는 방식입니다.
    특징: DB 커널 수준이나 메시지 브로커(JMS 등) 수준에서 트랜잭션을 관리합니다.
    장점: 개발자가 비즈니스 로직에 롤백 코드를 일일이 짤 필요가 없습니다. (자동화)
    단점: 한 놈이라도 응답이 없으면 전체 시스템이 대기 상태(Lock)에 빠지는 '블로킹 문제'가 심각합니다. 
         현대 MSA 환경에서는 성능 때문에 잘 안 씁니다.
```

2\. TCC (Try-Confirm-Cancel): 보상 중심 (BASE)
-----------
```
TCC는 애플리케이션(코드) 계층에서 해결하려는 방식입니다.
    
    갈래: 보상 트랜잭션(Compensating Transaction). 2PC의 '블로킹' 문제를 피하기 위해, 일단 각각의 로컬 트랜잭션을 커밋하되 문제가 생기면
         "취소" 로직을 실행해 결과를 맞춥니다.
    특징: 분산 시스템의 최종적 일관성(Eventual Consistency)을 목표로 합니다.
    장점: DB 락(Lock) 시간이 짧아 성능이 좋습니다. 상대 시스템이 XA 같은 표준을 지원 안 해도 API만 있으면 구현 가능합니다.
    단점: 개발자가 Confirm 성공 로직과 Cancel 취소 로직을 직접 코딩해야 하므로 개발 공수가 매우 큽니다.
```
