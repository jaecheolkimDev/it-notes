DB 트랜잭션 격리수준(Isolation Level) 공부 노트
=============

1\. 개념
--------
```
데이터베이스에서 여러 트랜잭션이 동시에 실행될 때, 각 트랜잭션이 서로의 데이터 변경에 얼마나 영향을 받지 않고 독립적으로 실행되는지를 정의하는 설정으로, 
Read Uncommitted, Read Committed, Repeatable Read, Serializable의 4가지 주요 단계가 있으며, 
높아질수록 데이터 일관성은 보장되지만 동시 처리 성능은 저하되는 상충 관계를 가집니다. 
```

2\. 주요 격리 수준 (낮은 수준부터 높은 수준 순)
-----------
```
Read Uncommitted (커밋되지 않은 읽기) : 가장 낮은 수준으로, 다른 트랜잭션이 아직 커밋하지 않은 데이터(Dirty Data)도 읽을 수 있어 가장 성능이 좋지만, 
                                    데이터 일관성이 가장 낮습니다.
Read Committed (커밋된 읽기)         : 커밋된 데이터만 읽을 수 있어 Dirty Read는 방지하지만, 같은 트랜잭션 내에서 반복적으로 읽을 때 다른 트랜잭션에 의해 
                                     데이터가 변경될 수 있습니다 (Non-repeatable Read 발생).
Repeatable Read (반복 가능한 읽기)    : 한 트랜잭션 내에서 동일한 데이터를 여러 번 읽어도 항상 같은 값을 보장합니다 (Snapshot 기술 사용). 
                                     하지만 새로운 행이 추가되는 현상(Phantom Read)은 발생할 수 있습니다.
Serializable (직렬화 가능)           : 가장 높은 수준으로, 모든 트랜잭션을 순서대로 하나씩 실행하는 것과 동일한 결과를 보장합니다. 
                                     데이터 일관성은 최고지만, 동시 처리 성능이 가장 낮습니다. 
```

3\. 선택의 기준
--------
```
높은 격리 수준: 데이터의 정확성과 일관성이 매우 중요한 금융 거래 등에서 유리합니다.
낮은 격리 수준: 대규모 데이터 조회나 속도가 중요한 경우, 어느 정도의 데이터 불일치를 감수하고 성능을 높일 수 있습니다. 
```
