DB 문법
=============

1\. 문법
--------
```
1) 오라클
 - NULLIF(expr1, expr2)   : expr1과 expr2가 같으면 NULL을 반환하고, 같지 않으면 expr1을 반환
 - LISTAGG(컬럼, '구분자') WITHIN GROUP (ORDER BY 정렬기준)    : 여러 행의 한 컬럼 값을 특정 구분자(쉼표 등)로 연결할때 사용합니다. 
                                                              그룹별 데이터를 하나의 문자열로 합칠 수 있습니다.
                                                              4,000byte 초과하면 오류 발생하므로 XMLAGG 사용해야함
 - XMLELEMENT               : 자동으로 인코딩함(예약어를 엔티티로 변환) - 데이터를 XML 형식에 맞게 "보호"하려다 보니 발생한 부작용
 - DBMS_XMLGEN.CONVERT      : 2번째 넣는 인자로 인코딩이나 디코딩을 함.
    - 0 (Encoded): 문자를 엔티티로 바꿈 (기호를 코드로)
    - 1 (Decoded): 엔티티를 문자로 바꿈 (코드를 기호로)
 - UNION                    : 중복되는 결과를 제외한다.(중복은 1개만 표시)
 - UNION ALL                : 중복되는 결과까지 다 보여준다.(중복을 전부 표시)
 - SUBSTR('20140101', 1, 4)     : '2014'
 - TO_CHAR(ADD_MONTHS(SYSDATE, -12), 'YYYYMMDD')    : 1년전 조회
 - TO_CHAR(1234567, 'FM999,999,999,990')            : 3자리 콤마
 - SIGN(x)      : X값이 0보다 작으면 -1 , 0이면 0 , 0보다 크면 1을 반환
 - LENGTHB(x)   : 바이트수 계산
 - MOD(m, n)    : m을 n으로 나누었을 때 나머지를 반환한다.
 - NVL(값, null일때 값)
 - NVL2(컬럼, NULL이 아닐 때 값, NULL일 때 값)
 - RTRIM(컬럼, 오른쪽 끝 제거하고 싶은 문자)
```

3\. 조인
--------
```
- (+) 아우터조인 	: 없을수도 있다는 의미
  : 조인 테이블의 값이 존재하지 않아도 메인 테이블의 데이터가 조회된다.
  LEFT OUTER JOIN: 왼쪽 테이블의 모든 값이 출력되는 조인
  RIGHT OUTER JOIN: 오른쪽 테이블의 모든 값이 출력되는 조인
- ON절   : 조인 대상 제한 (조인을 수행할 때만 해당 조건을 따집니다. 조건에 맞지 않더라도 기준 테이블의 데이터는 사라지지 않고 NULL과 함께 출력됩니다.)
- WHERE절: 최종 결과 제한 (조인이 모두 끝난 판 위에서 데이터를 삭제합니다. 이 과정에서 OUTER JOIN이 사실상 INNER JOIN처럼 동작하게 되어 
           기준 테이블의 데이터가 사라질 수 있습니다.)
```

4\. 오류
--------
```
ORA-00907 : 누락된 우괄호
    - SUBQUERY 안에서 ORDER BY 사용하면 발생한다.(스칼라 서브쿼리에서는 단건만 나와야해서 ORDER BY가 의미없음.)
ORA-00918 : 열의 정의가 애매합니다
    - 똑같은 이름의 컬럼(예: ID, CREATE_DATE 등)이 존재하는데, SELECT절이나 WHERE절에서 어떤 테이블의 컬럼인지 명시하지 않았을 때 발생합니다.
ORA-01722 : 수치가 부적합합니다.
    - TO_NUMBER(1,200) : VARCHAR2로 저장된값을 변환하려고할때 콤마를 변환못할때 발생하는 오류.
```

6\. MERGE INTO
--------
```
오라클의 MERGE INTO 문은 USING 절에 있는 소스 테이블(또는 서브쿼리)의 데이터를 바탕으로 타겟 테이블에 데이터를 넣거나 바꿀지 결정합니다.

만약 USING 안에 WHERE 1=9999 같은 절대 거짓(False)인 조건이 붙으면 다음과 같은 과정이 일어납니다.

소스 데이터가 0건이 됨: USING 안의 쿼리가 반환하는 결과 집합(Row)이 아무것도 없게 됩니다.

비교 대상이 없음: ON 절에서 타겟 테이블과 비교할 소스 데이터 자체가 존재하지 않습니다.

모든 액션 패스: * 기존 데이터와 일치하는지(WHEN MATCHED) 확인할 수 없으니 UPDATE나 DELETE가 수행되지 않습니다.

일치하지 않는 새로운 데이터(WHEN NOT MATCHED)도 없으니 INSERT 역시 수행되지 않습니다.
```
