인코딩
======================

1\. 인코딩 / 디코딩
--------------
```
인코딩 : 컴퓨터가 이해할 수 있는 형태로 바꿈.
디코딩 : 사람이 이해할 수 있는 형태로 바꿈.
```

1\. 텍스트 / 문자를 숫자로 표현 (Character Encoding)
--------------
사람이 읽는 문자를 컴퓨터가 이해하는 비트(0과 1)로 변환하는 방식입니다.
```
1) ASCII (7비트): 영문 대소문자, 숫자, 특수문자 등 128개 문자를 표현하는 가장 기본적인 인코딩입니다.
2) UTF-8 (가변 길이): 오늘날 웹과 시스템의 표준입니다. ASCII 영역은 1바이트, 한글/한자 등은 3바이트로 효율적으로 표현합니다.
3) UTF-16 (16비트/32비트): Java, Windows 내부 메모리 표현 등에 주로 쓰이며, 기본 문자를 2바이트(16비트) 단위로 다룹니다.
```

1\. URL 및 웹 전송용 인코딩
--------------
웹 주소(URL)에서 사용할 수 없는 특수문자나 한글을 안전하게 전달하기 위한 방식입니다.
```
1) Percent Encoding (URL Encoding):
 - URL 규격(RFC 3986)에 벗어나는 문자를 % 뒤에 16진수 바이트 값으로 변환합니다.
 - 예: 한글 안녕 $\rightarrow$ %EC%95%88%EB%85%90
2) HTML Entity Encoding:
 - HTML 내부에서 <, >, & 같은 문자가 태그로 해석되지 않도록 변환합니다. (XSS 방어용)
 - 예: <script> $\rightarrow$ &lt;script&gt;
```

1\. Base-N 계열 인코딩 (Base64 외)
--------------
Base64나 Base62처럼 특정 문자 세트만 사용하여 데이터를 줄이거나 특수문자를 제거하는 방식들입니다.
```
방식              사용 문자                                           특징 및 주요 용도
Base16 (Hex)    "0-9, A-F (16개)"                                "16진수 표현. 해시값(SHA-256), 바이트 배열 출력, 색상 코드(#FFFFFF) 등에 사용"
Base32          "A-Z, 2-7 (32개)"                                "혼동하기 쉬운 숫자(0, 1, 8, 9)를 제외하여 사람이 직접 입력할 때 오타를 줄임. OTP 인증키, DNSSEC 등에 활용"
Base58          "Base64에서 헷갈리는 6개 제외 (0, O, I, l, +, /)"    비트코인/블록체인 주소 생성. 사람이 읽고 복사하기 쉬우며 URL Safe함
Base85 (Ascii85) 출력 가능한 ASCII 85개                           Base64보다 용량 증가율이 낮음 (약 33% → 약 25% 증가). PDF 파일 내부 데이터 압축 등에 사용
```

1\. 데이터 구조화 / 직렬화 (Serialization Encoding)
--------------
프로그램 내의 객체(Object)나 구조체 데이터를 통신/저장용 텍스트 또는 바이너리로 변환하는 인코딩입니다.
```
1) JSON / XML (텍스트 기반): 사람이 읽기 쉽지만 데이터 용량이 큽니다.
2) Protocol Buffers (Protobuf) / FlatBuffers (바이너리 기반): Google에서 개발한 방식 등으로, 필드명을 텍스트 대신 바이너리 
                                                태그로 변환하여 전송 크기를 획기적으로 줄이고 속도를 높입니다. (gRPC 등에 사용)
```
