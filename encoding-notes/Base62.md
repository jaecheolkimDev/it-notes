Base62
======================

1\. 정의
--------------
데이터를 62개의 문자로 표현하는 진법 변환 방식(인코딩)입니다.
```
알파벳 대문자(26개), 소문자(26개), 숫자(10개)를 조합하여 $26 + 26 + 10 = 62$개의 문자를 기본 단위로 사용합니다.
```

3\. 사용되는 문자 구성
--------------
Base62는 사람이 읽기 쉬우면서도, 특수문자 없이 표현할 수 있는 최대 영역의 문자를 사용합니다. 일반적으로 아래의 인덱스 순서를 따릅니다.
```
1) 숫자 (0-9): 10개
2) 알파벳 대문자 (A-Z): 26개
3) 알파벳 소문자 (a-z): 26개
```

4\. Base64와의 차이점
--------------
```
구분          Base62                              Base64
사용 문자       숫자(10) + 대문자(26) + 소문자(26)  "숫자(10) + 대문자(26) + 소문자(26) + +, / (+ 패딩 =)"
특수문자 사용     사용 안 함                          사용함
URL 안전성     안전함 (URL Safe)                  "인코딩 없이 URL에 쓰면 파라미터 충돌 위험 (+, /)"
주요 목적       "ID 단축, URL 인코딩, 특수문자 차단"   바이너리 데이터를 텍스트로 변환 (이메일 첨부파일 등)
```

1\. 주요 활용 사례
--------------
URL Shortener(단축 URL) 서비스나 고유 ID 생성 시스템에서 널리 활용됩니다.
```
1) 단축 URL 서비스 (e.g., bit.ly):
 - 데이터베이스의 Auto-Increment PK(숫자 ID)가 100000000처럼 길어질 때, 이를 Base62로 변환하면 6LA6A처럼 매우 짧은 문자열로 
   압축하여 URL 경로에 사용할 수 있습니다.
2) 고유 ID / 토큰 생성:
 - UUID는 36자(하이픈 포함)로 길지만, 이를 정수로 바꾼 뒤 Base62로 변환하면 약 22자의 정돈된 문자열로 줄어듭니다.
3) 파일명 및 시스템 파라미터:
 - 운영체제나 웹서버에서 문제를 일으키기 쉬운 특수문자(/, \, ?, % 등)가 전혀 들어가지 않아 안전합니다.
```

1\. 동작 원리 (진법 변환 예시)
--------------
```
10진수 숫자를 62로 계속 나누어 나머지를 Base62 문자 매핑 테이블에서 찾아 붙이는 방식을 씁니다.
예시: 10진수 12345를 Base62로 변환
 - $12345 \div 62 = 199$, 나머지 9
 - $199 \div 62 = 3$, 나머지 13
 - $3 \div 62 = 0$, 나머지 3
각 나머지를 62진수 매핑표로 변환합니다.
 - $3 -> '3'
 - $13 -> 'D' (0~9는 숫자, 10은 'A', 11은 'B', 12는 'C', 13은 'D')
 - $9 `->` '9'
역순으로 조합하면 10진수 12345는 Base62로 3D9가 됩니다.
```

1\. 장점과 한계
--------------
```
1) 장점:
 - 우수한 가독성 및 안전성: URL, 파일명, DB 저장 등에 특수문자 탈출(Escape) 처리가 필요 없음
 - 효율적인 길이 축소: 10진수 대비 훨씬 짧은 문자열로 표현 가능
2) 한계:
 - 대소문자 구분 필수: 대소문자를 구분하지 않는 시스템/DB 환경(예: 대소문자 구분이 없는 Collation 설정)에서는 데이터 충돌이 발생할 수 있음
 - 암호화가 아님: 단순히 진법을 변환(인코딩)한 것이므로 보안 목적으로 사용할 수 없음 (누구나 쉽게 10진수로 복원 가능)
```
