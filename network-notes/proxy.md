proxy
=====================

1\. Forward Proxy
--------------------------------------
```
연결의 클라이언트 측에 위치 (서버는 실제 요청을 보낸 클라이언트의 IP를 알 수 없음)
- 캐싱        : 자주 요청되는 리소스 저장으로 통신속도 향상 시킴
- 접근 제어    : 특정 웹사이트나 컨텐츠에 대한 접근을 필터링하거나 제어합니다
```

2\. Reverse Proxy
--------------------------------------
```
백엔드 서버 앞단에 배치
1) 역할
 - 클라이언트 요청 수신
 - 적절한 서버로 요청 전달
 - 서버의 응답을 다시 클라이언트에게 반환
 
2) 추가 가치
 - 로드 밸런싱
 - 보안       : 백엔드 서버의 세부 정보를 숨기고 악의적인 요청을 프록시단에서 필터링함
 - 로깅       : 백엔드 서버의 바로 앞단에 있기 때문에 요청과 응답에 대한 정보를 로깅
 - 모니터링    : 백엔드 서버의 바로 앞단에 있기 때문에 요청과 응답에 대한 정보를 모니터링
```

3\. API Gateway
--------------------------------------
```
본질적으로는 리버스 프록시 (클라이언트는 하나의 엔드포인트만 호출하면 되기 때문에 복잡도가 줄어듬)
- API 트래픽 처리에 특화            : 클라이언트의 요청을 적절한 서버에 라우팅 시켜줌
- 요청 제어, 인증, 로깅, 응답 가공 등
```
