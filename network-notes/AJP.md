AJP(Apache JServ Protocol) 공부 노트
=====================

1\. AJP 프로토콜의 역할 (왜 쓰는가?)
--------------------------------------
"웹 서버(Apache)와 WAS(JBoss/Tomcat)가 서로 대화하기 위해 사용하는 통신 규약"입니다.
```
효율성: HTTP보다 데이터 크기가 작고 최적화되어 있어 통신 속도가 빠릅니다.
연결 유지: 한 번 연결을 맺으면 계속 재사용하여 성능을 높입니다.
정보 전달: 웹 서버가 받은 클라이언트의 IP 주소나 인증 정보 등을 WAS에게 아주 상세하게 전달해 줍니다.
```

2\. Delay Timeout
--------------------------------------
```
질문자님이 보신 10분(600초) 설정은 바로 이 AJP 통신로의 '응답 대기 시간'입니다.
"상대방의 응답을 얼마나 기다려줄 것인가"를 정하는 규칙 중 하나입니다.
웹 서버(Apache)가 WAS를 기다려주는 시간입니다. 하지만 이 시간이 길게 잡혀 있으면, 
WAS가 내부에서 트랜잭션 에러(50초)를 냈더라도 웹 서버가 계속 소켓을 붙잡고 있기 때문에 WAS 스레드가 풀려나지 못하는 현상이 발생합니다.
reply_timeout (AJP 설정): "내가(Web) 너에게(WAS) 일을 보냈는데, 너는 아무리 늦어도 10분 안에는 나한테 답을 줘야 해. 
안 주면 나 이 연결 끊어버릴 거야."라는 약속입니다.
```

3\. 스턱 스레드(Stuck Thread)
--------------------------------------
```
WAS 스레드가 AJP소켓을 점유한 채로 설정된 시간(ex. 300초) 이상 넘어갔을때 Stuck Thread 진단을 함.
사내 시스템에서 Apache-JBoss 구조를 쓸 때, 이 AJP 연결은 'Persistent Connection'이라고 해서 연결을 계속 유지하려고 합니다.
50초 지점: 자바 코드(@Transactional)는 타임아웃이 나며 "끝났다"고 하지만,
연결 상태: AJP는 여전히 "10분(600초)은 기다리기로 했으니까 소켓 열어둬!"라며 버팁니다.
결과: WAS 스레드는 AJP 소켓을 점유한 채로 멍하게 서 있게 되고, 이게 5분이 넘어가면서 Stuck Thread 로그가 찍히게 되는 것입니다.
해결방법 : In-Memory Map 배치 조회 (가장 추천)
    사중 for문을 돌리기 전에, for문에 필요한 모든 데이터를 상위 부모 키(Key) 기준으로 딱 한 번만 대량 조회(In 쿼리 등)해 옵니다. 그 후 Java의 Map<Key, List<Entity>> 형태로 메모리에 올려두고, 
    for문 내부에서는 DB 조회 대신 map.get(key)로 데이터를 꺼내 쓰세요.
    효과: DB 조회 횟수가 10,000번에서 단 1~2번으로 줄어들어, 전체 수행 시간이 100초에서 0.x초로 단축됩니다. StuckThread 자체를 원천 봉쇄할 수 있습니다.
```
