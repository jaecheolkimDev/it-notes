HTTP 공부 노트
=====================

1\. HTTP 요청과 응답
--------------
```
HTTP 응답(Response)은 클라이언트(브라우저, 앱 등)가 서버에 요청(Request)을 보냈을 때 서버가 답변하는 데이터 구조입니다.

1. HTTP 응답의 구조 파악 (3대 요소)
 1) 상태 줄 (Status Line)         : HTTP 버전, 상태 코드(Status Code), 상태 텍스트(Reason-phrase)를 포함합니다.
                                   (예: HTTP/1.1 200 OK)
 2) 응답 헤더 (Response Headers)  : 서버 이름, 콘텐츠 타입, 날짜 등 메타데이터를 담고 있습니다.
 3) 메시지 본문 (Body)             : 실제 전송되는 데이터(HTML, JSON 등)입니다. 


2. HTTP 상태 코드(Status Codes)
  2xx (Success)       : 200 OK (성공), 201 Created (생성됨)
  3xx (Redirection)   : 301 Moved Permanently, 304 Not Modified
  4xx (Client Error)  : 400 Bad Request (잘못된 요청), 401 Unauthorized (인증 필요), 403 Forbidden (권한 없음)
                      , 404 Not Found (찾을 수 없음)
                      , 405 Method Not Allowd (메서드 불일치)
                      , 409 Conflict (요청 충돌)
  5xx (Server Error)  : 500 Internal Server Error (서버 내부 에러), 502 Bad Gateway, 502 Proxy Error, 503 Service Unavailable
                        , 504 타임 아웃
```

2\. 전송 제어의 뿌리: TCP/IP와 흐름 제어
--------------
HTTP의 모든 버전은 결국 그 아래 계층인 L4(전송 계층)와의 관계 속에서 탄생했습니다.
```
1) HTTP/1.1 (줄 서서 기다리기) : 한 번에 하나의 데이터만 보낼 수 있었습니다. 이미지 파일이 많으면 페이지 로딩이 '줄줄이' 늦게 뜨던 현상이 
                               바로 이 버전의 한계 때문이었습니다.
    * HoL Blocking (Head-of-Line Blocking): 앞선 요청(예: 대용량 이미지 조회)이 늦어지면 뒤에 있는 가벼운 API 호출들이 줄줄이 대기하게 됩니다.

2) HTTP/2 (한 길로 여러 개 보내기)   : 하나의 연결통로를 쪼개서 여러 데이터를 동시에 보내는 멀티플렉싱이 도입되었습니다. 덕분에 웹사이트 로딩 속도가 
                                   비약적으로 빨라졌습니다. 하지만 '도로(TCP)' 자체가 막히면 전체 데이터가 멈추는 고질적인 문제는 여전했습니다.

3) HTTP/3 (신속한 우회와 연결)  : 아예 도로의 기반(TCP → UDP)을 바꿨습니다. 모바일 환경에서 와이파이를 쓰다가 LTE로 바뀔 때 연결이 끊기지 않고 
                               부드럽게 유지되는 등의 강력한 연결 안정성과 더 빠른 초기 속도를 제공합니다.
```

3\. 정보 이론의 뿌리: 데이터 압축과 최적화 (Claude Shannon)
--------------
"데이터를 얼마나 작게 만들어 빨리 보낼 것인가"라는 정보 이론이 핵심 뿌리 중 하나입니다.
```
Header Compression (HPACK/QPACK): HTTP/1.1까지는 중복된 헤더 정보를 매번 텍스트로 다 보냈습니다. 하지만 버전이 올라가면서 "이미 보낸 정보는 
                                  생략하거나 압축하자"는 정보 이론적 접근을 통해 데이터 크기를 획기적으로 줄였습니다.
```

4\. 분산 시스템 아키텍처의 뿌리: 지연 시간(Latency)과의 싸움
--------------
컴퓨터공학에서 분산 시스템은 "네트워크는 믿을 수 없고 느리다"는 가정에서 출발합니다.
```
Round Trip Time (RTT) 최소화: 버전이 올라갈수록 '악수(Handshake)' 횟수를 줄이는 데 집착합니다. 1.1은 여러 번 왔다 갔다 해야 통신이 시작됐다면, 
                             3버전은 첫 요청에 바로 데이터를 실어 보낼 정도로 이 '왕복 시간'을 줄이는 데 집중했습니다.
```

5\. 보안 공학의 뿌리: 신뢰할 수 있는 통신
--------------
과거에는 보안이 선택(HTTP vs HTTPS)이었지만, 현대의 버전들은 보안을 뿌리부터 통합하고 있습니다.
```
HTTP/2 & 3: 최신 버전들은 사실상 암호화(TLS)를 기본 전제로 설계되었습니다. "성능을 올리되, 보안은 공기처럼 당연하게 존재해야 한다"는 현대 보안 
            공학의 철학이 반영된 것입니다.
```
