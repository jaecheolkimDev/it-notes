프로세스 디버깅 명령어 공부 note
======================

1\. ps  : 현재 실행 중인 프로세스의 정보를 확인하는 명령어입니다.
--------------
```
- 주요 옵션:
    • `-e` 또는 `-A` : 시스템의 모든 프로세스 정보를 출력합니다.
    • `-f` : 풀 포맷(full format)으로 프로세스의 상세 정보를 출력합니다. (UID, PID, PPID 등 표시)
    • `-u [사용자명]` : 특정 사용자의 프로세스 정보를 출력합니다.
    • `-p [PID]` : 특정 PID를 가진 프로세스 정보를 출력합니다.
    • `aux` : 시스템에서 실행 중인 모든 프로세스를 BSD 형식으로 상세히 출력합니다. (CPU, 메모리 사용량 포함)

- 사용 예시:
    1. `ps -ef`                   : 모든 프로세스 상세 확인 (표준) 
    2. `ps aux`                   : 모든 프로세스 상세 확인 (CPU/메모리 사용량 포함) 
    3. `ps -ef | grep 프로세스명`   : 특정 프로세스 검색 (grep 조합) 
    4. `ps -u 사용자명`             : 사용자별 프로세스 확인 
    
- 출력 항목 설명
    • UID / USER        : 프로세스를 실행한 사용자 ID
    • PID               : 프로세스 고유 ID
    • PPID              : 부모 프로세스 ID
    • %CPU / %MEM       : CPU 및 메모리 사용 백분율
    • COMMAND / CMD     : 실행된 명령어/프로세스 이름
```

2\. kill    : 프로세스를 '죽이는(종료시키는)' 명령어입니다.
--------------
```
좀 더 정확하게는 실행 중인 프로세스에게 특정 '신호(Signal)'를 보내는 역할을 합니다.
기본적으로 아무런 옵션 없이 kill을 사용하면 프로세스에게 종료 신호를 보내고, 이 신호를 받은 프로세스는 정상적으로 종료 절차를 수행합니다.

- 주요 시그널:
    시그널 번호	시그널 이름	설명
    15	        SIGTERM	    정상 종료를 요청합니다. 프로세스가 스스로 종료를 준비할 시간을 줍니다 (기본값).
    9	        SIGKILL	    강제 종료를 명령합니다. 프로세스가 무시할 수 없는 강력한 종료 명령입니다.
    💡 팁: 옵션을 지정하지 않으면 자동으로 SIGTERM (15번)이 사용됩니다.

- 사용 예시:
    - `$ kill [시그널 옵션] [PID]`
    - `$ kill -9 $(lsof -t -i:80)`    : 80번 포트를 사용하는 PID를 찾아 한꺼번에 종료
```

3\. top : CPU·메모리 등 시스템 자원 사용 현황과 프로세스 상태를 실시간으로 조회하는 명령어
--------------
```
컴퓨터는 CPU나 메모리가 부족하면 렉이 걸리기 때문에, CPU 또는 메모리의 사용률이 높은 프로그램이 컴퓨터를 느려지게 만든 프로그램일 가능성이 높다. 

## 2. 기본 사용법
- 사용법: `top` → 현재 실행 중인 프로세스와 시스템 자원 상태를 실시간으로 출력한다.
 - CPU 사용률이 높은 프로세스를 알아서 상위로 노출시켜준다. 

## 3. 화면 상단(System Summary)

- uptime: 시스템 가동 시간과 로그인한 사용자 수를 나타내는 정보이다.
- load average: 1·5·15분 평균 CPU 부하로, 실행 대기 중인 프로세스 수를 의미한다.
- Tasks: 전체 프로세스 수와 실행·대기·중지·좀비 상태의 구성 현황이다.
- %Cpu(s): user·system·idle 등 CPU 사용 비율을 구성요소별로 나타낸다.
 - ex) 99.7 id      : 여유로운 CPU 비중이 99.7%
- MiB Mem: 전체·사용·여유·버퍼/캐시 메모리로 구성된 물리 메모리 상태이다.
 - ex) 538.4 free   : 538.4MB만큼 사용할 수 있는 여분이 메모리가 있음 
- MiB Swap: 스왑 메모리의 전체 용량과 사용량을 나타내는 가상 메모리 정보이다.

## 4. 프로세스 목록(Process List)

- PID: 프로세스를 식별하는 고유한 프로세스 ID이다.
- USER: 해당 프로세스를 실행한 사용자 계정이다.
- PR: 커널이 관리하는 프로세스 우선순위 값이다.
- NI: nice 값으로, 우선순위 조정을 위한 사용자 지정 값이다.
- VIRT: 프로세스가 사용하는 전체 가상 메모리 크기이다.
- RES: 실제 RAM에서 사용 중인 물리 메모리 크기이다.
- SHR: 다른 프로세스와 공유 중인 메모리 크기이다.
- S: 프로세스 상태(R 실행, S 대기 등)를 나타낸다.
- %CPU: 해당 프로세스의 CPU 사용 비율이다.
- %MEM: 전체 메모리 대비 해당 프로세스의 사용 비율이다.
- TIME+: 프로세스가 CPU를 사용한 누적 시간이다.
- COMMAND: 실행 중인 명령어나 프로그램 이름이다.

## 5. 실행 중 키 명령어

- q: top 명령어를 종료한다.
- P: CPU 사용률 기준으로 프로세스를 정렬한다.
- M: 메모리 사용량 기준으로 프로세스를 정렬한다.
- T: 실행 시간 기준으로 프로세스를 정렬한다.
- k: 특정 PID를 입력해 프로세스를 종료한다.[15/sigterm]
- 1: CPU 코어별 사용률을 개별로 표시한다.
- h: 도움말 화면을 출력한다.
- o: 'PID=38219' 등을 통해 필터할 수 있다.
- =: 필터 초기화

## 6. 초보자 핵심 체크 포인트

- CPU 병목 확인: load average와 idle CPU 비율을 함께 확인한다.
- 메모리 부족 확인: free·available 메모리 수치를 확인한다.
- 문제 프로세스 탐지: %CPU 또는 %MEM이 과도한 프로세스를 찾는다.

## 7. 연관 명령어

- htop: top을 시각적으로 개선한 대화형 프로세스 모니터이다.
- ps: 특정 시점의 프로세스 상태를 조회하는 명령어이다.
- vmstat: CPU·메모리·IO 상태를 요약해서 보여주는 명령어이다.
```

5\. strace(System Call Trace)   : 
--------------
프로세스가 실행되면서 커널(Kernel)에 요청하는 시스템 콜(System Call)과 프로세스가 받는 신호(Signal)를 추적하고 기록하는 강력한 디버깅 툴입니다.
```
- 주요 옵션:
    -c	프로그램을 마칠 때까지의 시스템 콜 통계(횟수, 시간, 에러)를 요약해서 표로 보여줌. (성능 병목 지점 찾기 좋음)	
    -e	특정 시스템 콜만 필터링해서 확인. (file, process, network, signal 등 표현 가능)
    -o	추적 결과를 화면이 아닌 파일로 저장.	
    -t / -tt	각 시스템 콜이 실행된 시각(Time)을 표시 (-tt는 마이크로초 단위까지).	
    -T	각 시스템 콜이 소요한 실제 시간(Duration)을 맨 끝에 표시.	
    -f	자식 프로세스(Fork된 프로세스)나 멀티 스레드까지 함께 추적.	

- 사용 예시:
    - strace -c ls	
    - strace -e trace=openat,read ls
    - strace -e trace=network -p 1234
    - strace -o output.txt ls
    - strace -tt ls
    - strace -T ls
    - strace -f -p 1234
    - strace ls -l        :새 프로그램을 실행하면서 시스템 콜 추적
    - strace -p 1234      : 이미 실행 중인 프로세스(PID)에 붙어서(Attach) 추적
    
- 주의
    - strace는 프로세스의 모든 시스템 콜을 가로채서 기록하므로, 실행 중인 서비스의 성능을 눈에 띄게 떨어뜨릴 수 있습니다 (약 2x~10x 이상 느려짐)
```


6\. jstack  : 자바 가상 머신(JVM) 내에서 실행 중인 특정 자바 프로세스의 스레드 덤프(Thread Dump)를 생성하는 유틸리티
--------------
```
- 주요 옵션:
    -`l`	Long listing. 스택 정보와 함께 잠금(Lock)과 관련된 추가 정보를 출력합니다. (Deadlock 분석 시 필수)
    -`F`	Force. 프로세스가 응답하지 않을 때 강제로 스레드 덤프를 생성합니다. (일반 jstack이 작동하지 않을 때 사용)
    
- 사용 예시:
    jstack [옵션] <pid>
```
