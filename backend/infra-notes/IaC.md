IaC(Infrastructure as Code, 코드로서의 인프라)
======================

1\. 정의
--------------
```
서버, 네트워크, 스토리지 등 클라우드 인프라 자원을 클릭이나 수작업 대신 텍스트 파일(코드)로 정의하고 관리하는 기술 및 수법입니다.
```

1\. 핵심 요점
--------------
```
1) 자동화 및 신속성: 명령 한 줄로 수백 개의 인프라 자원을 몇 분 만에 동일하게 생성
2) 버전 관리 (Git): 인프라 변경 이력을 Git으로 관리하여 추적 및 이전 상태로 복구(Rollback) 용이
3) 휴먼 에러 방지: 클릭 실수나 일관성 없는 설정으로 인한 장애 최소화
4) 문서화: 작성된 코드 자체가 곧 최신 인프라 구성도가 됨
```

1\. 선언적(Declarative) vs 명령적(Imperative) 접근 방식
--------------
IaC는 크게 두 가지 방식으로 작성됩니다.
```
구분      선언적 (Declarative)                           명령적 (Imperative)
개념      "**""무엇(What)""**을 만들지 최종 상태를 정의"   """어떻게(How)"" 만들지 순서대로 명령 실행"
특징      최종 상태만 명시하면 도구가 알아서 변경사항 계산     인프라 생성 절차를 스크립트로 하나씩 제어
장점      멱등성(Idempotency) 보장이 쉬움                 기존 프로그래밍 언어의 제어문 활용에 유용
대표 도구   "Terraform, AWS CloudFormation"             "AWS CDK, Pulumi, Bash Script"
```

1\. 대표적인 IaC 도구 분류
--------------
```
1) 프로비저닝 도구 (Provisioning): 클라우드 인프라 자원(VPC, EC2, RDS 등)을 생성 및 배치
 - Terraform (멀티 클라우드 지원, 가장 광범위하게 사용)
 - AWS CloudFormation (AWS 전용)
2) 구성 관리 도구 (Configuration Management): 생성된 서버 내부의 OS 설정 및 소프트웨어 설치/배포
 - Ansible, Chef, Puppet
```
