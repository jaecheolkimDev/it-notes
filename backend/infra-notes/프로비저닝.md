프로비저닝(Provisioning)
======================

1\. 정의
--------------
```
 - 사용자가 요청한 IT 자원(서버, 네트워크, 애플리케이션, 계정 등)을 사용 가능한 상태로 준비하여 제공하는 일련의 과정을 의미합니다.
 - 단순히 장비를 설치하는 것을 넘어, 시스템이 즉시 정상 작동하도록 설정(Configuration)하고 권한을 부여하는 전체 수명주기 관리 
   프로세스를 포함합니다.
```

1\. 주요 프로비저닝 유형
--------------
```
1) 서버/인프라 프로비저닝 (Server/Infra Provisioning)
 - 물리 서버 설치, 가상 머신(VM) 생성, OS 설치, IP 배정, 기본 패키지 설치 등을 진행하여 개발자나 운영자가 즉시 사용할 수 있도록 
   인프라를 구동합니다.
2) 클라우드 프로비저닝 (Cloud Provisioning)
 - AWS, GCP, Azure 등 클라우드 환경에서 필요한 컴퓨팅 자원(EC2, S3, RDS 등)을 주문에 맞게 동적으로 할당하고 구성합니다.
3) 계정/사용자 프로비저닝 (User/Identity Provisioning)
 - 신규 입사자나 서비스 회원에게 사번/ID 생성, 이메일 계정 할당, 부서·직급별 시스템 접근 권한(IAM) 부여 등을 일괄 처리합니다.
4) 네트워크 프로비저닝 (Network Provisioning)
 - 스위치, 라우터 설정, 방화벽 규칙 적용, VLAN 분리, IPsec VPN 터널링 등을 통해 통신 경로를 확보합니다.
5) 소프트웨어/애플리케이션 프로비저닝 (Software Provisioning)
 - 미들웨어(WAS, DB) 설치, 필요한 라이브러리 및 환경변수 설정, 컨테이너(Docker, Kubernetes) 배포 등을 수행합니다.
```

1\. 수동 프로비저닝 vs 자동 프로비저닝
--------------
```
구분      수동 프로비저닝 (Manual)                       자동 프로비저닝 (Automated)
방식      엔지니어가 직접 GUI/CLI에 접속하여 일일이 설정   "스크립트, API, 자동화 도구를 통해 일괄 실행"
속도      수시간~수일 소요                               수초~수분 내 완료
휴먼 에러   "작업자 실수(오타, 누락) 발생 가능성 높음"      동일 코드로 수행하여 환경 일관성 제고
확장성     서버 수 늘어날수록 공수 비례 증가                 서버 백 대도 클릭 한 번으로 일괄 배포 가능
```

1\. 프로비저닝 핵심 자동화 기술 (IaC)
--------------
현대 IT 인프라에서는 코드로 인프라를 관리하는 IaC(Infrastructure as Code) 기법을 활용해 프로비저닝을 자동화합니다.
```
1) 인프라 프로비저닝 도구: Terraform, AWS CloudFormation (클라우드/가상 자원 생성)
2) 구성 관리(Configuration Management) 도구: Ansible, Chef, Puppet (생성된 서버 내부 설정 및 패키지 설치)
3) 컨테이너 오케스트레이션: Kubernetes, Docker Swarm (컨테이너 기반 자원의 자동 할당 및 관리)
```

1\. 디프로비저닝
--------------
자원을 할당하는 것만큼 사용이 끝난 자원을 회수하는 디프로비저닝(Deprovisioning) 과정도 중요합니다.
```
1) 자원 절감: 미사용 서버나 VM을 격리·삭제하여 Cloud 비용 오버헤드 방지
2) 보안 강화: 퇴사자 계정의 접근 권한 즉시 박탈 및 SSH 키/토큰 회수
```
