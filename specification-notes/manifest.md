Manifest 공부 노트
=================

1\. 철학
----------------------------------------
```
결국 컴퓨터공학에서 매니페스트는 다음 세 가지 철학을 계승합니다.
    캡슐화: 내부를 다 뜯어보지 않아도 밖에서 정보를 알 수 있게 함.
    무결성: 목록에 적힌 것과 실제 내용물이 일치하는지 확인하는 기준.
    자동화: 사람이 아닌 시스템(OS, 런타임)이 읽고 스스로 판단하게 함.
```


2\. 배포의 규격화 (Packaging)
----------------------------------------
```
1990년대 Java가 등장하면서 여러 클래스 파일을 하나의 JAR 파일로 묶기 시작했습니다. 
이때 내부의 MANIFEST.MF 파일이 "이 중 메인 함수는 어디에 있는가?"를 알려주는 역할을 하며 표준화되었습니다.
```


3\. 의존성 관리 (Dependency)
----------------------------------------
```
소프트웨어가 외부 라이브러리에 의존하게 되면서, "이 프로그램을 실행하려면 A, B, C 라이브러리가 필요하다"는 정보를 기록할 필요가 생겼습니다.
```


4\. 선언적 프로그래밍 (Declarative Programming)
----------------------------------------
```
최근의 쿠버네티스나 테라폼 같은 클라우드 기술에서는 매니페스트가 더 강력해졌습니다. 
단순히 목록을 보여주는 것을 넘어, "시스템이 이 매니페스트에 적힌 상태와 똑같이 유지되어야 한다"는 설계도(Blueprint)의 역할까지 확장되었습니다.
```
