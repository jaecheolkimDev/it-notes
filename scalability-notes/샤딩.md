샤딩 (Sharding) 공부 노트
================

1\. 개념 : 데이터베이스의 수평적 확장 기법입니다.
-----------------------------
샤딩은 여러 데이터베이스 서버에 나누어 저장하는 방식입니다.
```
파티셔닝의 확장된 개념입니다.
각각의 분할된 데이터베이스를 샤드라고 부릅니다.
```

2\. 목적
-----------------------------
```
1) 데이터베이스의 부하 분산
2) 전체 시스템의 성능을 향상
```

3\. 종류
-----------------------------
```
1) Range 샤딩 : 특정값을 기준으로 나눔. 구현이 간단해서 많이 쓰임. 하지만, 특정 샤드의 데이터가 집중될 수도 있다는 단점이 있습니다.
2) Hash 샤딩  : 해시 함수를 사용해서 데이터를 분산시키는 방식으로 균등한 분포를 원할 때 사용. 하지만, 새로운 샤드를 추가하면 재샤딩이 필요합니다.
3) Geographic 샤딩    : 사용자의 지리적 위치를 기준으로 데이터를 분산시키는 샤딩. 
```

4\. 필요한 이유
-----------------------------
```
1) 확장성 문제           : 데이터베이스의 크기가 증가함에 따라 단일 서버로 모은 데이터를 효율적으로 처리하기 어려워집니다.
                         이는 쿼리 속도 저하나 저장 공간 부족 문제 등으로 이어질 수 있습니다.
2) 성능 및 용량 한계 해결  : 샤딩을 통해 데이터를 여러 서버로 분산시키면 각 서버가 처리해야 할 데이터의 양이 줄어들기 때문에 성능이 향상됩니다.
```

5\. 단점
-----------------------------
```
1) 데이터베이스의 구조를 상대적으로 좀 복잡하게 만들 수 있음.
2) 여러 서버에 분산된 데이터를 일관성 있게 유지하는 것도 중요한 과제가 됩니다.
3) 샤드 간 조인 연산이 필요할 경우에는 추가적인 프로그래밍 등이 필요할 수도 있습니다.
```
