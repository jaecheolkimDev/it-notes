Scalability(확장성) 공부 노트
================

1\. 수직적 확장 (Vertical Scaling / Scale-up)
-----------------------------
컴퓨터 아키텍처 및 하드웨어 성능 최적화
```
단일 장비(노드)의 성능을 높이는 방식입니다.
기술적 기원: CPU의 클럭 속도 향상, 멀티코어 설계, 메모리(RAM) 용량 증대 등 하드웨어 사양을 업그레이드하는 전통적인 방식에 기반합니다.
특징: 소프트웨어 구조를 크게 바꿀 필요가 없어 관리가 비교적 단순하지만, 하드웨어 비용이 기하급수적으로 비싸지고 
     물리적인 한계(한 대의 컴퓨터가 가질 수 있는 최대 성능)에 부딪히는 단점이 있습니다.
```

2\. 수평적 확장 (Horizontal Scaling / Scale-out)
-----------------------------
분산 시스템 및 병렬 컴퓨팅 (Distributed Systems & Parallel Computing)
```
여러 대의 저렴한 컴퓨터를 연결하여 하나의 거대한 시스템처럼 동작하게 만드는 방식입니다.
기술적 기원: 여러 노드 간의 데이터를 동기화하고 부하를 분산하는 로드 밸런싱(Load Balancing), 클러스터링 기술, 그리고 클라우드 컴퓨팅의 핵심인 
           가상화 기술 등에서 파생되었습니다.
특징: 이론적으로 무한한 확장이 가능하고, 한 대가 고장 나도 다른 컴퓨터가 대신 일할 수 있는 가용성(Availability)이 높습니다. 
     다만, 여러 대의 서버 간 데이터 일관성을 유지하기 위한 복잡한 소프트웨어 설계가 필요합니다.
```

3\. 무어의 법칙 : 반도체 집적회로의 성능이 약 24개월마다 2배로 증가한다"는 관측 보고입니다.
-----------------------------
```
현재의 한계: 최근에는 미세 공정의 물리적 한계와 발열 문제로 인해 단일 코어의 성능 향상이 둔화되었습니다. 
           이로 인해 현대 컴퓨팅은 단일 성능을 높이는 대신, 여러 CPU를 사용하는 수평적 확장(Scale-out)과 병렬 컴퓨팅으로 패러다임이 
           완전히 전환되었습니다.
```

4\. SPOF (Single Point of Failure, 단일 장애점) : 시스템 전체를 중단시킬 수 있는 단 하나의 지점"을 의미합니다.
-----------------------------
```
배경: 수직적 확장의 가장 큰 위험 요소입니다. 아무리 강력한 서버 한 대를 사용하더라도, 
     그 서버(또는 전원 공급 장치, 네트워크 스위치 등)가 고장 나면 서비스 전체가 마비됩니다.
확장성과의 관계: 수평적 확장(Scale-out)은 이 SPOF를 제거하기 위한 핵심 전략입니다. 
              여러 대의 서버에 기능을 분산(Redundancy)함으로써, 한 대가 죽어도 나머지 서버가 서비스를 유지할 수 있게 합니다.
```

5\. 가용성 (Availability)
-----------------------------
```
시스템이 정상적으로 서비스를 제공할 수 있는 상태를 말합니다. 
보통 "99.999%(Five Nines)"와 같은 비율로 측정하며, SPOF를 제거할수록 가용성이 높아집니다.
```

6\. 중복성 (Redundancy)
-----------------------------
```
장애에 대비해 핵심 부품이나 서버를 여러 개 배치하는 것입니다. 
"1+1" 구조처럼 똑같은 자원을 하나 더 두어, 하나가 고장 나면 즉시 교체 투입될 수 있도록 설계하는 핵심 원리입니다.
```

7\. 로드 밸런싱 (Load Balancing)
-----------------------------
```
수평적 확장 시 필수적인 기술로, 여러 대의 서버에 트래픽을 골고루 나누어 주는 '교통 정리' 역할을 합니다. 
로드 밸런서 자체가 SPOF가 되지 않도록 이 장치 또한 이중화하는 것이 중요합니다.
```
