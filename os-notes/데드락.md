운영체제(OS, Operating System)의 교착상태(데드락, DeadLock)
=================

1\. 개념
-----------
```
여러 프로세스가 서로 다른 프로세스의 작업이 끝나기를 기다리다가 아무도 작업을 진행하지 못하는 상태
```

2\. 공유 자원
-----------
```
여러 프로세스에서 공유하는 자원
```

3\. 교착상태의 필요조건 4가지
-----------
한 가지라도 충족하지 않는다면 교착상태는 발생하지 않습니다.
```
1) 상호배제     : 점유한 리소스는 다른 프로세스에게 공유되면 안됩니다.
2) 비선점      : 점유하는 있는 리소스를 빼앗을 수 없어야 합니다.
3) 점유와 대기   : 리소스 A를 가지고 있을때 리소스 B도 원하는 상태.
4) 원형대기     : 점유와 대기를 하는 프로세스들의 관계가 원형을 이룸.
```

4\. 교착상태 회피
-----------
어느정도 자원에서 교착상태가 발생하는지 파악해서 교착상태가 발생하지 않는 수준의 자원을 할당한다.
```
전체 자원과 할당된 자원의 수를 기준으로 안정상태와 불안정상태로 나눕니다.
불안정상태일때는 교착상태에 빠질 확률이 높아집니다.
불안정상태라도 모든 프로세스가 최대 자원을 요청하지 않는다면 교착상태에 빠지지 않음
```

5\. 은행원 알고리즘 (은행이 대출해주는 방법)
-----------
교착상태 회피를 표현한 알고리즘 (비용이 비싸고 비효율적입니다.)
```
돈을 여럿에게 빌려주고 못받는 교착상태를 피하기 위해서 은행의 여유자금과 사업가들에게 빌려준 돈들을 보고 대출 가능한 상황인지 확인하고 빌려주는 알고리즘.
시스템의 총 자원   : 운영체제는 프로세스들에게 자원을 할당하기전에 자신이 가지고 있는 전체 자원의 수를 알고 있어야 합니다.
최대 요구 자원    : 프로세스들은 각자 필요한 자원의 최대 숫자를 운영체제에게 알려줘야 합니다. 
```

6\. 교착상태 검출 방법
-----------
```
1) 가벼운 교착상태 검출 (타이머)
    - 프로세스가 일정 시간 동안 작업을 진행하지 않는다면 교착상태가 발생했다고 간주함.
    - 일정 시점마다 체크포인트 만들어 작업을 저장하고 타임아웃으로 교착상태가 발생했을때 마지막 체크포인트로 롤백함
2) 무거운 교착상태 검출 (자원 할당 그래프)
    - 사용하는 자원을 지켜보고 교착상태가 발생하면 해결.
    - 교착상태를 일으킨 프로세스를 강제 종료 시킴.
    - 오버헤드가 큽니다.
    - 가벼운 교착상태 검출에서의 억울하게 종료되는 프로세스는 발생하지 않음.
```
