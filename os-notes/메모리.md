운영체제(OS, Operating System)의 메모리(Memory)
=================

1\. 종류
-----------
```
1) 레지스터     : 
    - ALU, 버스, 경계 레지스터
2) 캐시       :
    - L1, L2, L3
3) RAM      : 
    - MMU
4) SSD/HDD  : 
```

2\. 주소 공간
-----------
```
1) 상대 주소(논리 주소 공간)  : 사용자가 바라보는 주소공간
2) 절대 주소(물리 주소 공간)  : MMU는 절대주소를 바라봄
3) 재배치 레지스터         : 프로그램의 시작 주소가 저장되어 있음.
```

3\. 메모리 할당 방식 (연속 메모리 할당)
-----------
```
1) 고정 분할 메모리 할당 : 고정된 값으로 메모리 할당
    - 내부 단편화 발생
    - 고정된 값보다 크면 프로세스 실행 불가능
2) 가변 분할 메모리 할당 : 프로세스의 크기에 맞춰서 메모리 할당
    - 외부 단편화 발생
```

4\. 메모리 할당 방식 (불연속 메모리 할당)
-----------
```
가상 메모리  : 보조 메모리 공간 활용
    - 물리 메모리 크기와 CPU의 비트수로 결정됨. 32비트면 2^32 = 4GB
    - 하드 디스크 내부의 스왑영역으로 옮기고, 처리가 필요할때 물리 메모리로 가져와 실행.
    - DAT(Dynamic Address Transfer, 동적 주소 변환)   : 가상 주소를 물리 주소로 변환.
1) 가변 분할 방식(세그멘테이션)
    - 외부 단편화 발생
2) 고정 분할 방식(페이징)
    - 내부 단편화 발생
3) 세그멘테이션-페이징 혼용 기법
    - 각 단점들을 보완한 기법
```

5\. MMU (Management Memory Unit)
-----------
```
1) 프로세스에서 논리주소를 물리주소로 연결 시켜줌.
    - 운영체제 영역, 물리 메모리 크기 몰라도됨.
    - 가상 주소는 메모리나 하드 디스크의 스왑 영역 중 한 곳에 위치
    - 가상 주소와 물리 주소를 1대1 매핑 테이블로 관리
2) 물리 메모리를 어떻게 나누고 프로세스를 어디 배치할지, 부족한 물리 메모리를 어떻게 처리할지 복잡한 과정을 거침.
    - 세그먼트 테이블 베이스 레지스터를 이용해 물리 메모리 내에 있는 세그멘테이션 테이블을 찾음
    - 세그먼트 번호를 인덱스로 Base Address와 Bound Address를 찾음
    - Bound Address : 세그먼트의 크기 (가변적인 크기)
    - Base Address + 논리 주소  = 실제 주소 위치
```

6\. 메모리 배치 정책
-----------
```
1) 세그멘테이션
2) 페이징
3) 페이지드 세그멘테이션
    - 90% 시간이 10% 코드에서 보낸다는 지역성 이론.
    - 공간의 지역성   : 현재 위치에서 가장 가까운 데이터에 접근할 확률이 높음
    - 시간의 지역성   : 현재 기준으로 가까운 시간에 접근했던 데이터가 접근할 확률이 높음
```

7\. 가져오기 정책
-----------
```
디맨드 페이징 : 쓰일것 같은걸 메모리에 가져오고, 안쓰일것 같은걸 스왑영역에 보내는 정책
스왑인     : 물리 메모리로 가져오는것 (물리 메모리 <- HDD)
스왑아웃    : 물리 메모리에서 보내는것 (물리 메모리 -> HDD)
```

8\. 교체 정책
-----------
메모리가 꽉 찼을 때 어떤 페이지를 스왑 영역으로 보낼지 결정하는 정책
```
1) Random   : 무작위
2) FIFO     : 가장 오래된 페이지 먼저 교체
    - 빌레이디의 역설  : Page Fault를 줄이려고 메모리를 더 늘려서 프레임의 수를 늘려 놨는데 Page Fault가 더 많이 발생
    - 2차 기회 페이지 교체 알고리즘 (FIFO 개선)   : Page Fault없이 Page 접근에 성공했다면 해당 페이지는 큐의 맨뒤로 이동시켜서 수명 연장
3) Optimum  : 오랫동안 쓰이지 않을 페이지 선택
4) LRU      : 가장 최근에 사용되지 않은 페이지 선택
    - Clock Algorithm   : 접근 비트 하나를 사용해서 교체를 구현
    - Enhanced Clock Algorithm  : 접근 비트와 변경 비트까지 사용해서 교체를 구현
```

9\. 스레싱과 워킹셋
-----------
```
1) 스레싱  : CPU 사용률을 더 높이려고 했지만 오히려 더 떨어지는 상황
    - 물리 메모리 크기 부족
2) 워킹셋  : 현재 메모리에 올라온 페이지는 다시 사용할 확률이 높기 때문에 하나의 세트로 묶어서 메모리에 올림
    - 준비->실행 상태로 컨텍스트 스위칭 할 때 사용
```
