Thread
=================

2\. 프로세스(Process) 와 쓰레드(Thread)의 차이점
-----------
```
- 프로세스 : OS가 메모리 등의 자원을 할당해준 실행중인 프로그램을 가리킨다. 이때, 각각의 프로세스는 서로 메모리 공간을 독자적으로 갖기
            때문에 서로 메모리 공간을 공유하지 못한다. 따라서 공유하기 위해서는 IPC(InterProcess Communication)과 같은 방식이 
            필요하다.
- 쓰레드 : 쓰레드는 프로세스 내에서 프로세스의 자원을 가지고 실제로 일하는 "일꾼"과 같으며 각 쓰레드는 독자적인 Stack 메모리를 갖고 
          그 외의 자원(PCB, 코드 영역, 데이터 영역, 힙 영역)은 프로세스 내에서 공유하게 된다.
```

2\. 메모리 구조 관점에서의 차이
-----------
운영체제는 프로세스가 생성될 때 독립된 메모리 영역(Code, Data, Heap, Stack)을 할당합니다.
```
구분      Code / Data / Heap 영역       Stack 영역
프로세스    프로세스마다 독립적으로 할당     프로세스마다 독립적으로 할당
쓰레드     동일 프로세스 내 쓰레드끼리 공유  쓰레드마다 독립적으로 할당

💡 쓰레드가 Stack만 독립적으로 가지는 이유
 - Stack은 함수 호출과 리턴값, 지역 변수를 관리하는 공간입니다. 각 쓰레드가 독립적인 함수 호출과 실행 흐름을 유지하려면 독자적인 
   Stack 공간이 필수적입니다.
```

2\. 4가지 영역
-----------
```
1) Code (코드 영역): 실행할 프로그램의 코드가 저장되는 영역 (공유 가능)
2) Data (데이터 영역): 전역 변수와 정적(static) 변수가 저장되는 영역 (공유 가능)
3) Heap (힙 영역): 동적으로 할당되는 메모리 영역 (공유 가능)
4) Stack (스택 영역): 지역 변수, 매개변수, 함수 호출 정보가 저장되는 영역 (독립적)
```

2\. 특징
-----------
```
1) 자원 효율성: 쓰레드는 Code, Data, Heap 영역을 공유하므로 메모리 사용량이 적고 통신(IPC) 비용이 적게 듭니다.
2) 컨텍스트 스위칭(Context Switching): 쓰레드 간 교체가 프로세스 간 교체보다 가볍고 빠릅니다. (캐시 메모리를 비울 필요가 없음)
3) 안정성: 프로세스는 독립적이어서 하나가 쓰러져도 안전하지만, 쓰레드는 메모리를 공유하므로 한 쓰레드에서 예외가 발생하면 프로세스 
          전체가 종료될 수 있습니다.
```
