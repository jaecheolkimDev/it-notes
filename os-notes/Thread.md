운영체제(OS, Operating System)의 Thread 공부 노트
=====================

1\. 컨텍스트 스위칭(Context Switching)
--------------------------------------
```
컨텍스트 스위칭(Context Switching)이 '비용'인 이유
    컴퓨터가 쓰레드를 갈아 끼울 때 단순히 몸만 움직이는 게 아니라, 아주 복잡한 뒷정리를 합니다.
    - 기존 작업 저장: 현재까지 계산하던 데이터, 메모리 주소 등을 어딘가에 기록해둡니다.
    - 새 작업 로드: 다음에 할 일의 기록을 다시 불러와서 CPU 세팅을 맞춥니다.
    - 캐시 메모리 초기화: CPU 안에 쌓아뒀던 빠른 데이터(Cache)들이 쓸모없어지면서 효율이 뚝 떨어집니다.
```

2\. 프로세스(Process) 와 쓰레드(Thread)의 차이점
--------------------------------------
```
- 프로세스 : OS가 메모리 등의 자원을 할당해준 실행중인 프로그램을 가리킨다. 이때, 각각의 프로세스는 서로 메모리 공간을 독자적으로 갖기 때문에 
           서로 메모리 공간을 공유하지 못한다. 따라서 공유하기 위해서는 IPC(InterProcess Communication)과 같은 방식이 필요하다.
- 쓰레드 : 쓰레드는 프로세스 내에서 프로세스의 자원을 가지고 실제로 일하는 "일꾼"과 같으며 각 쓰레드는 독자적인 Stack 메모리를 갖고 
          그 외의 자원(메모리)는 프로세스 내에서 공유하게 된다.
```

3\. IPC(Inter-Process Communication, 프로세스 간 통신)
--------------------------------------
운영체제 내에서 독립적으로 실행되는 프로세스들이 서로 데이터를 주고받거나 실행 상태를 공유할 수 있게 해주는 메커니즘입니다.
```
현대 운영체제는 메모리 보호를 위해 각 프로세스에게 독립적인 주소 공간을 할당합니다. 즉, 프로세스 A는 프로세스 B의 메모리를 함부로 읽거나 
쓸 수 없습니다. 이러한 격리(Isolation) 상태에서 협업이 필요할 때 사용하는 통로가 바로 IPC입니다.

1) 주요 모델
 1-1) 공유 메모리 (Shared Memory)    : 두 개 이상의 프로세스가 물리적 메모리의 특정 영역을 함께 점유하는 방식입니다.
    특징: 메모리에 직접 접근하므로 속도가 매우 빠릅니다.
    단점: 여러 프로세스가 동시에 데이터를 쓰려고 할 때 발생하는 동기화 문제(Race Condition)를 프로그래머가 직접 해결해야 합니다.
 1-2) 메시지 전달 (Message Passing)  : 운영체제가 제공하는 커널(Kernel)을 통해 메시지를 주고받는 방식입니다.
    특징: 커널이 데이터를 복사해서 전달해주므로 구현이 비교적 쉽고 안전합니다.
    단점: 시스템 호출(System Call)이 발생하여 공유 메모리 방식보다 속도가 느릴 수 있습니다.
    
2) 구체적인 IPC 기법들
기법                      설명
Pipe (파이프)          한 프로세스의 출력을 다른 프로세스의 입력으로 연결하는 단방향 통로입니다.
Named Pipe (FIFO)     파이프와 비슷하지만, 이름이 있는 파일을 통해 서로 모르는 프로세스 간에도 통신이 가능합니다.
Message Queue         메시지들을 큐(Queue) 형태로 관리하며, 비동기적으로 데이터를 전달할 때 유용합니다.
Shared Memory         프로세스들이 공유하는 메모리 영역을 만들어 직접 데이터를 읽고 씁니다.
Socket (소켓)         동일한 컴퓨터뿐만 아니라 네트워크로 연결된 다른 컴퓨터의 프로세스와도 통신할 수 있는 방식입니다.
Semaphore/Mutex       엄밀히는 통신보다는 '동기화' 기법으로, 공유 자원에 접근하는 프로세스 수를 제어합니다.

3) 정리 : IPC는 독립된 섬처럼 떨어져 있는 프로세스들이 '다리(공유 메모리)'를 놓거나 '배(메시지 전달)'를 띄워 서로 소통하는 모든 기술적 수단을 
         의미합니다. 개발자는 상황에 따라 속도(공유 메모리)와 안정성(메시지 전달) 중 우선순위를 정해 적절한 기법을 선택하게 됩니다.
```
