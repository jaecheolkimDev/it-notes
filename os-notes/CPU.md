CPU
======================

2\. 64bit vs 32bit
-----------
```
핵심 차이는 "주소 공간의 크기"와 "데이터 처리 효율성" 두 가지로 요약됩니다.
```

2\. 가상 주소 공간 (Virtual Address Space) — 가장 결정적 차이
-----------
OS가 프로세스에 할당할 수 있는 메모리 주소의 한계가 달라집니다.
```
1) 32비트 OS ($2^{32}$):
 - 최대 4GB까지만 주소를 지정할 수 있습니다.
 - 보통 OS 커널이 1~2GB를 가져가므로, 단일 앱이 쓸 수 있는 메모리는 2~3GB에 불과합니다.
2) 64비트 OS ($2^{64}$):
 - 이론상 $16\text{EB}$(엑사바이트), 실제 현대 OS 구현 기준으로도 256TB 이상의 메모리를 다룹니다.
 - 대용량 데이터베이스, 가상화, AI 모델 등을 메모리 부족 없이 실행할 수 있습니다.
```

2\. 레지스터와 CPU-커널 간 데이터 전달 효율
-----------
```
1) 포인터 및 데이터 크기: 64비트 OS에서는 포인터(메모리 주소) 크기가 4바이트에서 8바이트로 늘어납니다.
2) 함수 호출 방식 (Calling Convention):
 - 32비트: 범용 레지스터가 8개에 불과해, 함수에 인자를 전달할 때 느린 스택 메모리를 자주 활용합니다.
 - 64비트: 범용 레지스터가 16개로 2배 늘어나, 인자를 레지스터에 직접 담아 전달하므로 OS 성능과 처리 속도가 향상됩니다.
```

2\. 시스템 호출(System Call)과 호환성
-----------
```
1) 빠른 커널 전환: 64비트 OS는 전용 명령어(SYSCALL/SYSRET)를 통해 유저 모드에서 커널 모드로 넘어가는 오버헤드를 대폭 줄였습니다.
2) 32비트 하위 호환성: 64비트 OS에서 32비트 프로그램 실행 시 에뮬레이션 레이어(Windows의 WoW64, Linux의 Multiarch)를 거쳐 
                    변환 처리됩니다.
3) 드라이버 제약: 커널 모드 드라이버는 변환 레이어가 적용되지 않으므로, 64비트 OS에는 반드시 64비트 전용 드라이버만 로드할 수 있습니다.
```

2\. 커널 보안 강화
-----------
```
1) 강화된 ASLR: 주소 공간이 압도적으로 넓어져 메모리 주소를 난수화하는 ASLR(Address Space Layout Randomization)의 방어 
               효과가 극대화됩니다.
2) 커널 보호 메커니즘: 64비트 OS(예: Windows PatchGuard)는 커널 영역 메모리의 무단 변조를 하드웨어 차원과 연동해 강력하게 
                    차단합니다.
```
