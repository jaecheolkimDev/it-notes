CPU 스케줄링 공부 노트
=====================

1\. 개념
--------------
운영체제가 프로세스들에게 CPU를 할당/해제 하는 것
```
1) 고려사항
 - 어떤 프로세스에게 CPU리소스를 줘야 하는가?
 - 할당 받으면 얼마나 사용해야 하는가?
2) PCB의 프로세스 상태가 변할때 우선순위를 보고 그에 맞는 준비큐에 넣습니다.
 - 준비상태의 다중큐에 있는 프로세스들 중에 적당한 프로세스를 선택해서 실행상태로 만든다.
 - I/O작업이 일어나면 대기상태로 변하므로 분류된 큐에 들어감
3) 목표   : 사용하는 시스템에 따라 우선순위가 다름
 - 리소스 사용률
 - 오버헤드 최소화
 - 공평성
 - 처리량
 - 대기시간
 - 응답시간
4) 성능 기준        : 평균대기시간이 짧으면 성능이 좋은것으로 판단한다.
5) Time Quantum
 - Windows : 20ms
 - Unix : 100ms
 
 
* CPU 버스트 : CPU를 할당받아 실행하는 작업
* I/O 버스트 : 입출력 작업
```

999\. CPU 스케줄링
--------------
구분	    알고리즘	방식	            장점	                    단점
비선점	FCFS	도착 순서	    단순함, 공평함	        콘보이 효과 (긴 대기 시간)
        SJF	    짧은 작업 우선	최소 평균 대기 시간	    기아 현상, 실행 시간 예측 불가
        HRN	    응답률 우선	    기아 현상 보완	        오버헤드 증가
선점	    RR	    시간 할당량	    빠른 응답성 (현대 OS 기초)	문맥 교환 오버헤드
        SRTF	남은 시간 우선	최단 대기 시간	        잦은 선점, 기아 현상
        MLFQ	다단계 피드백	    유연함, 효율성 최강	    구현이 복잡함
```
1) 비선점형 스케줄링 (Non-preemptive)   : 프로세스가 CPU를 할당받으면 작업이 끝날 때까지 CPU를 강제로 뺏을 수 없는 방식입니다.
    ① FCFS (First-Come, First-Served)
        특징: 준비 큐에 도착한 순서대로 CPU를 할당하는 가장 단순한 방식입니다.
        장점: 구현이 매우 쉽고 간단하며, 모든 프로세스가 공평하게 처리됩니다.
        단점: 콘보이 효과(Convoy Effect)가 발생할 수 있습니다. 
             즉, 처리 시간이 긴 프로세스가 앞에 오면 뒤의 짧은 프로세스들이 무한정 기다려야 해서 평균 대기 시간이 길어집니다.
    ② SJF (Shortest Job First)
        특징: 실행 시간이 가장 짧은 프로세스에게 먼저 CPU를 할당합니다.
        장점: 평균 대기 시간을 최소화하는 최적(Optimal) 알고리즘입니다.
        단점: 기아 현상(Starvation)이 발생할 수 있습니다. 짧은 작업이 계속 들어오면 긴 작업은 영원히 CPU를 못 잡을 수 있습니다. 
             또한, 실제 프로세스의 실행 시간을 미리 예측하기 어렵습니다.
    ③ HRN (Highest Response Ratio Next)
        특징: SJF의 기아 현상을 보완하기 위해 대기 시간과 서비스 시간을 고려하여 우선순위를 정합니다.
            $우선순위 = \frac{대기 시간 + 서비스 시간}{서비스 시간}$
        장점: 대기 시간이 길어질수록 우선순위가 높아지므로(Aging 기법), 긴 작업도 결국 처리됩니다.
        
2) 선점형 스케줄링 (Preemptive)        : 운영체제가 실행 중인 프로세스로부터 CPU를 강제로 뺏어 다른 프로세스에게 줄 수 있는 방식입니다. 
                                      현대 운영체제에서 주로 사용됩니다.
    ① RR (Round Robin)
        특징: 각 프로세스에 동일한 시간 할당량(Time Quantum)을 주고, 시간이 지나면 다음 프로세스로 교체합니다.
        장점: 응답 시간이 매우 빨라 대화형 시스템(Windows, macOS 등)에 적합합니다.
        단점: 시간 할당량이 너무 크면 FCFS와 같아지고, 너무 작으면 잦은 문맥 교환(Context Switching)으로 인해 오버헤드가 커집니다.
        
    ② SRTF (Shortest Remaining Time First)
        특징: SJF의 선점형 버전입니다. 현재 실행 중인 프로세스보다 남은 시간이 더 짧은 프로세스가 들어오면 CPU를 뺏어 넘겨줍니다.
        장점: 평균 대기 시간이 매우 짧습니다.
        단점: 남은 시간을 계속 계산해야 하므로 오버헤드가 발생하고 기아 현상도 여전합니다.
        
    ③ 다단계 피드백 큐 (Multilevel Feedback Queue, MLFQ)
        특징: 여러 개의 큐를 두고 각 큐마다 다른 우선순위와 시간 할당량을 부여합니다. 
             프로세스가 CPU를 너무 오래 쓰면 낮은 우선순위 큐로 강등시키고, 오래 대기하면 높은 큐로 올립니다.
        장점: 현대 운영체제(Unix, Windows 등)에서 가장 많이 사용하는 가장 일반적이고 효율적인 알고리즘입니다. 프로세스 특성에 따라 유연하게 대응합니다.
        
3) 요약
    가장 공평한 것: FCFS
    가장 대기 시간이 짧은 것: SJF / SRTF
    사용자 반응성이 좋은 것: Round Robin
    실제 운영체제가 쓰는 것: Multilevel Feedback Queue
```
