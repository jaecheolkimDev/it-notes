SSE(Server-Sent Events)
=================

4\. 정의
-----------
HTTP 프로토콜 위에서 작동하며, HTML5 표준 사양에 포함되어 있습니다.
```
웹 브라우저가 서버와 한 번 HTTP 연결을 맺은 후, 서버가 클라이언트로 실시간 데이터를 지속적으로 보낼 수 있게 하는 단방향 스트리밍 표준 
기술입니다.
```

5\. 동작 원리 및 데이터 포맷
-----------
```
1) 클라이언트 요청: 브라우저가 EventSource API를 사용하여 서버에 연결을 요청합니다.
2) 서버 응답 헤더: 서버는 Content-Type: text/event-stream 헤더를 설정하여 SSE 스트림임을 명시합니다.
3) 데이터 전송: 서버는 일반 텍스트 형태로 규격에 맞춰 데이터를 지속적으로 샌딩합니다.
```

6\. 주요 장단점
-----------
```
1) 장점
 - HTTP 재활용: 기존 HTTP 인프라(HTTP/2, HTTP/3, CORS 등)와 보안 설정을 그대로 사용 가능합니다.
 - 자동 재연결: 연결이 끊어지면 브라우저가 Last-Event-ID를 포함해 자동으로 재연결을 시도합니다.
 - 가벼움: 웹소켓 대비 서버 및 클라이언트 구현이 매우 간단하고 가볍습니다.
2) 단점
 - 단방향 한계: 클라이언트가 서버로 데이터를 보낼 때는 별도의 HTTP POST/PUT 요청을 사용해야 합니다.
 - HTTP/1.1 연결 수 제한: HTTP/1.1 환경에서는 브라우저당 도메인별 최대 연결 수가 6개로 제한됩니다 (HTTP/2 이상 사용 시 해결).
 - 텍스트 기반: 기본적으로 UTF-8 텍스트 데이터 전송에 최적화되어 있습니다.
```
