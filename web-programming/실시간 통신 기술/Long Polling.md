롱 폴링 (Long Polling)
=================

4\. 정의
-----------
```
클라이언트가 요청을 보내면, 서버는 새로운 데이터가 발생하거나 타임아웃(Timeout)이 될 때까지 응답을 보내지 않고 
대기(Connection Hold)하는 방식입니다.
```

5\. 동작 방식
-----------
[Client] --- (1) 요청: 새로운 데이터 있나요? -----------------------> [Server]
(이벤트 발생 대기 중...)
(새 데이터 발생!)
[Client] <--- (2) 응답: 네, 이벤트가 발생했습니다! ------------------ [Server]
[Client] --- (3) 응답을 받자마자 즉시 재요청 -------------------------> [Server]
(다시 대기...)
```
1) 클라이언트가 서버에 요청을 보냅니다.
2) 서버는 데이터가 없으면 응답을 바로 주지 않고 커넥션을 유지한 채 대기합니다.
3) 데이터가 발생하면 그 즉시 응답을 반환하고 커넥션을 종료합니다. (타임아웃 시 빈 응답 반환)
4) 클라이언트는 응답을 수신하자마자 곧바로 다음 요청을 보냅니다.
```

6\. 장점
-----------
```
1) 우수한 실시간성: 서버에서 이벤트가 발생하는 즉시 응답을 받으므로 일반 폴링보다 즉각적입니다.
2) 트래픽 절감: 데이터 변경이 없을 때 무의미하게 반복되는 요청/응답 횟수가 줄어듭니다.
```

7\. 단점
-----------
```
1) 서버 리소스 자원 소모: 데이터가 올 때까지 수많은 클라이언트와의 커넥션을 열어둔 채 유지해야 하므로 서버의 동시 접속 처리 
                       능력(Connection/Thread 관리)이 중요해집니다.
2) 이벤트 빈도가 높을 때의 한계: 데이터 변화가 매우 빈번하게 일어나면, 매번 커넥션을 맺고 끊는 작업이 반복되어 일반 폴링보다 오히려 
                             오버헤드가 커질 수 있습니다.
```

4\. 폴링 (Polling) vs 롱 폴링 (Long Polling)
-----------
```
구분                  폴링 (Polling)                    롱 폴링 (Long Polling)
요청 주기           일정한 시간 간격 (Fixed Interval)      이벤트 발생 시 즉시 재요청
응답 시점           요청 수신 즉시 응답                     데이터 발생 or 타임아웃 발생 시 응답
실시간성            낮음 (주기 대기 시간 존재)                높음 (이벤트 발생 즉시 전달)
서버/네트워크 부하  무의미한 HTTP 요청 폭증 위험              커넥션 대기(Hold)로 인한 메모리/스레드 부담
적합한 유즈케이스   • 주기적 갱신으로 충분한 대시보드         • 웹 채팅 (메시지가 가끔 올 때)
                • 미세한 실시간성이 필요 없는 데이터       • 실시간 알림 서비스 (Notification)
```
