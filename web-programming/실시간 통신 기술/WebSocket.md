웹소켓(WebSocket)
=================

4\. 정의
-----------
```
클라이언트와 서버 간에 단일 TCP 연결을 통해 실시간 양방향 통신을 제공하는 네트워크 프로토콜입니다.
```

5\. 기존 HTTP 방식과의 차이점
-----------
```
구분          HTTP 통신                                 웹소켓(WebSocket)
통신 방향       단방향 (클라이언트 요청 → 서버 응답)      양방향 (서버도 원할 때 데이터 전달)
연결 유지       요청-응답 후 연결 종료 (Stateless)       연결을 계속 유지 (Stateful)
헤더 오버헤드     요청마다 매번 큰 HTTP 헤더 전송        "초기에만 HTTP 사용, 이후 가벼운 프레임 전송"
적합한 분야      "문서/데이터 조회, 단발성 API"        "실시간 채팅, 주식 차트, 멀티플레이 게임"
```

6\. 동작 원리 (연결 과정)
-----------
```
1) 핸드셰이크(Handshake): 클라이언트가 서버에 "웹소켓으로 프로토콜을 전환하자"라는 HTTP 요청(Upgrade: websocket 헤더 포함)을 
                        보냅니다.
2) 프로토콜 전환: 서버가 이를 승인하면 HTTP 응답 코드 101 Switching Protocols를 반환합니다.
3) 양방향 통신: HTTP 연결이 웹소켓 연결로 업그레이드되며, 데이터가 프레임 단위로 실시간으로 자유롭게 오갑니다.
4) 연결 종료: 클라이언트나 서버 중 한쪽이 종료 프레임을 전송하여 통신을 끊습니다.
```

7\. 주요 장단점
-----------
```
1) 장점:
 - 낮은 지연 시간(Low Latency): 매번 연결을 맺고 끊는 과정이 없어 매우 빠르게 데이터를 주고받습니다.
 - 네트워크 자원 절약: HTTP 헤더 재전송에 따른 트래픽 손실을 획기적으로 줄여줍니다.
2) 단점:
 - 서버 부하: 지속적인 연결(Stateful)을 유지해야 하므로 동시 접속자가 많을 때 서버 메모리 관리가 중요해집니다.
 - 연결 유실 가능성: 네트워크 상태 불안정 시 연결이 끊길 수 있으므로 재연결(Reconnection) 로직이 필요합니다.
```
