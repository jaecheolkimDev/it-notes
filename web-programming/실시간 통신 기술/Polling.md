폴링 (Polling, Short Polling)
=================

4\. 정의
-----------
```
클라이언트가 일정한 시간 간격(예: 3초, 5초)마다 서버에 HTTP 요청을 지속적으로 보내 변경 사항이 있는지 확인하는 방식입니다.
```

5\. 동작 방식
-----------
[Client] --- (1) 요청: 새로운 데이터 있나요? ---> [Server]
[Client] <--- (2) 응답: 아니요, 없습니다. -------- [Server]
(3초 대기)
[Client] --- (3) 요청: 새로운 데이터 있나요? ---> [Server]
[Client] <--- (4) 응답: 네, 여기 있습니다! ------- [Server]
```
1) 클라이언트가 주기적으로 GET /updates 요청을 보냅니다.
2) 서버는 요청을 받자마자 현재 상태를 즉시 응답합니다. (새 데이터가 없으면 빈 값이나 변경 없음 상태 전달)
3) 클라이언트는 설정된 주기만큼 대기한 후 다시 요청을 반복합니다.
```

6\. 장점
-----------
```
1) 구현이 매우 단순하고 직관적입니다.
2) 서버나 클라이언트의 상태 관리가 거의 필요 없습니다 (Stateless).
```

7\. 단점
-----------
```
1) 불필요한 트래픽/L7 Overhead: 데이터 변경이 없어도 계속 요청/응답을 주고받으므로 HTTP 헤더 오버헤드와 네트워크 트래픽이 낭비됩니다.
2) 서버 부하: 클라이언트 수가 늘어날수록 서버가 처리해야 하는 HTTP 요청 수가 폭증합니다.
3) 실시간성 저하: 설정한 주기(Polling Interval)보다 빠른 데이터 변화는 즉시 감지할 수 없습니다.
```
