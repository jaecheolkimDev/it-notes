RPC(Remote Procedure Call, 원격 프로시저 호출) 공부 노트
=================

1\. 개념
----------------------------------------
네트워크로 연결된 다른 컴퓨터에 있는 함수(프로시저)를 마치 자신의 컴퓨터에 있는 함수처럼 실행할 수 있게 해주는 기술입니다.
```
복잡한 네트워크 통신(소켓 생성, 데이터 직렬화 등) 과정을 개발자가 직접 신경 쓰지 않아도 되도록 운영체제나 프레임워크가 대신 처리해 주는 것이 핵심입니다.
```

2\. 동작 원리
----------------------------------------
RPC는 클라이언트와 서버가 서로를 호출할 때 중간에서 대리인 역할을 하는 Stub(스텁)을 사용합니다.
```
1) Client Call: 클라이언트가 로컬 함수를 호출하듯 RPC 함수를 호출합니다.
2) Client Stub: 인자값을 네트워크로 전송하기 적합한 형태(Byte stream)로 변환합니다. 이를 Marshaling(마샬링)이라고 합니다.
3) Network Transmission: 변환된 데이터를 서버로 전송합니다.
4) Server Stub: 서버가 받은 데이터를 다시 함수 인자 형태로 복원합니다. 이를 Unmarshaling(언마샬링)이라고 합니다.
5) Server Procedure: 서버에서 실제 함수를 실행하고 결과값을 다시 스텁을 통해 클라이언트에게 돌려줍니다.
```

3\. 특징
----------------------------------------
```
1) 투명성(Transparency): 개발자는 호출하는 함수가 내 컴퓨터에 있는지, 저 멀리 있는 서버에 있는지 알 필요 없이 코드만 작성하면 됩니다.
2) 강한 결합(Strong Coupling): 일반적으로 클라이언트가 요청을 보내면 서버의 응답이 올 때까지 기다리는 동기(Synchronous) 방식이 기본입니다.
3) 인터페이스 정의: 서버와 클라이언트가 어떤 함수를 쓸지 약속해야 하므로, 보통 IDL(Interface Definition Language)이라는 별도의 언어로 
                 인터페이스를 정의합니다.
```

4\. 현대적 RPC: gRPC
----------------------------------------
최근에는 구글에서 만든 gRPC가 가장 많이 쓰입니다.
```
1) Protocol Buffers: XML이나 JSON보다 훨씬 작고 빠른 이진(Binary) 데이터 형식을 사용합니다.
2) HTTP/2: 최신 네트워크 프로토콜을 사용하여 양방향 스트리밍이 가능하고 효율적입니다.
3) MSA에서의 역할: 마이크로서비스 아키텍처에서 각 서비스들이 서로 빠르게 데이터를 주고받는 핵심 통로로 사용됩니다.
```
