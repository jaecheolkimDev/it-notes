IDL(Interface Definition Language, 인터페이스 정의 언어)
=================

1\. 개념
-----------
서로 다른 언어나 플랫폼에서 돌아가는 소프트웨어 컴포넌트들이 '서로 어떻게 대화할지'를 정의하는 표준 언어입니다.
```
서버와 클라이언트 사이의 '계약서(Contract)'를 작성하는 공용어
```

2\. IDL이 왜 필요한가요?
-----------
만약 Java로 만든 클라이언트가 C++로 만든 서버의 함수를 부르려 한다면, 두 언어의 데이터 타입이나 함수 구조가 달라서 직접 대화가 불가능합니다.
```
이때 IDL이 중간에서 다리 역할을 합니다.
1) 공통 문법: IDL이라는 중립적인 언어로 "이 함수는 이런 파라미터를 받고 이런 값을 돌려준다"라고 딱 정의합니다.
2) 코드 생성: 정의된 IDL 파일을 도구(Compiler)에 넣으면, Java용 스텁 코드와 C++용 스켈레톤 코드가 자동으로 생성됩니다.
```

3\. IDL의 작동 흐름
-----------
```
1) 정의: .idl 또는 .proto 파일에 통신 규격을 작성합니다.
    예: GetUser(int id) returns (String name)
2) 컴파일: IDL 컴파일러를 실행합니다.
3) 생성: 각 언어에 맞는 스텁(Stub) 코드가 자동으로 만들어집니다.
4) 사용: 개발자는 생성된 스텁을 자기 언어의 일반 함수처럼 호출합니다.
```

4\. 대표적인 IDL 사례
-----------
```
1) Protocol Buffers (Protobuf): 구글의 gRPC에서 사용하는 IDL입니다. 현재 가장 대중적이며 성능이 뛰어납니다. (확장자: .proto)
2) AIDL (Android Interface Definition Language): 안드로이드 앱과 서비스가 통신(IPC)할 때 쓰는 IDL입니다.
3) Thrift IDL: 페이스북(현 Meta)에서 만든 Apache Thrift 프로젝트의 IDL입니다.
4) WSDL (Web Services Description Language): 과거 SOAP 방식의 웹 서비스에서 사용하던 XML 기반의 IDL입니다.
```

5\. IDL을 쓰면 뭐가 좋은가요?
-----------
```
1) 언어 독립성: 서버는 Go로 짜고, 클라이언트는 Java로 짜도 아무 문제 없습니다.
2) 강력한 타입 체크: 컴파일 시점에 데이터 형식이 맞는지 체크하므로 런타임 에러(예: JSON 필드 오타)를 획기적으로 줄입니다.
3) 문서화 대체: IDL 파일 자체가 완벽한 API 명세서 역할을 하므로, 별도의 문서가 필요 없습니다.
```
