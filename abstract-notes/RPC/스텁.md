스텁(Stub)
=================

1\. 개념
----------------------------------------
분산 컴퓨팅 환경에서 "원격지에 있는 함수를 마치 로컬에 있는 함수처럼 호출할 수 있도록 중간에서 대리인 역할을 하는 코드 조각"을 의미합니다.
```
RPC 구조에서 클라이언트와 서버가 서로 다른 메모리 공간이나 물리적 위치에 있을 때, 그 사이의 복잡한 네트워크 통신 과정을 개발자로부터 감추기 위해 
사용됩니다.
```

2\. 스텁의 종류와 역할
----------------------------------------
스텁은 통신 방향에 따라 클라이언트 측과 서버 측으로 나뉩니다.
```
1) 클라이언트 스텁 (Client Stub)   : 클라이언트 프로그램 안에 포함되며, 실제 원격 함수의 '껍데기' 역할을 합니다.
 1-1) 함수 호출 가로채기: 클라이언트가 원격 함수를 호출하면, 스텁이 이를 가로채서 처리합니다.
 1-2) 마샬링(Marshaling): 함수에 전달된 인자(Parameter)들을 네트워크를 통해 전송할 수 있는 표준 바이트 형태로 변환합니다.
 1-3) 전송 요청: 변환된 데이터를 네트워크 모듈을 통해 서버로 보냅니다.

2) 서버 스텁 (Server Stub)  : 서버 측에서 요청을 받아 실제 함수로 연결해 주는 역할을 하며, 흔히 스켈레톤(Skeleton)이라고도 부릅니다.
 2-1) 언마샬링(Unmarshaling): 네트워크로 들어온 바이트 데이터를 서버의 언어와 메모리 구조에 맞는 데이터 형식으로 복원합니다.
 2-2) 실제 함수 호출: 복원된 인자를 사용하여 서버 내부에 구현된 실제 비즈니스 로직(함수)을 실행합니다.
 2-3) 결과 반환: 함수의 실행 결과값을 다시 마샬링하여 클라이언트 스텁으로 돌려보냅니다.
```

3\. 왜 스텁이 필요한가?
----------------------------------------
```
1) 추상화(Abstraction): 개발자는 소켓 통신, 패킷 조립, 데이터 직렬화 같은 복잡한 네트워크 하위 로직을 짤 필요가 없습니다. 
                       그냥 함수를 호출하면 스텁이 나머지를 알아서 합니다.
2) 투명성(Transparency): 함수 호출자 입장에서는 이 기능이 내 컴퓨터에서 도는지, 아니면 수천 킬로미터 떨어진 서버에서 도는지 신경 쓰지 않아도 됩니다.
3) 이종 시스템 간 통신: 클라이언트는 Java로 짜여 있고 서버는 C++로 짜여 있어도, 각 언어에 맞는 스텁이 데이터를 표준 규격(IDL 등)으로 변환해주기 
                     때문에 소통이 가능합니다.
```
