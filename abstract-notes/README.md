추상화
=================

1\. 핵심 개념: "What, not How"
---------------
복잡한 내부 구현 로직을 뒤로 숨기고, 사용자나 다른 시스템이 꼭 알아야 할 핵심적인 기능(인터페이스)만을 노출하는 과정을 의미합니다.
```
추상화는 "어떻게(How) 작동하는가"를 숨기고 "무엇(What)을 하는가"에 집중하게 합니다.

1) 자동차 운전의 예: 운전자는 핸들을 돌리고 브레이크를 밟는 법(인터페이스)만 알면 됩니다. 엔진 내부에서 피스톤이 어떻게 움직이고 연료가 
                   어떻게 분사되는지(구현)는 몰라도 운전하는 데 지장이 없습니다.
2) 컴퓨팅의 예: printf() 함수를 쓸 때, 우리는 모니터 픽셀 하나하나에 빛을 쏘는 하드웨어 로직을 고민하지 않습니다. 
              "화면에 글자를 출력한다"는 추상화된 기능만 가져다 씁니다.
```

2\. 추상화의 층위 (Layers of Abstraction)
---------------
컴퓨터 시스템은 거대한 추상화의 탑과 같습니다. 아래 계층이 복잡한 일을 처리해주면, 위 계층은 그 결과를 바탕으로 더 고차원적인 일을 합니다.
```
계층	            추상화의 결과물	    설명
하드웨어	        게이트, 회로	        전자의 흐름을 0과 1이라는 논리값으로 추상화
운영체제	        파일, 프로세스	    복잡한 디스크 섹터와 메모리 주소를 '파일'과 '프로그램'으로 추상화
프로그래밍 언어	변수, 함수, 클래스	    0과 1의 이진수를 인간이 이해하기 쉬운 단어와 구조로 추상화
네트워크	        소켓, API	        전기 신호와 패킷 전송 과정을 '연결'과 '호출'로 추상화
```

3\. 개발 실무에서의 추상화 방법
---------------
```
1) 데이터 추상화 (Data Abstraction)   : 복잡한 데이터 구조를 하나의 타입으로 묶는 것입니다. Java에서 클래스(Class)나 DTO를 만드는 것이 이에 
                                      해당합니다. 사용자는 클래스 내부의 멤버 변수가 어떻게 얽혀 있는지 몰라도 제공되는 Getter/Setter나 메소드만 
                                      사용하면 됩니다.

2) 프로세스 추상화 (Process Abstraction)   : 반복되는 일련의 실행 단계를 메소드로 묶는 것입니다. 
    ex) 스텁(Stub)도 네트워크 통신이라는 복잡한 프로세스를 '메소드 호출'이라는 단순한 형태로 추상화한 대표적인 사례입니다.
```

4\. 정리
---------------
```
- 추상화가 잘 된 시스템일수록 유지보수가 쉽고, 코드가 깔끔해지며, 개발자가 비즈니스 로직에만 몰입할 수 있게 됩니다.
- 코드를 짜오시면서 "이 코드는 너무 복잡한데, 좀 더 깔끔하게 묶을 수 없을까?"라고 고민하셨던 모든 순간이 사실 더 나은 추상화를 찾기 
  위한 과정이었던 셈이죠.
```
