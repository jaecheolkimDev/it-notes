SOLID
=================
- 객체 지향 프로그래밍(OOP)에서 소프트웨어의 유지보수성과 확장성을 높이기 위한 5가지 핵심 설계 원칙
- 이 원칙들을 따르면 코드가 읽기 쉽고, 변경에 유연하며, 재사용하기 좋아져 코드 냄새를 제거하고 견고한 소프트웨어를 만드는 데 도움을 줍니다.

1\. S: 단일 책임 원칙 (Single Responsibility Principle - SRP)
----------------------------------------
```
핵심: 하나의 클래스는 단 하나의 책임(역할)만 가져야 합니다.
목표: 클래스의 변경 이유가 단 하나가 되도록 하여, 특정 기능 변경 시 다른 기능에 영향을 주지 않도록 합니다.
```

2\. O: 개방-폐쇄 원칙 (Open/Closed Principle - OCP)
----------------------------------------
```
핵심: 소프트웨어 요소(클래스, 모듈 등)는 확장에는 열려있고, 수정에는 닫혀있어야 합니다.
목표: 기존 코드를 수정하지 않고 새로운 기능을 추가할 수 있도록 다형성(Polymorphism) 등을 활용하여 설계합니다.
```

3\. L: 리스코프 치환 원칙 (Liskov Substitution Principle - LSP)
----------------------------------------
```
핵심: 자식 클래스는 언제나 부모 클래스를 대체할 수 있어야 합니다.
목표: 부모 타입을 사용하는 코드에서 자식 타입 객체로 바꿔도 프로그램의 정상적인 동작을 보장합니다.
```

4\. I: 인터페이스 분리 원칙 (Interface Segregation Principle - ISP)
----------------------------------------
```
핵심: 클라이언트가 사용하지 않는 인터페이스에 의존하도록 강요하지 말아야 합니다. 큰 인터페이스를 여러 개의 작은 인터페이스로 분리해야 합니다.
목표: 불필요한 의존성을 줄여 결합도를 낮춥니다.
```

5\. D: 의존성 역전 원칙 (Dependency Inversion Principle - DIP)
----------------------------------------
```
핵심: 구체적인 클래스에 의존하기보다, 추상화(인터페이스, 추상 클래스)에 의존해야 합니다.
목표: 상위 모듈은 하위 모듈에 의존하지 않고, 양쪽 모두 추상화에 의존해야 합니다 (결합도를 낮추고 유연성을 높임). 
```
