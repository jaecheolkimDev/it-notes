전략 패턴(Strategy Pattern)
=====================
```
템플릿 메소드 패턴과 함께 가장 자주 언급되는 패턴 중 하나입니다.
템플릿 메소드가 '상속'을 이용한다면,
전략 패턴은 '구성(Composition)'을 이용하는 것이 특징입니다.

전략 패턴은 알고리즘군을 정의하고 각각을 캡슐화하여, 실행 중에 알고리즘을 선택할 수 있게 하는 패턴입니다.
이 패턴을 사용하면 알고리즘을 사용하는 클라이언트와 상관없이 알고리즘을 독립적으로 변경할 수 있습니다.

1. 핵심 개념
   전략(Strategy): 실행 가능한 알고리즘에 대한 인터페이스를 정의합니다.

구체적인 전략(ConcreteStrategy): 전략 인터페이스를 실제로 구현한 클래스들입니다.

컨텍스트(Context): 전략을 사용하는 역할입니다. 전략 인터페이스를 참조하며, 필요에 따라 동적으로 전략을 바꿀 수 있습니다.

3. 장점과 단점
장점
    런타임 교체: 프로그램 실행 중에 행동을 바꿀 수 있습니다.
    OCP(개방-폐쇄 원칙) 준수: 기존 코드를 수정하지 않고 새로운 전략을 추가할 수 있습니다.
    코드 재사용: 알고리즘을 독립적으로 분리했으므로 다른 곳에서도 재사용이 가능합니다.

단점
    객체 수 증가: 알고리즘이 많아질수록 관리해야 할 클래스 수가 늘어납니다.

복잡성: 클라이언트가 어떤 전략이 적합한지 알고 있어야 할 수도 있습니다.

4. 구현 예제 (Java)
   결제 방식(카드, 페이)에 따라 결제 로직이 달라지는 상황을 예로 들어보겠습니다.

5. 요약
   전략 패턴은 "상속보다는 구성(Composition)을 사용하라"는 객체지향 원칙을 가장 잘 보여주는 패턴입니다.
   클래스 내부의 로직이 자주 바뀌거나, 여러 알고리즘 중 하나를 동적으로 선택해야 할 때 필수적으로 사용됩니다.
```
